# Model catalog and reasoning analysis

## Finding

The original Cursor symptom had a real merge-layer cause. Cursor discovery already emits a model-level reasoning profile and transport bindings, but `effectiveCatalogReasoningApply` derives a provider-wide boolean from `Models.Reasoning.Apply` (`internal/daemon/model_catalog_reasoning.go:10-34`). The builtin Cursor config has no such strategy, so the map contains `cursor=false`. Before the current worktree change, `applyEffectiveReasoningProfile` discarded all efforts/defaults whenever this value was false (`internal/modelcatalog/reasoning_merge.go:24-31`), even though `cursorModelRow` had parsed the levels and bindings (`internal/modelcatalog/live_model_rows_cursor.go:150-210`). The current `hasReasoningTransportBindings` exception (`internal/modelcatalog/reasoning_merge.go:34-38`) addresses this specific launch-argument transport case; the existing Cursor fixture now projects Grok 4.6 with its profile (`internal/modelcatalog/live_sources_test.go:394-400`).

Codex had a separate source gap. Generic ACP discovery converts only the advertised model option to `ModelRow` (`internal/modelcatalog/live_sources_acp.go:76-100`, `internal/modelcatalog/live_sources_acp.go:133-166`); it never reads an ACP reasoning option per model. `models.dev` only maps a boolean support field and does not parse effort lists/defaults (`internal/modelcatalog/modelsdev.go:271-337`). Consequently, a live support signal can be true while the selector has no levels. The current native Codex branch is the right shape: one short-lived `codex app-server` process per catalog refresh, `initialize`, then paginated `model/list`; it does not create a thread or launch one ACP session per model (`internal/modelcatalog/live_sources_codex.go:35-77`, `:117-139`). There is no existing reusable Go app-server client in this repository; the helper is local to that file. The T3 reference uses a typed, multiplexing client (`.resources/t3code/packages/effect-codex-app-server/src/client.ts:38-78`, `:253-264`).

## Remaining correctness risks

1. **New effort values are still silently lost.** The Codex path normalizes every advertised value through the closed internal vocabulary and drops unknown values (`internal/modelcatalog/live_sources_codex.go:163-170`; `internal/modelcatalog/live_model_rows.go:232-265`). It then derives `SupportsReasoning` from the _raw_ advertised count (`internal/modelcatalog/live_sources_codex.go:172-178`). A future model advertising only `super-high` therefore becomes `supports_reasoning=true` with zero selectable efforts; an unknown default is also discarded because it is assigned only when normalized and present in the retained list (`:179-183`). This reproduces the user-visible inconsistency for the next provider update. The upstream Codex v2 schema explicitly defines a reasoning effort as any non-empty string (`.resources/codex/codex-rs/app-server-protocol/schema/json/v2/ModelListResponse.json:229-247`), and the upstream Rust enum has `Custom(String)` fallback (`.resources/codex/codex-rs/protocol/src/openai_models.rs:55-87`, `:139-155`). T3 likewise labels unknown Codex values by their raw string (`.resources/t3code/apps/server/src/provider/Layers/CodexProvider.ts:76-90`) and maps every server-advertised option (`:141-181`). Preserve non-empty provider values as opaque efforts, with canonical values first for display, or explicitly reject the entire model row with a visible source error; silently returning `true` plus an empty list is unsafe.

2. **OpenCode currently has the same missing-metadata path.** The builtin adapter runs `opencode models` without `--verbose` (`internal/modelcatalog/live_sources_adapters.go:121-124`). The generic command parser accepts the slash-prefixed heading but only emits identity/availability fields (`internal/modelcatalog/live_sources.go:419-423`; `internal/modelcatalog/live_model_rows.go:165-207`). It does not associate the following JSON block with that heading, so `capabilities.reasoning` and `variants` are discarded. A local CLI check on 2026-09-09 confirmed that `opencode models` prints slugs only, while `opencode models --verbose` prints per-model JSON containing `capabilities.reasoning` and `variants`. T3 invokes the verbose form (`.resources/t3code/apps/server/src/provider/opencodeRuntime.ts:931`) and parses the paired heading/JSON stream (`.resources/t3code/apps/server/src/provider/opencodeRuntime.ts:293-360`; tests at `.resources/t3code/apps/server/src/provider/opencodeRuntime.cliParsers.test.ts:98-132`). Until Compozy either requests/parses verbose output or uses OpenCode's structured API, OpenCode model rows cannot expose provider-advertised reasoning levels.

3. **The native JSON-RPC helper is intentionally minimal.** `codexCatalogClient.call` decodes the response id as `int` and skips every nonmatching line (`internal/modelcatalog/live_sources_codex.go:80-115`). JSON-RPC ids are allowed to be strings or numbers; a future app-server response with a string id will fail decoding. It also cannot answer a server-to-client request while waiting for `model/list`. The current initialize/model-list flow is unlikely to issue such a request, but a typed id (`json.RawMessage`/number-or-string) and an explicit unexpected-request policy would make protocol evolution fail clearly. The current tests cover pagination and canonical Astra data (`internal/modelcatalog/live_sources_test.go:1479-1526`) but do not cover custom effort values, string ids, malformed required model fields, or a server request.

4. **Persisted dynamic rows can be stale on the first read after restart.** Live/model.dev rows and child reasoning/binding data are persisted by `ReplaceSourceRows` (`internal/modelcatalog/service.go:230-280`; schema `.internal/store/globaldb/schema/definitions/36_model_catalog.sql:16-74`). The models.dev source also has a process-local cache only (`internal/modelcatalog/modelsdev.go:43-59`, `:139-187`). On list bootstrap, `sourceRefreshAttempted` treats any persisted source status as “already attempted” without checking `NextRefresh` (`internal/modelcatalog/service_bootstrap.go:54-80`, `:143-166`). Thus a persisted, expired dynamic status suppresses the first synchronous refresh after daemon restart; the background sweep runs every 30 seconds (`internal/daemon/model_catalog_refresh_loop.go:14`, `:112-145`). This explains a bounded stale window, not data loss, but it is material for a selector expected to reflect newly launched models immediately. Bootstrap should skip only when the persisted status is fresh, or the first read should force a dynamic refresh when `NextRefresh <= now`.

5. **Source precedence intentionally favors explicit config over live metadata.** Rows are grouped by provider/model and sorted config (120), provider-live (110), extension (100), models.dev (50), builtin (10) (`internal/modelcatalog/types.go:35-46`; `internal/modelcatalog/merge.go:14-33`, `:171-182`). The first non-models.dev row containing a support signal or effort list supplies the effective reasoning profile (`internal/modelcatalog/reasoning_merge.go:41-60`). This preserves operator-authored values, but a configured row for an existing model can mask a newer live effort list/default. The native branch fixes previously unknown Astra rows because there is no matching static row; it will not update an existing configured model unless the config source is deliberately made partial or the precedence contract changes.

## Recommended owning tests

- Extend `TestCodexCatalogProtocol` in `internal/modelcatalog/live_sources_test.go:1479-1526` with an unknown non-empty effort and unknown default. The invariant is “provider-advertised selectable values survive catalog normalization”; the owning layer is native live discovery, not a UI test. Also add a response with a string JSON-RPC id if the protocol helper remains local.
- Add the OpenCode verbose fixture to the existing live-source tests near `internal/modelcatalog/live_sources_test.go:488-535`. Assert the command includes `--verbose`, the paired JSON metadata is parsed, and a model with `variants` gets selectable efforts. This is the owning source-parser invariant.
- Keep `internal/modelcatalog/service_test.go:339-672` as the merge precedence/strategy suite. Add one case proving transport-backed efforts survive a provider-level `none` strategy and one case proving an expired persisted status is refreshed on first list after restart.
- Keep the existing persistence/hydration cases in `internal/store/globaldb/global_db_model_catalog_test.go` (reasoning/bindings around the existing hydration tests) to ensure any opaque effort representation remains lossless across replacement and reload.
