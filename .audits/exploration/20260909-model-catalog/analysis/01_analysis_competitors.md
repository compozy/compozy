# Analysis: competitor model catalogs and reasoning dispatch

Read-only exploration of the slice `competitor-catalog` (ordinal `01`) for the research prompt:

> Compare model/provider/reasoning catalogs in `.resources/*` with Compozy's catalog, with emphasis on dynamic per-model reasoning, model drift, source precedence, selection dispatch, and provider-specific errors.

## Scope

- Slice question: what do Synara, T3 Code, OpenCode, and Codex do to keep newly released models and reasoning controls correct from discovery through dispatch?
- Primary sources: `.resources/synara`, `.resources/t3code`, `.resources/opencode`, `.resources/codex`, and `internal/modelcatalog` plus the web runtime selector.
- Sources read in full vs. sampled: targeted provider contracts, discovery/cache modules, adapters, transport transforms, and tests were read in full or at the relevant implementation ranges; large provider trees and generated/source snapshots were sampled.
- Total candidate sources surveyed: more than 40 files across the four competitor trees and the current Compozy catalog/runtime path.

## Overview

The strongest common pattern is a provider-owned, runtime-first descriptor for **each concrete model**. The descriptor carries the model identity, the exact reasoning values the provider currently advertises, the provider's current default, and the opaque transport binding needed to apply a selection. Static tables are treated as startup or offline fallback. They are not allowed to override a successful live list.

Codex is the clearest reference for this contract: `model/list` returns `supported_reasoning_efforts` and `default_reasoning_effort` on every model, and the app server forwards the selected model and effort. Cursor shows why a provider-level effort list is insufficient: its ACP `list_available_models` response is a per-model matrix of native config IDs, effort values, context options, fast mode, and thinking mode; a flat CLI model list is only a fallback. Grok similarly prefers the current CLI list over an API list that may contain retired IDs.

OpenCode and T3 Code add two important safeguards. They distinguish an absent reasoning declaration from an explicit empty declaration, so a model can mean “use generated/provider defaults” versus “this model has no reasoning variants.” They also preserve a last usable catalog across refresh failures, while validating remote/bundled metadata before replacing it. Synara combines these ideas with runtime descriptors, single-flight/stale-while-revalidate discovery, and provider/method-specific errors.

The current Compozy shape has most of the raw fields (`SupportsReasoning *bool`, effort list, default, transport bindings), but the merge and UI boundaries can still erase or cross-contaminate the information. In `internal/modelcatalog/reasoning_merge.go:41-50`, the first high-priority non-models.dev row with either a boolean or any effort list becomes the complete reasoning profile. A row that says only `supports_reasoning=true` therefore clears a lower-priority row's known effort list when `applyEffectiveReasoningProfile` resets the model at `:7-18`. In `web/src/systems/model-catalog/lib/derive-active-session-options.ts:46-65,138-175`, any provider-level ACP reasoning option wins before the selected model is inspected; a stale option matrix can expose the wrong ladder for the selected model. These are the most direct paths to “a reasoning-capable model appears unsupported.”

The parent should make the merge field-aware and selected-model-aware, preserve provider-declared effort strings, and make every discovery source report whether it is authoritative, fallback, stale, or an error. The competitor evidence below provides the concrete patterns and their limits.

## Mechanisms / Patterns

- **Runtime per-model capability is authoritative.** Synara resolves the selected model by normalized slug/resolved model and then overlays runtime descriptors on static capability data; runtime effort values replace the static ladder when present (`.resources/synara/apps/web/src/components/chat/runtimeModelCapabilities.ts:45-73,76-120,122-156`). Its contract keeps values open strings (`providerDiscovery.ts:253-258,279-298`) and carries `supportedReasoningEfforts`, a default, generic option descriptors, context choices, and model variants. This prevents a new provider value from being rejected merely because the UI enum shipped earlier.

- **Static metadata is startup fallback, not live truth.** Synara explicitly documents that runtime discovery is authoritative and the static table is only a startup fallback (`runtimeModelCapabilities.ts:76-84`). T3 uses a bundled manifest for offline startup but refreshes a remote manifest and retains the last successful disk copy (`.resources/t3code/apps/server/src/provider/ModelManifest.ts:1-14,298-318`). OpenCode loads disk data, then its bundled snapshot, then fetches the remote ModelsDev catalog (`.resources/opencode/packages/core/src/models-dev.ts:184-231`).

- **Reasoning declarations have three useful states.** OpenCode's ModelsDev schema has `reasoning` plus optional `reasoning_options`; an effort list may contain nullable values, or the provider may declare a toggle or budget range (`.resources/opencode/packages/core/src/models-dev.ts:52-76`). `reasoningVariants` returns generated/provider variants when `reasoning_options` is absent, returns an empty map when it is explicitly empty, and maps the declared values when present (`.resources/opencode/packages/opencode/src/provider/transform.ts:1704-1734`). This is a better semantic model than treating “no list” as “no reasoning.” In Compozy terms, `nil`/unknown, explicit `false`, and known non-empty values must survive each boundary; a boolean-only live row must not erase a known ladder.

- **Transport mapping belongs to the provider adapter.** OpenCode turns each declared effort into native request fields by SDK/provider (`reasoning`, Anthropic `thinking`/`effort`, Google `thinkingConfig`, Bedrock `reasoningConfig`, OpenAI `reasoningEffort`, and compatible-provider variants) at `.resources/opencode/packages/opencode/src/provider/transform.ts:1769-1837`. T3 Codex builds option descriptors directly from each app-server model's effort list and default (`.resources/t3code/apps/server/src/provider/Layers/CodexProvider.ts:141-207`); Synara Codex sends the selected `model` and `options.reasoningEffort` as app-server `model` and `effort` (`.resources/synara/apps/server/src/provider/Layers/CodexAdapter.ts:186-200`). The catalog should expose a normalized selection, while the selected provider owns the wire name and validation.

- **Per-model ACP matrices must remain bound to the selected model.** Synara Cursor prefers `cursor/list_available_models`, whose response contains each model's native select/boolean config options. It extracts effort/context/fast/thinking choices and current values (`.resources/synara/apps/server/src/provider/Layers/CursorAdapter.ts:1687-1727`; `.resources/synara/apps/server/src/provider/acp/CursorAcpSupport.ts:423-512`). Applying a selection searches the actual model's ACP option values and returns updates using the native config IDs (`CursorAcpSupport.ts:760-849,978-1005`). T3 follows the same shape, flattening provider config options, normalizing effort aliases, and mapping generic selections back to native IDs (`.resources/t3code/apps/server/src/provider/Layers/CursorProvider.ts:130-231,255-362,444-554`). A provider-global `reasoning_effort` option is only safe if the runtime proves it is shared by the selected model.

- **Provider source precedence must reflect drift.** Synara's Grok adapter treats `grok models` as source of truth because the xAI language-model API still advertises retired slugs; API models are used only when the CLI list is empty (`.resources/synara/apps/server/src/provider/Layers/GrokAdapter.ts:560-573,2390-2459`). T3's Codex adapter paginates app-server `model/list`, uses each model's own supported efforts/default, and does not infer a ladder from the name (`.resources/t3code/apps/server/src/provider/Layers/CodexProvider.ts:141-225,320-336`). Codex itself treats visible ChatGPT catalogs as authoritative but augments bundled metadata for other catalogs, replacing entries by exact slug (`.resources/codex/codex-rs/models-manager/src/manager.rs:482-514`).

- **Cache identity prevents cross-account and cross-install contamination.** Codex caches model metadata only when provider/auth identity, client version, and (where available) ETag match (`.resources/codex/codex-rs/models-manager/src/manager.rs:32-65,390-414,516-554`; `.resources/codex/codex-rs/models-manager/src/cache.rs:16-24,63-84,181-220`). Synara keys discovery by provider, binary path, endpoint, agent directory, and cwd, single-flights concurrent probes, serves stale good catalogs while revalidating, and keeps failures short-lived (`.resources/synara/apps/server/src/provider/providerModelDiscoveryCache.ts:17-45,90-115,163-175,177-249`). The query layer also includes all those inputs in its key (`.resources/synara/apps/web/src/lib/providerDiscoveryReactQuery.ts:236-277,394-450`).

- **Empty, stale, and failed catalogs are different states.** Synara only stores a non-empty, error-free catalog as a good result; an error-free empty response clears stale models as authoritative, while an errored fallback is replayed briefly (`providerModelDiscoveryCache.ts:90-97,163-175`). It preserves a prior good dynamic catalog when a background refresh fails (`providerDiscoveryReactQuery.ts:202-233,380-448`). T3's `current` path never waits for network, and failed refreshes retain the in-memory/disk model (`ModelManifest.ts:298-318,336-405`). This avoids blanking the picker during an ordinary provider timeout while still allowing a genuine authoritative removal to take effect.

- **Discovery errors carry provider and operation context.** Synara wraps CLI/ACP failures as `ProviderAdapterRequestError` with `provider: PROVIDER` and `method: "model/list"` and uses explicit timeout details (`.resources/synara/apps/server/src/provider/Layers/CursorAdapter.ts:1653-1684,1703-1725`; `GrokAdapter.ts:2410-2453,2460-2476`). Codex exposes typed JSON-RPC invalid-cursor handling and paginates `model/list` (`.resources/codex/codex-rs/app-server/src/request_processors/catalog_processor.rs:243-294`). OpenCode parses provider error bodies/statuses into context overflow, quota, invalid prompt, overloaded/server, and retryability classes (`.resources/opencode/packages/opencode/src/provider/error.ts:23-70,89-193`).

- **Malformed remote entries should be isolated.** Synara decodes each provider model descriptor separately, logs a warning, and returns the valid descriptors rather than discarding the entire catalog (`.resources/synara/apps/server/src/provider/Layers/ProviderDiscoveryService.ts:67-91,272-304`). T3 rejects the manifest as a unit when references/adapter metadata are invalid (`.resources/t3code/apps/server/src/provider/ModelManifest.ts:95-119`), which is appropriate for a versioned manifest but would be too coarse for an untrusted provider list. The target should choose the boundary deliberately: isolate malformed rows from live provider discovery, reject an internally inconsistent static manifest.

- **Selection is a compound provider/model identity.** OpenCode's session model resolver requires an exact provider/model pair and rejects unsupported variants (`.resources/opencode/packages/core/src/session/runner/model.ts:83-126,172-213`); its picker writes both provider and model (`.resources/opencode/packages/app/src/components/dialog-select-model.tsx:255-291`). Synara normalizes provider-specific aliases only at the provider boundary (`.resources/synara/packages/shared/src/model.ts:559-643`). Bare model IDs must never be used to look up reasoning metadata across providers.

## Transferable Patterns

- **Use a per-model runtime descriptor as the source of truth** → make the provider discovery DTO carry open effort descriptors, default, native option bindings, source, freshness, and authoritative/fallback state; static model tables only fill missing data before the first successful provider response.
- **Merge reasoning fields independently** → retain a lower-priority known effort ladder when a higher-priority row supplies only `supports_reasoning=true`; let an explicit provider `false` suppress it; accept a known non-empty ladder as support even if its boolean is absent; accept a default only when it belongs to the winning ladder. This augments the current whole-row selection in `internal/modelcatalog/reasoning_merge.go:5-31,41-50`.
- **Preserve provider-declared effort strings** → replace a global closed enum at the provider boundary with trimmed non-empty strings plus provider-specific normalization/aliases. OpenCode, Synara, and T3 all keep newly introduced values without waiting for a client release. The canonical enum can remain a UI label/order helper, but must not be the admission gate for a live provider value.
- **Make ACP overrides model-scoped** → key config options by `(provider, selected model, descriptor generation/session)` and only use a provider-global option when the adapter proves it applies to the selected model. Revalidate current/default values against that model's option values before rendering or dispatching.
- **Separate advertised capability from transport applicability** → keep catalog truth even when no generic transport exists, then have the adapter expose a precise “selectable” descriptor or reject with a provider/method error. Do not turn a discovered capability into `supports_reasoning=false` merely because the generic dispatch path lacks a binding.
- **Adopt explicit source precedence and provenance** → provider live/ACP data wins for the exact model and option set; authenticated remote lists can be authoritative or additive by provider contract; static manifest/models.dev data is fallback; stale data is usable but visibly stale; failures do not replace the last good catalog. Persist source and last error per field/row for diagnostics.
- **Key caches by every discovery input and auth identity** → include provider, binary, endpoint, agent directory, cwd, account/credential identity, and client/provider version where applicable. Revalidate in the background with single-flight and a bounded timeout; retain a good stale catalog during transient failures.
- **Distinguish explicit empty from missing** → represent “provider returned no reasoning choices” separately from “provider did not report capabilities.” This is required to stop a stale static fallback from reintroducing controls while still allowing generated/provider defaults when metadata is absent.
- **Keep actual dispatch adjacent to the provider adapter** → Codex and Cursor demonstrate that normalized UI values are not enough; dispatch must resolve exact model identity, check membership in the selected descriptor, and map to the provider's current wire ID/field. Add one integration check per provider proving the selected value reaches the native request.
- **Add drift-oriented tests** → new effort value, unknown model, model-specific default outside the ladder, stale ACP matrix for another model, remote list removing one model, malformed row alongside valid rows, timeout after a good cache, and cross-account cache mismatch. These are observable behavior invariants, not snapshots of static tables.

## Risks / Mismatches

- **Copying static family inference globally would repeat the current failure class.** Synara's Grok family fallback (`.resources/synara/packages/shared/src/model.ts:490-553`) is intentionally a startup fallback before discovery; Grok live CLI/ACP data still wins. Current Compozy tests explicitly reject inferring reasoning from model names (`internal/modelcatalog/service_test.go` reasoning inference cases). Keep family inference provider-scoped and fallback-only.
- **Using a provider-global ACP option can leak another model's ladder.** The current `deriveActiveSessionOptions` immediately returns `acpOption.values` at `:138-152` and marks source ACP at `:77-88`; it does not first bind the option to the selected model. Cursor's richer matrix shows the required model-scoped alternative.
- **A closed effort allowlist will lag new providers.** `to-runtime-selector-options.ts:48-56,101-109` discards values that `isReasoningEffort` does not know. The current branch has added `ultra`, but every future provider value would require another release and may be silently dropped. Preserve non-empty runtime strings and use a separate transport validator.
- **“First non-empty row” is not a safe field merge.** `merge.go:69-80` first-populates broad fields, then `reasoning_merge.go:7-18` clears and reapplies the selected row. If a high-priority live/ACP row supplies only a boolean, it can suppress efforts from a lower but more complete row. If a stale explicit `false` outranks a fresh positive row, the reverse error appears. Precedence must be field- and freshness-aware, with explicit negative values handled deliberately.
- **Whole-manifest rejection and row isolation are not interchangeable.** T3 rejects invalid profile references or adapter metadata at the manifest boundary (`ModelManifest.ts:95-119`); Synara isolates malformed live descriptors (`ProviderDiscoveryService.ts:67-91`). Applying the former to an untrusted CLI/ACP list could hide all valid models; applying the latter to a versioned manifest could accept a partially invalid transport schema.
- **Blind remote replacement can remove useful metadata.** Codex's additive versus authoritative decision depends on auth/catalog visibility (`manager.rs:482-514`), while OpenCode merges remote Copilot fields with existing UI metadata (`github-copilot/models.ts:107-161`). A generic “latest source wins” rule would discard defaults, labels, aliases, or transport metadata that the provider did not return.
- **Source labels need to be truthful.** Synara's Grok fallback returns `source: "grok-cli+xai-api"` when the CLI is empty and the API supplied the models (`GrokAdapter.ts:2455-2458`). This is a small competitor defect, but it demonstrates why source/provenance must be produced from the actual winning group rather than a coarse branch label.
- **Cache freshness alone is insufficient.** T3 compares manifest edit dates so a newer bundled release outranks an older disk cache (`ModelManifest.ts:336-355`); Codex checks identity and client version, not only age. A TTL-only Compozy cache can preserve a model catalog for the wrong account, provider binary, or schema.
- **Unknown model fallback must not fabricate reasoning.** Codex's unmatched model metadata has no reasoning levels/default (`.resources/codex/codex-rs/models-manager/src/model_info.rs:142-191`). That is safer than guessing from `gpt`/`grok` names; the UI can show the model as selectable while leaving reasoning unset until the provider confirms it.

## Open Questions

- Does the Compozy provider/ACP payload already carry a stable model key or descriptor generation that can scope config options, or must the contract add one? `deriveActiveSessionOptions` currently receives only `configOptions` and `selectedModel`.
- Which provider sources are authoritative for removal versus additive enrichment in Compozy? The answer must be explicit per adapter (for example, Codex app-server, Cursor ACP, Grok CLI, configured HTTP, and models.dev).
- Should provider-specific new effort values be accepted end to end as opaque strings, or should each adapter publish an allowlist/transport validator while the UI remains open? Competitors use both: Synara/T3 open descriptors and provider transforms validate at dispatch.
- Does the current live-source refresh/cache key include credential/account identity and provider binary version, or only provider/config path? The competitor cache evidence suggests this is necessary before enabling long-lived stale reuse.
- Can the UI distinguish an explicit provider “no reasoning” response from unavailable/stale metadata? Without that distinction it will continue to show “unsupported” for discovery failures and hide controls for models whose metadata simply has not arrived.
- The exact user-visible behavior for a model whose provider advertises reasoning but whose transport probe rejects the selected effort remains a product decision: disable the selection, fall back to provider default, or show a provider error while retaining the model.
