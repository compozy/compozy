## Summary

Valid `agh__network_send` calls failed with `tool_backend_failed` and `backend_unhealthy` in a real registered workspace even though the tool was enabled, available, authorized, executable, and callable. The equivalent CLI send succeeded for the same session, workspace, channel, and public-thread contract.

Every registered workspace has two legitimate identities: the runtime registry ID (`ws_...`) stored on sessions and Network peers, and the durable directory identity stored in `.agh/workspace.toml`. The native send adapter validated session ownership with the registry ID but sent the durable identity to the Network Router. The Router correctly rejected that mismatched workspace as an unknown local peer; the tool dispatcher correctly kept the raw backend detail out of the provider-visible error.

1. Start a session in a registered workspace and join a Network channel.
2. Confirm `network peers` shows the session under the registered `ws_...` workspace ID.
3. Call `agh__network_send` with the bound session, registered workspace, joined channel, `surface=thread`, a valid fresh `thread_id`, `kind=say`, and an object body.
4. Observe `tool_backend_failed` with `reason_codes=[backend_unhealthy]` and no Network audit row.
5. Send the equivalent payload through `agh network send`; observe a persisted message and implicitly created thread.

**Expected:** Native and CLI sends normalize a workspace reference to the registered runtime ID and publish through the same Network service boundary.
**Actual:** Native send passes the durable directory identity to the Router, which cannot match it to the session peer registered under `ws_...`.

## Fix

- **Root cause:** `internal/daemon.networkSend` used `ResolvedWorkspace.WorkspaceID` for `network.SendRequest.WorkspaceID`, while session ownership, local peer registration, stores, HTTP, UDS, and CLI use `ResolvedWorkspace.ID`.
- **Fix:** Resolve the registry workspace ID once and use it for both session ownership validation and the Network request. Keep the Hosted MCP and runtime-registry error masks unchanged.
- **Fix commit:** `f6748f2f`
- **Regression test:** The canonical native-send subtest now resolves deliberately distinct registered and durable identities and requires `Network.SendRequest.WorkspaceID` to equal the registered ID. The red run reported `01NATIVEWORKSPACEIDENTITY`; the green run passes.
