## Fix

- **Root cause:** The real-scenario bootstrap materialized an open-task description but never created and queued those tasks in the runtime. The single kickoff therefore reached only the Product Manager session; the declared owner pool had no claimable runs. The lab also registered a parent path that exposed QA contracts instead of the agent-only project root.
- **Correction:** Playbook tasks now receive deterministic runtime ids and are started idempotently behind an owned scheduler pause. The exact one-kickoff provider stream must be non-empty and confirmed before the helper releases dispatch. Only the agent-visible project root is registered, and global/scoped knowledge is projected into the declared workspaces. The activated retests then exposed and corrected the separate scheduler resume-age and saturated-capacity defects recorded in `BUG-20260715-scheduler-resume-starvation` and `BUG-20260715-serial-pool-starves-backlog`.
- **Fix commit:** pending Phase D checkpoint
- **Regression test:** The canonical bootstrap smoke suite covers deterministic materialization, preparation, kickoff confirmation, duplicate refusal, release ordering, idempotency, and failure-safe pause ownership. Release acceptance is a fresh one-kickoff real-provider run with all declared work completed.
