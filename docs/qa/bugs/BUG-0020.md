# BUG-0020: Switching back to a session workspace crashes the session page

- **Status:** fixed
- **Impact (user-side):** Blocks-Completion
- **Severity:** Critical · **Priority:** P0
- **Persona Affected:** Théo
- **Journey Step:** J-11 Return to a running session, step 2
- **Scenarios:** RT-041; RT-043; RT-045
- **Found:** 2026-07-08 · **Report:** docs/qa/reports/2026-07-08-session-improvements.md
- **Origin:** n/a

## Summary

Théo opens a permalink to a running session while the active workspace is different. AGH shows the
correct workspace mismatch notice, but after using **Switch back** the session route crashes instead
of rendering the running transcript. Retrying does not recover the page, leaving no interactive
session controls.

## Reproduction

- **Charter:** CH-014 · **Tour:** Interrupt Tour
- **Environment:** desktop / wifi-fast / en-US, deterministic QA lab

1. Bootstrap the task 43 QA lab and start the daemon with `AGH_WEB_API_PROXY_TARGET` pointing at the
   isolated daemon.
2. Create a real running session in workspace `qa-session-primary`:
   `sess-9f7f23fa5e200086` (`qa_faulty`, prompt `block until canceled`).
3. Open `http://localhost:3000/agents/qa_faulty/sessions/sess-9f7f23fa5e200086` while the active
   workspace is the home workspace.
4. Complete first-run setup with provider `acpmock` if prompted.
5. Observe the workspace mismatch toast: `Session "qa-reconnect-fault" belongs to workspace
   "qa-session-primary".`
6. Click **Switch back**.
7. Click **Retry** on the resulting error page.

**Expected:** The active workspace switches to `qa-session-primary`, the permalink remains on the
session route, and the running session renders its transcript/skeleton plus a truthful running
badge. A retry should recover transient render errors.

**Actual:** The route shows `Unable to load this page` with
`useClientLookup: Index 3 out of bounds (length: 3)`. The console reports the crash in
`<ThreadMessageComponent>`. After **Retry**, the page has no interactive elements.

## Fix

- **Root cause:** `ReadonlyThreadProvider` commits grown `messages` asynchronously, while the
  external virtualized rows were rendering `ThreadPrimitive.MessageByIndex` from the transcript
  length immediately. On a reconnect/workspace-switch growth from 3 to 4 messages, the virtual row
  addressed index 3 before the provider core knew about that index, throwing
  `useClientLookup: Index 3 out of bounds (length: 3)`. A second E2E failure exposed that persisted
  AGH `tool-*` error parts can include raw `output` payloads, which must be preserved for AGH
  renderers but sanitized before AI SDK validation.
- **Fix commit:** pending local diff (auto-commit disabled for task 43).
- **Fix:** `web/src/components/assistant-ui/session-thread.tsx` gates virtualized message rows on
  the readonly provider's committed message count and keys the provider by transcript identity.
  `web/src/systems/session/lib/message-schemas.ts` validates a sanitized dynamic-tool copy of AGH
  errored tool parts, then restores the original AGH tool payloads for rendering. The session clear
  control/dialog test IDs were hard-cut to the E2E contract used by the session hardening lane.
- **Regression test:** `web/src/components/assistant-ui/__tests__/session-thread.test.tsx`
  covers transcript growth after reconnect; `web/src/systems/session/adapters/__tests__/session-api.test.ts`
  covers AGH errored tool parts with raw output payloads.
