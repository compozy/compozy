# BUG-0025: Provider-scoped catalog refresh attached foreign live sources to the requested provider

- **Status:** fixed
- **Impact (user-side):** Trust-Damage
- **Severity:** High · **Priority:** P1
- **Persona Affected:** Ada; Marina
- **Journey Step:** J-20 refresh/status; J-22 provider Settings canary
- **Scenarios:** MS-043;MS-044;MS-055;MS-058
- **Found:** 2026-07-10 · **Report:** `docs/qa/reports/2026-07-10-model-selector.md`

## Summary

Refreshing Claude executed every registered provider-live source. The Claude status response and Settings inspector then listed `provider_live:codex`, `provider_live:gemini`, and other foreign sources as if they belonged to Claude.

## Reproduction

- **Charters:** CH-031; CH-033
- **Environment:** fresh isolated lab `model-selector-20260710-194713-914643`

1. Run `agh provider models refresh claude --force -o json`.
2. Read `agh provider models status claude -o json` or open Settings → Providers → Claude.

**Expected:** Only sources that declare Claude are executed and projected.  
**Actual:** Foreign provider-live source IDs were persisted and rendered under Claude.

## Fix

- **Root cause:** `CatalogService.Refresh` selected by source ID but did not filter selected sources by their declared `ProviderIDs` for provider-scoped refreshes.
- **Fix commit:** pending local diff; the user explicitly requested no commit.
- **Production fix:** `internal/modelcatalog/service_helpers.go` filters refresh execution and status projection by registered provider ownership; `service.go` applies the filter without growing the pre-existing over-cap file.
- **Regression:** `internal/modelcatalog/service_test.go` proves the Claude refresh never invokes or exposes the Codex source, including a pre-existing mismatched status row.

## Verification

- Fresh Claude refresh returned only `config`, `provider_live:claude`, `models_dev`, and `builtin`.
- The phone-large Settings retest rendered those same four sources and survived Back + refresh.
