# BUG-0032: Network histories reorder causally adjacent messages that share a timestamp

- **Status:** verified
- **Impact (user-side):** Functional
- **Severity:** High · **Priority:** P1
- **Persona Affected:** Théo; coordinating agents
- **Journey Step:** J-23 return to a long-running thread and continue safely
- **Scenarios:** NB-010
- **Found:** 2026-07-11 · **Report:** docs/qa/reports/2026-07-11-northstar-pay.md
- **Origin:** n/a

## Summary

Network message histories used `(timestamp, message_id)` as their stable ordering tuple. Protocol v0 timestamps have one-second precision and message IDs are random, so the tuple is deterministic but not causal. Messages written during the same second were reordered lexically by ID in REST/CLI pages and then re-sorted again by the Web cache.

In a real 125-message coordination thread, the persisted insertion order occupied old SQLite `rowid` values 118 through 242. The messages collapsed into only five timestamp buckets containing 9, 31, 32, 30, and 23 rows. Ordering each bucket by random `message_id` produced 60 adjacent causal inversions. This can reverse instructions, acknowledgements, or work-state transitions even though no row is lost.

## Fix

- **Root cause:** The timeline had no explicit causal identity; public storage reads, projections, recents, watch events, work replay, and Web merges inferred order from second-resolution timestamps plus random IDs.
- **Fix:** Append-only GlobalDB v71 rebuilds `network_timeline_log` with `sequence INTEGER PRIMARY KEY AUTOINCREMENT`, copying every historical `rowid` exactly. The pre-rebase QA build carried the same unshipped operation as local v68. All causal reads/projections use sequence. Public message cursors remain workspace/container-scoped `message_id`; thread/direct list cursors capture immutable message anchors and never serialize the global sequence. The Web preserves server page/tail order and replaces duplicates in place.
- **Fix commit:** `f6748f2f`
- **Regression tests:** Fresh and final-v70-baseline upgrade tests prove exact row preservation, sequence continuation/non-reuse, projection backfill, workspace isolation, and reopen. Canonical store/core/Web tests prove same-timestamp reverse-lexical IDs, stable cursor mutation, no sequence leakage, server-order preservation, and tail rollover.
