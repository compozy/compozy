# BUG-0038: Nested routes could erase active topbar controls

- **Status:** fixed
- **Impact (user-side):** Blocks-Completion
- **Severity:** High · **Priority:** P1
- **Persona Affected:** Bruno; Ada
- **Journey Step:** J-31 open or switch agent sessions and use lifecycle controls
- **Scenarios:** RT-076;RT-082
- **Found:** 2026-07-11 · **Report:** `docs/qa/reports/2026-07-11-agent-details.md`

## Summary

After a route transition or session-to-session navigation, the topbar could retain its title while losing all route-owned controls. On session detail this removed Clear, Delete, Stop, and Attach; on agent detail the same ownership flaw could remove New session, Edit settings, and overflow actions.

## Reproduction

1. Open a session detail route from an agent.
2. Create or navigate to a second session under the same parent route.
3. Wait for the session content to resolve.

**Expected:** The destination route owns the topbar and its lifecycle controls remain visible.
**Actual:** The parent `/agents` consumer or a late cleanup could publish an empty slot after the child published its controls. The route content loaded, but the topbar contained only the title.

## Fix

- **Root cause:** `TopbarSlotProvider` stored only a slot value, so every consumer cleanup called an unconditional `setSlot(null)`. In addition, the `/agents` parent published an object with undefined fields while a child route was active; React passive effects run child-first, allowing the parent to overwrite the child.
- **Fix commit:** `f7d8a96`.
- **Production fix:** the shared provider tracks slot ownership; only the current owner can clear its slot. A `null` consumer relinquishes ownership without overwriting another route. `/agents` now publishes `null` while rendering a child outlet.
- **Regression:** the canonical Topbar suite proves an older consumer cannot clear a newer slot and a non-owning null consumer cannot erase the active slot.
