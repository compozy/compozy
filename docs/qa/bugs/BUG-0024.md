# BUG-0024: Canonical Claude model IDs were sent literally to the ACP model option

- **Status:** fixed
- **Impact (user-side):** Blocks-Completion
- **Severity:** Critical · **Priority:** P0
- **Persona Affected:** Bruno; Ada; Lea
- **Journey Step:** J-21 Claude reasoning negotiation; J-17/J-19 Claude session creation

- **Found:** 2026-07-10 · **Report:** `docs/qa/reports/2026-07-10-model-selector.md`

## Summary

AGH persisted and exposed the canonical `claude-sonnet-5` ID correctly, but also sent that value literally to Claude ACP. Claude's provider-owned model option advertises `sonnet`, `opus[1m]`, and `haiku`, so a valid Claude Sonnet 5 + Max session failed with `model_unavailable` before the first prompt.

## Reproduction

- **Charter:** CH-032 · **Tour:** Feature Tour
- **Environment:** fresh isolated lab `model-selector-20260710-194713-914643`

1. Run `agh session new --provider claude --model claude-sonnet-5 --reasoning-effort max`.
2. Observe ACP valid choices `default, haiku, opus[1m], sonnet` and the pre-prompt `model_unavailable` failure.

**Expected:** Public APIs and persistence keep `claude-sonnet-5`; only the ACP boundary sends `sonnet`, then applies `max`.  
**Actual:** The canonical ID was used as the ACP option value.

## Fix

- **Root cause:** Session negotiation assumed catalog IDs and provider transport values were identical.
- **Fix commit:** pending local diff; the user explicitly requested no commit.
- **Production fix:** `internal/config/provider_model_transport.go` provides the explicit Claude-only transport mapping; `internal/session/manager_reasoning.go` applies it only at the ACP boundary. Unknown/custom values remain exact.
- **Regression:** `internal/session/provider_runtime_test.go`; the daemon reasoning E2E mock now advertises the real `sonnet` transport token while asserting canonical persistence.

## Verification
