# BUG-0035: Session status and inspection failed after deleting its agent definition

- **Status:** fixed
- **Impact (user-side):** Blocks-Completion
- **Severity:** High · **Priority:** P1
- **Persona Affected:** Ada; Bruno
- **Journey Step:** J-32 delete with an active session, then inspect after restart
- **Scenarios:** RT-080;RT-081
- **Found:** 2026-07-11 · **Report:** `docs/qa/reports/2026-07-11-agent-details.md`

## Summary

Deleting an agent definition left its active session and persisted event history intact, but `agh session status` and `agh session inspect` returned `agent_not_found`. The session therefore survived while its primary inspection surfaces became unavailable.

## Reproduction

- **Charter:** CH-052
- **Environment:** fresh isolated lab `agent-details-task-09-20260711-190957-738761`

1. Create a fixture-backed agent and start session `sess-3f410ebda7d8cca9`.
2. Begin a prompt and leave its permission request pending so the session is observably active.
3. Delete the agent definition through `agh agent delete --yes -o json`.
4. Approve the pending request and confirm the turn completes and history remains readable.
5. Run `agh session status sess-3f410ebda7d8cca9 -o json` or `agh session inspect ...`.

**Expected:** Persisted session health and history remain inspectable; definition-owned Heartbeat enrichment may be absent.
**Actual:** Both inspection commands returned `agent_not_found` because Heartbeat status reopened the deleted `AGENT.md`.

## Fix

- **Root cause:** `GetSessionStatus` and `InspectSession` treated optional Heartbeat enrichment as mandatory. The primary session health read succeeded, but `heartbeat.ErrAuthoringAgentNotFound` from the deleted definition replaced the entire response.
- **Fix commit:** `f7d8a96`.
- **Production fix:** `internal/api/core/session_heartbeat_status.go` classifies only `heartbeat.ErrAuthoringAgentNotFound` as unavailable optional enrichment. Status and inspection preserve the durable health payload while omitting `wake_state`; unrelated Heartbeat errors remain failures.
- **Regression:** `internal/api/core/authored_context_test.go` covers both status and inspection after deletion and proves unrelated Heartbeat errors are not swallowed.

## Verification

- Red-before/green-after regression: `go test ./internal/api/core -run '^TestSessionReadsSurviveAgentDefinitionDeletion$' -count=1`.
- The test-shape checker passed for the canonical suite.
- After rebuilding and restarting the lab daemon, `session status` returned the persisted stopped/dead health row, `session inspect` returned the same row without `wake_state`, and history retained all prompt, permission, completion, and shutdown events.
- Definition reads still report the deleted agent as absent.
