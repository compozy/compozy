# BUG-0033: Parked Loop recovery can contend with session reconciliation during daemon boot

- **Status:** fixed
- **Impact (user-side):** Blocks-Completion
- **Severity:** High · **Priority:** P0
- **Persona Affected:** Bruno
- **Journey Step:** J-16 Recover a parked watch-events Loop after a daemon restart
- **Scenarios:** LP-041
- **Found:** 2026-07-11 · **Report:** docs/qa/reports/2026-07-11-goal-execution.md
- **Origin:** n/a

## Summary

The runtime E2E restart case found that daemon boot started recovered Loop coordinators while the observer/session reconciliation phase was still running. Both paths touched the same SQLite-backed runtime state concurrently, so a parked watch-events Loop could fail recovery with a database-lock error instead of replaying its durable event exactly once.

## Reproduction

- **Charter:** Task 08 automated runtime backbone · **Tour:** Interrupt Tour
- **Environment:** current Goal worktree; serialized runtime E2E harness.

1. Start a daemon with a watch-events Loop parked on a task event.
2. Stop the daemon.
3. Commit the matching task event directly to the durable store while the daemon is down.
4. Restart the daemon against the same runtime home.
5. Wait for the Loop to replay the durable cursor gap.

**Expected:** Boot reconciliation completes, then the Loop coordinator backstop starts and wakes the parked Run exactly once from the durable row.  
**Actual:** The coordinator backstop started from `recoverBootTaskRuns` before final observer/session reconciliation completed, and the restart path failed with SQLite lock contention.

## Evidence

- Reproduction and regression owner: `internal/daemon/loop_run_events_e2e_integration_test.go`, `TestDaemonE2ELoopWatchEventsShouldWakeAndRecover/Should recover a parked watch-events loop from durable rows after restart`.
- Initial failing gate: `make test-e2e-runtime` on 2026-07-11.
- Fresh post-fix gate: `make test-e2e-runtime` passed all 70 runtime E2E cases on 2026-07-11.

## Fix

- **Root cause:** `recoverBootTaskRuns` combined durable task/Loop reconciliation with coordinator activation, while the recurring scheduler and Loop hook/watch observers also held independent activation paths. Moving only the explicit recovery call left those other paths able to cross the boot boundary.
- **Fix commit:** pending operator commit.
- **Production fix:** `recoverBootTaskRuns` now performs durable reconciliation only. A shared atomic `loopCoordinatorBootGate` wraps every coordinator activation source used by the recurring scheduler and the Loop hook/watch observers. `startBootLoopCoordinators` opens that gate only after `bootFinalize`, performs the initial backstop pass, and only then starts the recurring scheduler.
- **Regression tests:** `TestLoopCoordinatorBootGate/Should suppress observer and scheduler activation until reconciliation finishes` proves both observer and scheduler callers are inert before the barrier and delegate after it opens. The existing daemon runtime E2E restart case remains the end-to-end owner for the real stop/commit/restart/replay sequence.
