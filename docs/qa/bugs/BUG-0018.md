# BUG-0018: Fresh daemon cannot enroll the default dev-cycle extension.

- **Status:** verified
- **Impact (user-side):** Blocks-Completion
- **Severity:** Critical · **Priority:** P0
- **Persona Affected:** Lea / Operator
- **Journey Step:** J-01 Default dev-cycle launch and delivery, step 1
- **Scenarios:** ET-052; LP-001
- **Found:** 2026-07-06 · **Report:** `docs/qa/reports/2026-07-06-loops.md`

## Summary

Lea starts a fresh Loops lab expecting the default developer-loop package to be available, but the daemon exits before the catalog can load because the bundled `dev-cycle` manifest rejects the current daemon version.

## Reproduction

- **Charter:** CH-001 · **Tour:** Feature + Garbage
- **Environment:** laptop / Wi-Fi / en-US, deterministic QA lab

1. Bootstrap a fresh QA lab with the bundled `dev-cycle` extension enrolled by default.
2. Build and start the daemon from the current branch.
3. Read daemon startup status and logs.

**Expected:** The daemon starts, enrolls `dev-cycle`, and exposes the default Loops package.
**Actual:** Startup failed with an incompatible manifest error before the Loops catalog could be exercised.

## Evidence

- `docs/qa/evidence/2026-07-06-loops/ch001-dev-cycle-version-fix-log.txt`
- Independent read path after the fix: `docs/qa/evidence/2026-07-06-loops/ch001-fixed-extension-list-restored.json` shows `dev-cycle` active and healthy; `docs/qa/evidence/2026-07-06-loops/ch001-fixed-http-loops-restored.json` shows `reviews-watch` and `software-delivery` restored.

## Fix

- **Root cause:** The default-enrolled `dev-cycle` manifest declared a future `min_agh_version`, and daemon compatibility parsing treated git-describe build versions as stricter than their base tag.
- **Fix commit:** pending local diff
- **Regression test:** `internal/extension/manifest_test.go` (`TestValidateDaemonCompatibilityNormalizesDaemonBuildVersions`) plus `go test -race ./internal/extension -run 'TestValidateDaemonCompatibilityNormalizesDaemonBuildVersions|TestExtensionToolProviderCatalog|TestExtensionToolProviderAvailability' -count=1`

## Verification

- **Retested:** 2026-07-06, same persona/journey · **Report:** `docs/qa/reports/2026-07-06-loops.md`
- **Result:** Fresh daemon start succeeded after rebuild, `dev-cycle` loaded healthy, and the Loops catalog exposed both default loop definitions.
