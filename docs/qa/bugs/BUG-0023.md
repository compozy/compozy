## Summary

Ada could discover `ext__dev_cycle__import_tasks`, but could not call it through the public `agh tool invoke` surface. The daemon reported the read-only extension tool as registered, enabled, available, authorized, and executable, then denied the call with `source_disabled`. After BUG-0021 was fixed in the worktree, the same contract gap blocked `software-delivery`: `load_tasks` reached `ext__dev_cycle__import_tasks`, but the action could not consume the copied task graph from a workspace-relative pattern.

The 2026-07-09 fix-loop resolved both root causes for BUG-0023. Enabled bundled extension sources are trusted by the default runtime policy, and the daemon extension-tool wrapper anchors `ext__dev_cycle__import_tasks` relative patterns to the resolved workspace root while rejecting escapes.

## Fix

- **Root cause:** Two defects combined. First, the default native-tool source policy did not trust enabled bundled extension sources, so the discoverable read-only import tool was denied with `source_disabled`. Second, the dev-cycle import action received workspace-relative patterns from bundled loops, but the extension-host tool evaluated them outside the target workspace root.
- **Fix commit:** `f659c457` (`feat: loops refac finish`).
- **Production fix:** `internal/daemon/tool_policy_resolver.go` trusts enabled bundled extension source grants, and `internal/daemon/native_extension_tool_provider.go` wraps extension tool calls so `ext__dev_cycle__import_tasks` resolves relative `pattern` values against the request workspace root and rejects `../` escapes with `scope_mismatch`.
- **Regression tests:**
  - `internal/daemon/native_tools_test.go`: `Should trust bundled extension read only tools in default runtime policy`
  - `internal/daemon/native_extension_tool_provider_test.go`: workspace-root anchoring and escaping-pattern rejection
