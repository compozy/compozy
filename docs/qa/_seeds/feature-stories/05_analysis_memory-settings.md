## Overview

This slice covers AGH's **configuration and durable-knowledge control plane**: persistent memory (Memory v2 controller + dream consolidation + extractor + decision ledger), the unified Settings overlay (general/providers/mcp-servers/memory/skills/automation/network/observability/hooks-extensions sections plus apply/reload/restart/update lifecycle), the secret Vault, the native-provider Model Catalog, daemon Support bundles, log query/stream, and the operator filesystem browser used by onboarding. The web **Knowledge** route (`/knowledge`) is the UI front-end for the memory API; there is no `web/src/systems/memory` — `web/src/systems/knowledge` owns all memory queries/mutations. The web **Settings** route (`/settings/*`) is a nine-section tabbed surface, and **Vault** (`/vault`) is its own route.

The operator will most likely act on: (1) the large memory API surface (40+ endpoints) where several routes are **truthful-empty / unsupported stubs** that must be QA'd for honest behavior (recall trace always 404, dream status always empty list, extractor endpoints return "stopped"/empty or HTTP 501 when the runtime component is nil); (2) the **config lifecycle** (PATCH a section → apply record → restart banner → trigger restart → poll status), which is the highest-risk UX flow because mutations can be `pending-apply`/`blocked`/`failed` and require a daemon restart; (3) **Vault** write-only secret semantics and cross-scope typed-delete confirmation; (4) **Model Catalog** refresh/staleness; and (5) **Support bundle** consent gating.

Overlap with adjacent slices: the Settings sections for **automation**, **network**, **skills**, and **hooks-extensions** are registered here but their domain behavior belongs to other slices (autonomy/scheduler, AGH network, skills, extensions). **Logs/observability events** likely overlap a runtime-observability slice. **fs/browse** and **app_metadata onboarding** overlap the onboarding slice. These are captured as thin "settings-section exists" stories or noted in Risks to avoid duplicating domain stories.

## Mechanisms / Patterns

- **Shared `BaseHandlers` across HTTP+UDS:** every endpoint is a method on `core.BaseHandlers`; HTTP (`internal/api/httpapi/routes.go`) and UDS (`internal/api/udsapi/routes.go`) register the *same* handlers, differing only in auth (`privileged` middleware on HTTP mutations) — so most features are agent-manageable via CLI/UDS even when there is no web UI. `internal/api/core/memory.go:76`, `internal/api/httpapi/routes.go:356-392`, `internal/api/udsapi/routes.go:377-414`.
- **Memory v2 controller-decision pattern:** writes/edits/promotes/ad-hoc go through `store.ProposeCandidate` returning a `Decision` (`OpReject` → 422 with decision payload). The controller can accept, reject, or dedupe; the API never writes directly. `internal/api/core/memory.go:322-454,1136-1199`.
- **Truthful-empty / capability-gated endpoints:** when an optional runtime component is `nil`, handlers return honest empty/stopped states or HTTP 501 (`respondUnsupportedMemoryOperation`, status `http.StatusNotImplemented`). Examples: dream status always `[]` (`GetMemoryDreamStatus` :945), extractor status `stopped` when nil (:971), recall trace always 404 "not materialized" (:848-863), session-ledger/prune/repair 501 when `MemorySessionLedger==nil`. This is intentional per CLAUDE "truthful UI".
- **Memory health aggregation:** `MemoryHealth` scans global+workspace files, dream last-consolidation, indexed/orphaned counts; status ramps ok→disabled→degraded→unavailable. `internal/api/core/memory.go:1271-1359`. Surfaced in the Memory settings page health card.
- **Settings overlay = sections + collections + lifecycle:** sections (general/memory/skills/automation/network/observability/hooks-extensions) are GET/PATCH; collections (providers/mcp-servers/sandboxes/hooks) are list/get/PUT/DELETE; each mutation goes through `Settings.ApplySection`/`ApplyCollectionItem` with a `MutationSource` and returns a `SettingsApplyResponse` carrying lifecycle status. `internal/api/core/settings.go:47-573`.
- **Config apply lifecycle states:** `pending-apply | applied | blocked | failed` (`internal/config/lifecycle`), filterable via `GET /api/settings/apply`. `internal/api/core/settings.go:616-656`. Web surfaces this as `SettingsApplyRecordsPanel` + `RestartBanner` + restart store.
- **Daemon restart flow (async):** `POST /api/settings/actions/restart` → 202 + operation; `GET /api/settings/actions/restart/:operation_id` polls; terminal statuses tracked in `use-settings-restart-store`. `internal/api/core/settings.go:316-352`, `web/src/systems/settings/lib/restart-status.ts`.
- **Memory-provider validation on settings save:** changing `memory.config.provider.name` to a non-`local` provider is validated against the live provider registry (`extension.ErrMemoryProviderNotFound` → 422). `internal/api/core/settings.go:727-752`.
- **Vault write-only secret model:** `PUT /api/vault/secrets` stores a value that is never returned; only redacted metadata (ref/namespace/kind/present/timestamps) is exposed. Refs must be `vault:<namespace>/...`; namespaces validated. `internal/api/core/vault.go:73-128,169-196`. Web enforces typed-confirmation for cross-scope deletes, immediate delete for `vault:sessions/`. `web/src/routes/_app/vault.tsx:332-385`.
- **Vault response redaction registry:** `newVaultSecretRedaction`/`replaceVaultSecretRedaction` register the secret value for log/SSE redaction at write time, unregister on delete. `internal/api/core/vault.go:91-126`.
- **Model catalog single dispatch route:** `GET|POST /api/model-catalog/*catalog_path` is parsed into `models | providers/:id/models | sources/status | .../refresh`. Also an OpenAI-compat `GET /api/openai/v1/models`. Refresh returns per-source statuses; errors are redacted (`modelcatalog.RedactString`). `internal/api/core/model_catalog.go:26-150`.
- **Support bundle = async + consent-gated:** `POST /api/support/bundles` requires `yes:true` else 400 `bundle.consent_required` (structured diagnostic). Runs on a detached context (`context.WithoutCancel`), returns 202 + operation with status URL; download streams gzip. `internal/api/core/support.go:21-107`.
- **Logs = observer query + SSE poll:** `GET /api/logs` queries events; `GET /api/logs/stream` replays from `Last-Event-ID` cursor then polls on a ticker. `internal/api/core/handlers.go` ListLogs/StreamLogs.
- **fs/browse = read-only operator-scoped picker:** `GET /api/fs/browse?path=&show_hidden=&dirs_only=` lists immediate entries, requires absolute path, rejects control chars, `EvalSymlinks` hardening, sorts dirs-first. `internal/api/core/fs_browse.go:19-137`.
- **app_metadata KV store:** generic `GetAppMetadata/SetAppMetadata/DeleteAppMetadata` plus onboarding-completed marker. `internal/store/globaldb/global_db_app_metadata.go:15-133`.
- **Observability log-tail SSE:** `GET /api/settings/observability/log-tail` tails the daemon log file with rotation detection. `internal/api/core/settings.go:354-408`.

## Transferable Patterns

- **Truthful-empty/501 capability gating** → applies to QA test design for the whole memory surface: the parent's test loop must assert honest empty/stopped/404/501 responses (recall-trace, dream-status, extractor, session-ledger) rather than treating them as bugs. Augments naive "endpoint returns 200" checks.
- **Controller-decision (`ProposeCandidate`) accept/reject contract** → reusable test shape for all memory writes (create/edit/promote/ad-hoc): every story should test both the applied path and a policy-reject (422 + decision payload) path. Augments the per-endpoint story with a negative case.
- **Config-lifecycle (apply → pending/blocked/failed → restart → poll)** → the canonical risky UX flow; the parent should run one end-to-end QA journey (PATCH a section that needs restart → see banner → trigger restart → poll terminal → reconnect) covering MS-025/032/033/035. Replaces testing each settings section in isolation.
- **Write-only secret + redaction registry (Vault)** → security QA pattern: assert the secret value never appears in list/get/logs/SSE/error payloads. Applies to MS-038..041 and cross-checks the claim-token/secret redaction invariant.
- **Shared `BaseHandlers` HTTP+UDS parity** → for every web story, there is an agent/CLI path; the parent's "agent-manageable" QA can drive the same handler over UDS. Augments web-only manual testing.
