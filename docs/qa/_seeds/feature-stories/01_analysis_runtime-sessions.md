## Overview

This slice covers the **core runtime control plane**: the daemon-status surface, first-run onboarding, workspace registration, the full session lifecycle (create → prompt/stream → attach/resume → stop/repair/clear → delete), provider inventory & auth probing, agent definitions (list/get/create + soul/heartbeat authoring), the agent-facing identity/context/spawn surfaces, the workspace coordinator config, and sandbox-profile management. Every REST endpoint is implemented once in `internal/api/core` as a `BaseHandlers` method and registered by **both** the HTTP transport (`internal/api/httpapi/routes.go`, web UI, loopback-guarded) and the UDS transport (`internal/api/udsapi/routes.go`, CLI IPC), giving HTTP/UDS parity for almost every verb. A small set of operations are agent-only (kernel routes: `/agent/me`, `/agent/context`, `/agent/spawn`, `/agent/coordinator/config`) gated by daemon-validated caller identity from `AGH_SESSION_ID`/`AGH_AGENT` headers.

The operator is most likely to act on the **session lifecycle and prompt flow** (create a session, send a prompt, watch the SSE stream, approve a permission, steer/interrupt/queue, stop, clear, delete) and the **workspace + onboarding setup** that gates everything else. These are the highest-traffic, most testable journeys and the ones with the most web UI coverage (`agents.$name.sessions.$id.tsx`, `session-inspector`, `permission-prompt`, `runtime-activity-notice`).

This slice overlaps with adjacent slices at the edges: `/agent/channels*` and the coordination channel surface belong primarily to the **network** slice; coordinator bootstrap and task-run claim/lease semantics belong primarily to the **tasks/autonomy** slice (this slice only captures the read-only coordinator *config* surface and the agent *spawn* primitive). Memory inspector content, vault secrets, and settings collections (other than sandbox profiles) are owned by other slices. Where a control here reads from those (e.g. session inspector showing memory/vault), I note the overlap rather than duplicating the story.

The dominant architectural truth for testing: **execution is detached from the request** (`context.WithoutCancel` on prompt/steer in `httpapi/prompt.go:43,133`), so cancelling an HTTP stream does NOT cancel the running turn — there are explicit cancel/interrupt endpoints for that. Status code + body must both be asserted; error mapping is centralized in `statusForSessionError`/`statusForWorkspaceError` (`session_workspace.go:130-195`).

## Mechanisms / Patterns

- **Shared-handler / dual-transport parity:** Every endpoint is a `BaseHandlers` method in `internal/api/core`; HTTP and UDS only differ in registration + auth (HTTP adds loopback guard + `privilegedMutationGuard`). See `httpapi/routes.go:6-526` vs `udsapi/routes.go:6-549`. Implication: each story is testable over both `:2123` HTTP and the UDS socket; behavior must match.
- **Workspace-scoped session routes:** Session mutations live under `/api/workspaces/:workspace_id/sessions/:session_id/...` (`routes.go:113-135`), but list/create are flat (`/api/sessions`). Sessions carry a `workspace_id`; deleting a workspace requires no *active* sessions and cascades deletion of stopped ones (`workspaces.go:228-305`).
- **Session lifecycle state machine:** `Create` (type=user) → live → `Stop` (keeps history) / `Delete` (removes history) / `ClearConversation` (same id, fresh ACP context, wipes transcript) / `RepairSession` (dry-run/force on interrupted transcript) / `AttachSession` (short-lived lease, no new authority). Handlers: `handlers.go:405-611`.
- **Prompt flow + detached execution:** `promptSession` extracts the last user message, runs `SendPrompt` on a `context.WithoutCancel` execution ctx with a separate delivery ctx, and either returns an accepted/queued/staged JSON result or streams a Vercel-AI-UI SSE message (`httpapi/prompt.go:25-104`). Prompt modes: default, `queue`, `interrupt`, `steer` (`use-session-actions.ts:283-322`, `prompt.go:106-157`). Cancel endpoints: `/prompt/cancel` (cancel active), `/interrupt`, `/prompt/queue/:queue_entry_id` (cancel queued).
- **SSE prompt-stream encoder + redaction:** `PromptStreamEncoder` (`prompt_stream.go:118-549`) converts raw ACP events to typed `start/text-delta/reasoning-delta/tool-input-*/tool-output-available/data-agh-permission/finish/[DONE]` frames; all text/raw is redacted via `promptRedactString`/`promptKeyCarriesSecret` (`prompt_stream.go:710-739`) — secrets (api keys, tokens, PKCE) never reach the wire.
- **Permission approval loop:** Permission events surface as `data-agh-permission` frames; the user approves/denies via `POST /sessions/:id/approve` with `{request_id,turn_id,decision}` validated by `acp.ApproveRequest.Validate()` (`httpapi/sessions.go:13-45`). Web surfaces this through `permission-prompt.tsx`.
- **Live event replay + reconnect:** `SessionEvents`/`SessionHistory`/`StreamSession` accept `Last-Event-ID`/`after_sequence` for durable replay (`handlers.go:614-659,1040-1083`); `StreamSession` writes a backlog batch then long-polls. `SessionRecap` builds a deterministic recap (recent markers/messages, pending inputs, cursors) from persisted reads only (`handlers.go:716-772`).
- **Runtime overrides on create:** create-session accepts `provider`/`model`/`reasoning_effort`; `provider` is required if `model` or `reasoning_effort` is set, and `reasoning_effort` must pass `session.ValidateReasoningEffort` (`session_workspace.go:46-62`). Web exposes provider/model/reasoning command-selects (`web/src/systems/runtime/components/{provider,model,reasoning}-command-select.tsx`).
- **Provider inventory + auth classification:** `ListProviders`/`GetProvider` merge builtin + configured providers and classify declared auth (`providers.go:117-153`); `ProbeProviderAuth` runs the live `auth_status_command` with isolated env and returns a classification + redacted probe output (`providers.go:52-115`). `auth_mode=none` short-circuits to "no auth required"; missing status command → 422. Login itself is the provider's own CLI (`AuthLoginCmd`/`SuggestedCommand`) — there is **no HTTP login endpoint**.
- **Agent-identity gate (kernel surface):** `/agent/me`, `/agent/context`, `/agent/spawn`, `/agent/coordinator/config`, `/agent/channels*` resolve a daemon-validated caller from `X-AGH-Session-Id`/`X-AGH-Agent`/`X-AGH-Workspace-Id` headers via `agentidentity.Resolve` (`agent_identity.go:69-131`). Failure modes map to 401/403/503 (`agent_identity.go:26-42`).
- **Bounded agent spawn:** `/agent/spawn` creates a child session with TTL, auto-stop-on-parent, spawn role, prompt overlay, and a narrowed permission policy (tools/skills/mcp/paths/channels/sandboxes), enforcing spawn limit/permission/validation errors → 409/403/422 (`agent_spawn.go:26-135`).
- **Situation/context surface:** `/agent/context` returns a bounded `AgentContextPayload` — self identity, workspace, session, soul, capabilities, limits, task + coordination channel, inbox summary, peer roster (`situation/service.go:216-296`).
- **Coordinator config (read-only here):** `/agent/coordinator/config` resolves enabled/agent/provider/model/TTL/max-children/max-active-per-workspace with a global-or-workspace source (`agent_contracts.go:11-27`, `agent_identity.go:163-180`). Coordinator tool allowlist + operational message kinds are fixed constants (`coordinator.go:36-74`).
- **Authored agent context (soul + heartbeat):** Full CRUD + history + rollback + validate for `SOUL.md` and `HEARTBEAT.md` per agent, plus per-session soul refresh with expected-digest optimistic concurrency, heartbeat wake, and heartbeat status (`authored_context.go:126-409,412-755`).
- **Session health/inspect:** `GET .../health|status|inspect` return health, active-prompt, attachable, wake eligibility/ineligibility reason, and (inspect) policy/config digests + recent wake events (`authored_context.go:756-833`).
- **Onboarding flag:** `GET/POST complete/DELETE /api/onboarding` is a single persisted "completed + completedAt" flag; the web wizard (3 steps: default model → workspaces → onboarding chat) calls complete (`onboarding.go:13-73`, `onboarding-wizard.tsx`).
- **Sandbox profiles:** Managed via the settings-sandbox collection (`/api/settings/sandboxes*`); web `sandbox.tsx` lists/creates/edits/deletes overlay profiles with backends `local` (host, no sandbox) and `daytona` (cloud); builtin profiles cannot be deleted, only overridden; PUT is a full replace; usage count shows referencing workspaces.
- **Filesystem browse:** `GET /api/fs/browse` (`routes.go:63-66`) backs the onboarding/workspace directory picker (`onboarding/components/directory-browser.tsx`).
- **Web home dashboard:** `/_app/` shows daemon status card (version, connection) + metric grid (active sessions, workspaces, agents, uptime) with loading/error/disconnected states (`routes/_app/index.tsx`).
- **Session permalink redirect:** `/_app/session/$id` resolves the session's agent and redirects to `/agents/$name/sessions/$id`, with not-found fallback (`routes/_app/session.$id.tsx`).
- **Active-workspace selection:** Web persists an active workspace (zustand store `useActiveWorkspaceStore`, `useActiveWorkspace`) that scopes session lists and mutations; a workspace guard redirects when a session's workspace differs (`agents.$name.sessions.$id.tsx:166`).

## Transferable Patterns

- **Dual-transport story testing** → applies to QA automation for the whole spreadsheet: every runtime story can/should be exercised over both HTTP `:2123` and the UDS socket because handlers are shared (`httpapi/routes.go` ↔ `udsapi/routes.go`). This lets the testing loop assert agent-manageability (CLI/UDS) without the web UI.
- **Centralized error→status mapping** (`statusForSessionError`/`statusForWorkspaceError`/`statusForAgentSpawnError`/`StatusForAgentIdentityError`) → gives the test loop a precise expected-status oracle per error class (404/409/410/422/403/401/503/499) instead of guessing.
- **Detached-execution contract** (`context.WithoutCancel`) → the testing loop must verify that closing/aborting an SSE prompt stream does NOT stop the turn, and that the explicit cancel/interrupt endpoints are the supported stop path. This is a known UX trap to test deliberately.
- **Secret-redaction at the encoder boundary** (`promptRedactString`, `promptKeyCarriesSecret`, `diagnostics.Redact`) → security assertions reusable across every SSE/status story: probe stdout/stderr, status messages, prompt frames must never leak `api_key`/`token`/PKCE.
- **Optimistic-concurrency via expected digest** (soul refresh, authored context) → the test loop can assert conflict handling by sending a stale digest.

## Risks / Mismatches

- **Provider login has no in-product action (RT-027).** UI/status only surface a `suggested_command`/`login_command`; native_cli providers rely on the provider's own CLI login state. This is intentional (security boundary: AGH never stores native creds, per `internal/CLAUDE.md` Provider auth boundary), but is a likely operator UX gap: "Why can't I log in from the dashboard?" Flag as UX/logistics risk, not a bug, and confirm expected behavior before "fixing".
- **Daytona sandbox backend may be inert locally (RT-037).** `sandbox.tsx` offers `daytona` (cloud) as a selectable backend, but local QA without Daytona credentials cannot exercise it; sessions using it may fail to resolve. Test `local` end-to-end; treat `daytona` as configuration-gated and capture as a conditional story, not a guaranteed-working flow.
- **Privileged-guard asymmetry between transports.** HTTP wraps onboarding/settings/extension/skill/vault/tool mutations in `privilegedMutationGuard`; UDS does not. The testing loop must not assume identical auth on both transports — capture the guard difference rather than reporting a "missing auth" bug on UDS (it is the trusted local IPC).
- **Coordinator bootstrap & heartbeat wake semantics overlap the tasks/autonomy slice.** RT-033 (coordinator *config* read) and RT-036 (heartbeat authoring/wake surface) intentionally capture only the runtime-control surfaces; the *behavioral* coordinator bootstrap (task-run-triggered) and wake scheduling belong to the autonomy slice. Avoid duplicating those behavioral stories — cross-reference instead.
- **`/agent/channels*` belongs to the network slice.** Captured here only as part of the agent-kernel identity gate (RT-031 context references inbox/peers). The channel send/recv/reply stories should be owned by the network slice to avoid duplication.
- **Workspace-delete cascade is a data-loss path.** RT-008 deletes stopped sessions on workspace delete; the active-session 409 guard is the only safety. Worth a deliberate destructive-path test.
