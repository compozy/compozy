# Official-skill references must agree with the runtime they describe

- Source: BUG-20260825-skill-source-agent-write-doc-mismatch / `ET-skill-source-agent-parity` / `ET-compozy-official-skill-discovery`
- Why automate: `skills/compozy/references/*.md` is prompt-resident context every agent trusts before acting, and nothing gates it against the runtime. Two files shipped the claim that `compozy__config_set` denies `skills.sources` and `skills.custom_sources` with `config_trust_root_forbidden` while the tool has always written them successfully — a QA walk was the only thing that caught it, one full program after the docs landed. The failure is silent and self-reinforcing: an agent reads the reference, never attempts the write, and never discovers the reference was wrong.
- Suggested layer: a check in the `codegen-check` family that parses the error codes and tool ids asserted in `skills/compozy/references/*.md` and fails when a cited code is not emitted by the path the sentence names. Narrower fallback: a Go test that extracts every `compozy__config_*` denial claim from those references and asserts it against `ClassifyToolConfigPath` for the same key.
- Spec sketch: extract `(tool_id, config path, expected outcome code)` triples from the references; for each, call the real classifier/tool surface; fail on any triple whose runtime outcome differs. True end state: an agent that reads a reference and acts on it gets the outcome the reference promised.
- Interim guard shipped with the fix: `internal/config/tool_surface_test.go` (`TestToolConfigPathPolicy`) now pins both skill-source paths as agent-mutable string slices, so the code cannot silently drift back to denial and re-falsify the corrected sentence. That pins one direction only — it does not detect a *new* wrong claim in a reference, which is what this entry is for.
- Status: proposed
