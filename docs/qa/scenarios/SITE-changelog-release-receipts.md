Behavior changed by the release-receipt redesign: site changelog MDX is now generated by the release
publication job from the real tag and the release planner's exact predecessor-to-release range,
rather than by the release PR or a locally recomputed predecessor. `releaseStatus` reports the
prerelease channel over `breaking`.

## Steps

1. Publish a beta via the release flow (merge release PR with `RELEASE_AUTO_CHANNEL=beta`).
2. Confirm a `build: publish site changelog receipt v<X.Y.Z-beta.N>` commit lands on `main` and the site deploy shows the entry with status `beta` and a working compare link.
3. Publish the next beta and confirm its entry contains only changes from the prior beta tag to the new release commit.
4. Confirm no `/changelog` entry advertises a version whose tag does not exist.
5. With no receipts present, confirm `/changelog` renders the "Follow the beta" empty state.
