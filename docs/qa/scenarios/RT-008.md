## Project menu and Settings removal

The project action menu exposes Remove project in the picker and Settings. Its confirmation names
stopped session history, window bindings, and the new ID on re-add, and states that disk files remain.
Cancel preserves the registration. Archive instead opens the lossless archive confirmation for an
active project. Successful removal uses the existing DELETE route and its existing refusal rules.

qa-impact: 2026-10-28 archive/remove lifecycle slice passed against an isolated daemon and
production web bundle. See `docs/qa/reports/2026-10-28-archive-projects.md`; older unrelated
scenario verdicts above are retained rather than inferred from this focused walk.

## Missing project folders

Rename a registered project folder away after stopping its sessions. The project remains listed
with `root_missing: true` and “Folder not found” in Settings and the picker. Archive and Remove
remain available; selecting the project allows retained history reads, while creating a session
returns `workspace_root_missing`. Rename the folder back and refresh: the warning clears and the
same workspace ID and history remain. A missing folder never deletes a registration; explicit
Remove is the only destructive path. Confirm Remove separately and verify the existing cleanup
invariant, rather than treating a missing folder as consent to delete data.

## Inaccessible roots and deferred automation replacements

A permission or disk error in one registered project folder must not prevent listing
healthy projects or accessing that registration to archive, restore, or remove it.
Runtime resolution still refuses an inaccessible root; a failed inspection is logged
and is not classified as a confirmed missing folder.

Change an existing managed global job/trigger to target an archived project's Loop.
The refused replacement must persist a disabled overlay for the previous definition,
including after manager restart. Restore the project and sync the source again;
the requested definition is applied but stays paused until explicitly enabled.
New definitions with archived targets remain deferred. Source files and run history stay intact.

Automation resource tests exercised config/package sources, legacy/resource stores,
persisted disabled overlays and manager startup. Full UI and CI validation remain CI-owned.
