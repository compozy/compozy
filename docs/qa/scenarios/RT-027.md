story: As the runtime admin I want to authenticate a native provider without exposing its configured login command through any read surface

errors: Historical evidence covered the removed `--print-command` behavior and is stale. The new walk must prove write-only config input, redacted config readback, the safe descriptor across status/doctor/Settings/HTTP/UDS, internal CLI execution with only `--no-tty` and `--timeout`, and the absence of an HTTP/UDS login endpoint.

The safe descriptor is limited to configured state, source, executable basename, presence, and recommended action. It must never reveal arguments, an environment prefix, or a resolved executable path.

QA 2026-08-02: write and config-read redaction passed, but the provider descriptor exposed the environment prefix as the executable. The session stopped and filed `BUG-20260802-provider-login-secret-disclosure` before executing the login command.

QA rewalk 2026-08-03: both CLI config and `compozy__config_set` accepted the write-only value and returned redacted output. The internal CLI login executed the private environment prefix and arguments, reached `authenticated`, survived daemon restart, and every CLI/HTTP/Settings/Doctor/Web read retained only `qa-login-runner`. HTTP and UDS login routes remained absent. The disclosure bug is verified fixed in the working tree.
