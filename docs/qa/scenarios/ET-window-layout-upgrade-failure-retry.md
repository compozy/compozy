story: An operator whose old layout cannot be converted keeps working on an empty desktop and gets the layout back once the conversion can run, without losing either.

scope: The conversion failure path, the preserved backup, Retry with and without replace, the conflict guard, and a re-upgrade after a failed conversion.

Walk: Preconditions: an isolated lab from `eng-qa-bootstrap` running this build (unique home, port and socket), one workspace registered and opened once so its layout exists.

Seed fixtures (daemon stopped). The seeder is `web/e2e/fixtures/retired-knowledge-window-seeder`; its raw mode takes only `--home`, `--workspace`, optional `--profile` (default profile unless the lab uses another), `--raw-snapshot <file>` and `--raw-key snapshot|legacy` (default `snapshot`), and refuses any layout-building flag. It writes the file's bytes unchanged under the window-manager key `snapshot:<profile>` or `legacy:<profile>` through the client-state engine with a revision guard, without converter validation, and prints the stored value. Never edit the client-state database (`<home>/state/clientstate.db`, bbolt) by hand.

- `broken-v5.json`: `{"version":5,"windows":{"broken":{}}}`, a version 5 value the converter rejects (the value the Go suite uses in `internal/daemon/window_manager_repository_test.go`).
- `good-v5.json`: a convertible version 5 value for the same workspace. Copy the whole lab home (`cp -R <home> <home>-copy`) with the daemon stopped, run `go run ./web/e2e/fixtures/retired-knowledge-window-seeder --home <home>-copy --workspace <id> --floating <window-id>` there, and save its stdout as `good-v5.json`. The copy keeps the workspace id, which the conversion checks.

Seed: `go run ./web/e2e/fixtures/retired-knowledge-window-seeder --home <home> --workspace <id> --raw-snapshot broken-v5.json`.

1. Start the daemon and open the workspace: one desktop with a New tab window and the failure notice with Retry and Dismiss. `compozy layout migration status --workspace <id> -o json` shows `state: "failed"`, `from_version: 5`, `acknowledged: false` and `error.code`, and no `failure_revision` (omitted because the fallback desktop is revision 0).
2. Click Retry without changing anything: the value still fails, so the notice returns (briefly "Retrying"), and status stays `failed`.
3. Stop the daemon and write the convertible backup: `go run ./web/e2e/fixtures/retired-knowledge-window-seeder --home <home> --workspace <id> --raw-snapshot good-v5.json --raw-key legacy`. The stored layout is the v6 fallback desktop, so the next start does not convert again and the failure notice is still showing. Start and click Retry: the layout converts, "Your windows are now tabs" shows, and status is `migrated` with no `failure_revision`.
4. Conflict guard. Stop, run "Seed" again and start: status `failed`; the convertible backup from step 3 is set aside as `superseded:<profile>:<sha256 of good-v5.json>` and `error.message` ends with "1 earlier layout backup(s) were set aside and preserved; retry uses the current legacy backup." Stop, rerun the step 3 command, start, and open a window so the layout revision moves past the failure. Click Retry: the toast reads "Your layout changed after the upgrade failed, so it was kept as it is." and the window stays. `compozy layout migration retry --workspace <id>` answers `window_manager_revision_conflict`; `compozy layout migration retry --workspace <id> --replace` replaces the current layout with the converted one and status becomes `migrated`.
5. The workspace is now migrated: `compozy layout migration retry --workspace <id>` is rejected as an invalid command (422 over HTTP).
6. Dismiss. Stop, run "Seed" again and start: status `failed` and the failure notice shows (the backup from step 4 is set aside under the same key as before, so the message still says "1 earlier layout backup(s) …"). Click Dismiss: the notice closes in every connected client and status shows `acknowledged: true`. Run `compozy layout migration retry --workspace <id>`: the retry still runs on the kept backup, fails again, and resets `acknowledged` to `false`, so the notice returns.
7. Re-upgrade after a failed conversion. Step 6 leaves the workspace `failed` with the broken value as its backup. Stop and write the layout a v0.6 daemon would have saved in the meantime: `go run ./web/e2e/fixtures/retired-knowledge-window-seeder --home <home> --workspace <id> --raw-snapshot good-v5.json`. Start and open the workspace: it loads (no `window_manager_unavailable`, no 503) with the converted layout. `compozy layout migration status --workspace <id> -o json` shows `state: "migrated"`, no `failure_revision`, and `error` with `code: "migration.backup_superseded"`, `path` naming a `superseded:<profile>:` key, and the message "2 earlier layout backup(s) were set aside and preserved; retry uses the current legacy backup." (the count covers every set-aside backup of the profile).
8. Both byte sets are retrievable. Stop the daemon and read the bbolt store with the module's own CLI at the `go.mod` version, `go run go.etcd.io/bbolt/cmd/bbolt@v1.5.0` (written `bbolt` below). `bbolt keys <home>/state/clientstate.db ws:<id> window_manager` lists `legacy:<profile>`, `superseded:<profile>:<shasum -a 256 broken-v5.json>` and the step 4 key for `good-v5.json`. `bbolt get --format bytes <db> ws:<id> window_manager <key>` prints the stored entry framed as a 25-byte header, the value, then one LF added by the CLI (`writelnBytes` → `fmt.Fprintln` in `cmd/bbolt/command/utils.go`). Extract byte-exactly against each fixture without editing it: `bbolt get --format bytes <db> ws:<id> window_manager <key> > out.bin`, `n=$(wc -c < <fixture> | tr -d ' ')`; then `test "$(wc -c < out.bin | tr -d ' ')" -eq $((25 + n + 1))` (nothing extra), `tail -c 1 out.bin | od -An -tx1` prints `0a` (the CLI's LF), and `tail -c +26 out.bin | head -c "$n" | cmp - <fixture>` succeeds. The superseded key must match `broken-v5.json` and `legacy:<profile>` must match `good-v5.json`.
