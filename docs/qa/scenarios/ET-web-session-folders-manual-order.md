New folder asks for a name and adds a collapsible folder (chevron, folder icon, name, count) at the top, expanded by default with a trailing New session row that creates the session inside it. Right-click on a root session row opens the same actions as its … menu plus Move to folder (submenu of folders), Remove from folder when foldered, and Move up/Move down in Manual sort; Shift+F10 opens it from the keyboard. Right-click on a folder header offers New session in folder, Rename folder…, Move folder up/down, and Delete folder… (confirmation; sessions return to the list, none deleted). The sort menu has a fifth option, Manual, which shows folders first and then the root in the operator's order. Dragging a root session onto a folder header moves it into the folder in any sort; dragging between rows in Manual sort reorders within the folder or root with a visible drop line; dragging a folder header reorders folders. Manual reorder (row drag and Move up/Move down) is offered only when the whole container is on screen: not while a filter or a worktree scope narrows the list, and not on a later catalog page; moving into or out of a folder stays available. If the folder list fails to load, the list stays flat and shows "Couldn’t load folders." with Retry, which brings the folders back. The session-cycle shortcut follows the folder order and skips sessions inside a collapsed folder. A rejected mutation rolls the list back and shows an error. Folders, membership, and order persist across reload and daemon restart, reach another open window live, are per profile and workspace, and are also manageable through `compozy session folder|move|reorder` and the `compozy__session_folder_*`, `compozy__session_move`, and `compozy__session_reorder` tools. Children and subagents stay under their parent and are never foldered or dragged on their own. A flat All-workspaces list keeps rows flat and shows New folder disabled with its reason; grouped lists carry each pair's folders and manual order (ET-web-session-list-aggregate-parity). With several sessions selected, the selection bar's … menu offers Move to folder (the folders, No folder when a selected session is filed, New folder… that creates a folder and moves the selection into it), and dragging any selected row carries the whole selection onto a folder (anywhere on it, header highlighted, collapsed or empty) or the root; dragging an unselected row still moves only that row. A bulk move is one atomic write of the selected thread roots in on-screen order, skips sessions already in the target, announces the result in a toast, and ends the selection; a refusal rolls back and keeps the selection. A child-only selection or one spanning profiles explains why it cannot move.

Folder state lives in the global SQLite database (`session_folders`, `session_placements`, migration 00139) and never in browser storage; only the per-client folder collapse state is local view state.
