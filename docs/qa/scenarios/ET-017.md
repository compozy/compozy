QA impact 2026-11-13 (install replace): `POST /api/extensions`, `compozy extension install
--replace`, and `compozy__extensions_install {replace: true}` now replace the installed package of the
same name instead of refusing it. Walk three legs on a local fixture. (1) Successful replacement:
install `qa-local-ext` 1.0.0, then install 2.0.0 with `replace=true` and confirm the managed directory,
the registry version, the checksum, and every existing attachment report 2.0.0, with no duplicate
attachment and the staged previous directory gone. (2) Failure recovery: install a replacement whose
checksum mismatch (or unreadable manifest) fails before publication and confirm 1.0.0 stays installed,
byte-identical, invocable, and reported by `compozy extension status` and `GET /api/extensions/:name`;
the post-publication failure path is automated and does not need a manual walk. (3) Authority: a
workspace-bound caller with write authority that sends `replace=true` for a globally installed
extension receives 403 `permission denied` and the global package stays byte-identical, while the
same caller may replace an installation attached only to its own workspace. Automated coverage before
the manual walk: `TestDaemonExtensionInstallReplaceAuthority` (daemon authority),
`TestDaemonExtensionLocalInstallReplace` (post-commit restore and marketplace-name refusal),
`TestInstallLocalManagedReplace` and `TestInstallLocalManagedReplaceTransaction` (package-level backup
and restore). HTTP and UDS legs remain pending.

QA impact 2026-11-14 (local replace uses the reinstall transaction): a local replacement no longer
publishes through the local-only install path. It stages the previous directory, commits the new
package, and only drops the backup after reload and the returned status step succeed, so a failure in
input binding, Gateway confirmation, declared profiles, reload, or target status restores the previous
version, registry record, and Gateway confirmation instead of uninstalling. Without `--scope`, a
replacement manifest whose MCP `default_scope` resolves to a workspace with no attachment now fails
after the commit and is restored; re-run with an explicit `--scope`/`--workspace` that has an
attachment, or install that scope first. A local bundle can no longer overwrite a marketplace-owned
name: that returns `extension_name_conflict` with `installed_origin`, so marketplace provenance and
update tracking survive. Automated coverage: `TestDaemonExtensionLocalInstallReplace` and
`TestInstallLocalManagedReplaceTransaction`; no scenario replay ran.

QA impact 2026-11-13 (replace authority under the lifecycle lock): the replacement rechecks the
caller's authority inside the install commit, under the lifecycle lock, instead of trusting only the
preparation-time check. A package attached to a workspace outside the caller's own between
preparation and commit now receives 403 `permission denied` with the previous package, checksum, and
attachments untouched. Automated coverage: the `Should recheck replacement authority inside the
commit lock` case of `TestDaemonExtensionInstallReplaceAuthority`; a real concurrent HTTP race remains
uncovered by automation.

QA impact 2026-11-15 (release integration): replacement is optional in both HTTP and generated
TypeScript install/preview requests; callers that omit it retain the refusal behavior for an existing
local package. The rollback guarantee ends when the reinstall transaction returns successfully;
a subsequent enable failure retains the new package. No local scenario or test run is permitted in
release mode. Main CI owns automated execution; HTTP/UDS and the live scenario remain unverified.
