QA impact 2026-11-13 (install replace): `POST /api/extensions` and `compozy extension install
--replace` now replace the installed package of the same name instead of refusing it. Walk three legs
on a local fixture. (1) Successful replacement: install `qa-local-ext` 1.0.0, then install 2.0.0 with
`replace=true` and confirm the managed directory, the registry version, the checksum, and every
existing attachment report 2.0.0, with no duplicate attachment and the staged previous directory
gone. (2) Failure recovery: install a replacement whose checksum mismatch (or unreadable manifest)
fails before publication and confirm 1.0.0 stays installed, byte-identical, invocable, and reported by
`compozy extension status` and `GET /api/extensions/:name`; also force a post-publication failure and
confirm the staged backup is restored instead of leaving the extension absent. (3) Authority: a
workspace-bound caller with write authority that sends `replace=true` for a globally installed
extension receives 403 `permission denied` and the global package stays byte-identical, while the
same caller may replace an installation attached only to its own workspace. Automated coverage before
the manual walk: `TestDaemonExtensionInstallReplaceAuthority` (daemon authority) and the
`install_managed_test.go` backup/restore cases; HTTP and UDS legs remain pending.

QA impact 2026-11-13 (replace authority under the lifecycle lock): the replacement rechecks the
caller's authority inside the install commit, under the lifecycle lock, instead of trusting only the
preparation-time check. A package attached to a workspace outside the caller's own between
preparation and commit now receives 403 `permission denied` with the previous package, checksum, and
attachments untouched. Automated coverage: the `Should recheck replacement authority inside the
commit lock` case of `TestDaemonExtensionInstallReplaceAuthority`; a real concurrent HTTP race remains
uncovered by automation.
