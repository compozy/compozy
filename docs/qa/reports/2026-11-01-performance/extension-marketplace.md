# Extension, marketplace and discovery performance audit

Baseline: `de5ab2f4d`, 2026-11-01. Worktree: `responsiveness-audit-20261101`.

## Scope and method

Every assigned package/system was inspected separately, including the nested packages below. Production edits are limited to measured duplicate work. No daemon, browser, production state, credentials, full suite or gate was started by this worker. Tests, benchmarks and formatting use `.cache/performance/run-bounded.py`, which serializes task validation with `GOMAXPROCS=2` and `GOFLAGS=-p=2`. SQLC was regenerated by the root worker; generated files were not hand edited. Other workers own unrelated worktree changes.

Measurements ran on Darwin/arm64, Apple M4 Max, five 200 ms samples per benchmark. Medians below are microbenchmark operation costs, not measured UI or session latency. Shared-host timing varied; stable allocation reductions corroborate the removed work. Extension fixtures use real isolated SQLite databases and manifests; package availability uses a real 8 MiB cache blob. The provider benchmark prewarms its manifest cache before timing both versions.

## Retained changes

1. **Request-scoped extension visibility.** Tool discovery previously made installation and profile-enablement queries for each extension, plus a development-link query for workspace scopes. A single SQLC statement now reads current attachment reach, profile enablement and the matching development generation. There is no TTL, authorization or configuration cache. Workspace inventory similarly reads attachment names once and captures development overlays under one manager read lock, then performs SQL after releasing that lock.
2. **Verified package availability.** Browse/detail previously called installation `Open` only to close its reader; this rehashed every archive. `PackageCache.Check` securely opens the anchored regular file on every call. It reuses a previously verified SHA only for the same expected digest and matching held-file device/inode/ctime, size, mode and mtime. Metadata is sampled before and after hashing; changed or unavailable OS tokens never populate reusable entries. The map holds at most 1,024 snapshots and clears during sweep. Missing, unsafe, replaced, changed, unreadable and canceled requests remain visible immediately. Installation `Open` still hashes every time. No TTL substitutes for integrity checking.
3. **Single skill metadata parse.** The loader already built a YAML node for unknown-field warnings, then reparsed the same frontmatter. It now decodes the existing node, retaining warnings, validation, metadata and body semantics.

## Concurrency, memory and retained risks

No production goroutines, worker pools or new dependencies were added. SQL batching removes repeated calls without concurrent SQLite fanout. The package cache retains metadata only, with no archive bytes or open file handles. Package-check map locks protect metadata only; hashing is outside that lock. The existing cache read lock still coordinates publication/sweep with file access. Unsupported OS change tokens deliberately retain the slower full hash for availability; no Windows speedup is claimed.

The extension manifest cache tracks active paths by every visited profile/workspace scope until that scope is reconciled empty, and reconciliation scans retained scopes. Workspace skill caches and MCP descriptor caches expire by TTL rather than a hard count. These are recorded retention/scaling candidates, not measured leaks; no speculative eviction policy was introduced. Profile resource projection still performs additional declaration I/O. These paths need a representative long-lived workload before further performance claims.

Cross-surface behavior remains unchanged: native extension tools, hooks/config, workspace/profile isolation and `skills/compozy/` public content retain their existing contracts. Web changes are indirect through faster backend discovery/catalog reads.
