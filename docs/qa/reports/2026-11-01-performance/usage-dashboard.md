## PR 1141 reverse observation-order follow-up

Before changing coverage: invariant = an `Envelope` that observes owner B must not return retained owner-A quota merely because an earlier A observation applied first and advanced the validation sequence. Version application order is not credential observation order. The owning layer is the provider-usage Manager read fence; the canonical suite is `internal/providerusage/service_test.go` / `TestUsageService`. The reverse-order test must also preserve the existing A-to-B-to-A, cached-evidence, unverified-read and unrelated-profile isolation cases. Baseline: `56176f829`. The reverse-order case independently failed before the production edit: `want refreshing, got ok` in 0.333 s (`pr1141-reverse-before.log`). Additional canonical cases cover three successive sequence collisions, cancellation during a recheck after a collision, and a same-owner recheck that returns an error. Revalidation is conditional on a sequence-only stale mismatch; pointer/epoch/identity changes remain terminal. No timeout, retry-count limit or public error behavior was added.

The two initial probes both capture the same validation sequence. The A probe reads the original temporary credential and pauses; after the fixture writes B, the B probe reads that changed owner and pauses. A then applies first and advances the sequence. Previously the B probe discarded its observation solely because of that advance and returned A's quota. The correction refreshes the local check's sequence and cached evidence under the manager mutex, then obtains new evidence outside the mutex. It applies that evidence only against the refreshed checkpoint. Collection gates moved to the collector's `Collect` boundary so genuine credential rereads can proceed while a background collection remains unable to hide a cleared snapshot.

Only a mismatch colliding with a changed sequence retries. A matching or error-only result returns normally; replacement state, credential epoch or exact identity stops the old check. Each repeated attempt requires an actual intervening successful validation, and the caller context is checked before every attempt. With a persistent different owner, newly started probes also mismatch and cannot advance the successful-validation sequence; only already-pending positive probes can cause further collisions. Once those settle, the mismatch clears the old snapshot. Continuing external credential changes can require continuing evidence, but cancellation stops new attempts. This is not a fixed bound on filesystem I/O already in progress.

The fix preserves the exact `(mismatch, error)` pair from `validatePublication`. In particular, `(false, error)` must not be promoted to a mismatch, advance the sequence or replace cached evidence. This is reachable in production: `internal/providerusage/codex.go` / `loadCodex` retains `AccountID` when a missing access token produces `AuthMissing`; `internal/providerusage/identity.go` / `Same` compares known account IDs. `internal/providerusage/publication.go` / `publishLocked` likewise retains last-good measurements on same-owner failures. The new error case exercises that contract at the existing collector I/O boundary and asserts one actual reread plus preserved status/windows. Errors that already accompany `mismatch=true` keep their existing classification. The cancellation case begins a recheck, causes another sequence collision, and cancels before a further probe; it verifies no new credential I/O and preserves the existing `Envelope` return behavior.
