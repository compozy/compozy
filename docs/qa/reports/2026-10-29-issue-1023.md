## Supporting OS integration evidence

`COMPOZY_KEYCHAIN_TEST=1 CGO_ENABLED=1 go test -race -tags integration ./internal/providerusage -run TestClaudeKeychainIntegration -count=1 -v`
passed on this Mac. A disposable item created by `security` remained readable by the background
reader after `add-generic-password -U ... -X` without `-T`. A second item trusting only osascript
was denied before any secret-reader subprocess launched. Both items were deleted by cleanup.
The successful explicit read used `security`. No interactive prompt was needed in these cases.

The operator's existing Claude item was inspected without mutation: decrypt apps included
osascript and security, but partitions contained only `apple-tool:`. A direct security read
succeeded; only success and OAuth-shape booleans were recorded, never token bytes.

Removal of a previously expanded partition list is supported by Apple's
[`ItemImpl::updateSSGroup`](https://github.com/apple-oss-distributions/Security/blob/main/OSX/libsecurity_keychain/lib/Item.cpp),
which removes the partition ACL when replacing secret data. This specific widened-partition
transition was not performed live, by the operator's direction.

## Review follow-up: gate isolation

The preflight was rerun directly against the real Claude item using the current production JXA
script. It requested only an item reference and metadata, never `kSecReturnData`. Interaction was
disabled before lookup and restored to its previous value in `finally`; the child process group
had the same 1.5-second limit as the background secret reader. It returned
`{"status":0,"safe":true}` in 522 ms. A read-only CoreGraphics observer saw zero on-screen
SecurityAgent windows before, during all six samples, and after the probe. Sampling is supporting
observation; the no-UI property of this gate comes from its disabled-interaction API calls.

The owning Darwin suite now also executes the production gate against synthetic native metadata:
confirmation required and a missing `apple-tool:` partition each prevent all secret reads. A
positive control admits trusted metadata, and the fixture checks that lookup happens with
interaction disabled and that the previous interaction state is restored. These tests substitute
only native I/O responses; real disposable-item tests remain the OS integration proof. Both race
tests and disposable-item integration passed again after this change.

The CodeRabbit follow-up extends the existing timeout invariant to both subprocess phases: a slow
metadata gate now returns the same `keychain_read_timeout` / Refresh recovery as a slow secret
reader, rather than falsely reporting OS denial. A timed-out gate never launches the secret reader.
The integration case explicitly names the confirmed Claude-style `security` writer; it does not
claim a live foreign-writer partition transition.

## Limits

The metadata gate and secret read are separate operations. Concurrent item changes can briefly
show a system prompt before the 1.5-second deadline kills the client process group. This run does
not claim an absolute OS no-dialog guarantee or a forced SecurityAgent race reproduction.
Exa was unavailable because no API key was configured; research used Apple sources and Context7.
