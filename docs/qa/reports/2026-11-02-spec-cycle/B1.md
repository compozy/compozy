# B1: collector and upgrade safety

Contract: the read-only `spec-cycle-simplify` specification, stories US-003, US-006 and US-007,
ADR-003 and ADR-004. No extension resource is removed by this slice.

## Ownership and coverage

- Parsing, aging, deterministic oldest-nine selection and overflow fingerprint items belong to
  `internal/heartbeat`, covered by `TestWorkLogDigest` in `heartbeat_test.go`
  (UT-001, UT-002, UT-003, UT-005, UT-014, UT-015, UT-016).
- Bounded file reads and canonical workspace containment belong to the daemon collector,
  covered by `TestReadWorkspaceWorkLog` in `daemon_test.go` (UT-004, UT-006, UT-007).
- `TestWorkLogCollectorIntegration` runs the wired collector, real SQLite wake state and the
  real ACP subprocess triage dispatcher: one stale entry wakes triage; a successful result
  suppresses the unchanged digest within MaxInterval; invalid triage output retries it (IT-001).
- `TestSessionMessageOriginSteerChainIntegration/Should_send_a_follow-up` exercises IT-004:
  eight forwards refuse a ninth; a monitor starts a new turn with hop zero and a send succeeds.
- `TestRemovedResourceUpgradeIntegration` reopens a real daemon home with missing agent/loop
  references, keeps job/trigger/override rows, reads session history, rejects resume/run locally,
  and pauses the missing agent instance (IT-005, current instance schema). Automation fixtures
  are authored/read through the real resource API, the authority used by the released catalog.
- `TestReleasedSpecCycleReferenceUpgrade` in the existing global store migration suite proves
  that sessions, jobs, triggers and overrides survive migration from the actual v0.4.8 prefix,
  version 163, to the current stream. This owns persistence upgrade rather than daemon boot.

## Contract discrepancies

The actual v0.4.8 tag (`6bd423086`) has global migration 163 and no `agent_instances` table;
that table ships in 164. Thus one literal v0.4.8 fixture cannot already contain an instance.
Coverage is split between the genuine released-prefix migration and a current-schema daemon
reopen with instances. No historical migration is edited.

The requested active-loop behavior refers to an existing extension-disable path. The current
coordinator instead executes its durable pinned definition snapshot, including extension
provenance. The existing `TestCoordinatorRunnerShouldExecutePinnedDefinitionSnapshot` passed
with `-race`. This slice preserves that behavior; it does not invent cancellation semantics.
The integration owner should reconcile that sentence before claiming the entire upgrade table
has runtime coverage. Installed third-party extension execution and live release QA remain
with the final integration QA pair.
