Scope: S8 of `.compozy/tasks/file-explorer/_slices.md`, branch `feat/file-explorer-s8`.
Additive HTTP/UDS contracts only; no Changes routes or frontend implementation.
The spec `_impact-entry.md` owns the cross-surface audit. S10 consolidates it and runs the

changes. Root authorization reuses S1's profile/workspace/worktree resolver.

## Implementation

- `projectfiles.FileSearch` implements Finder and Searcher. A separate `workspacefiles` instance
  caches 200,000 files for 15 seconds; the composer defaults remain unchanged at 25,000.
- The collector adapter injects S1 `GitReadArgs` and the streaming projectfiles runner.
  FuzzyMatchV2 uses the path scheme and returns merged UTF-8 byte ranges and at most 50 results.
- Git grep candidates stream through the shared read-only policy. Include pathspecs never union
  with `.`. Validated root-relative globs are reapplied using doublestar.
- Every candidate is re-read through S1's confined Reader and filtered before counting. Symlinks,
  sensitive targets, protected metadata, binary content, and files above 1 MiB are skipped.
  Matching lines, columns, byte ranges and 300-character excerpts are computed in Go.
- Non-git roots use fastwalk without following symlinks. Request cancellation joins the Git call;
  the fixed 10-second deadline returns partial results. Caps are 2,000 matching lines globally
  and 100 per file.
- HTTP and UDS register the same four shared handlers. OpenAPI and TS/Go SDKs are generated by
  `compozy-codegen`; array query parameters explicitly use repeated form serialization.

## Contract clarifications and S9 notes

- Four operations: `findFiles`, `findSessionFiles`, `searchFileContents`,
  `searchSessionFileContents`. Workspace forms accept optional `worktree_id`; session forms use
  the bound worktree, excluding resumed CWD. Both forms accept existing profile selectors.
- Find uses `q` and `limit`. Empty queries are `400 invalid_query`; recent paths are client-owned.
  Results include path, kind, score, optional sensitive flag, and merged half-open byte ranges.
- Search uses `q`, booleans `regex`, `case_sensitive`, `whole_word`, repeated `include`/`exclude`
  parameters (maximum ten each). Pattern length is 2–512 Unicode characters. Invalid POSIX regex
  returns `400 invalid_query` with the compiler message. Invalid globs fail before Git execution.
- Search response: root, normalized query, engine (`git_grep` or `walk`), grouped files with
  matches, totals, truncated, timed_out, sensitive_excluded. Match columns are 1-based bytes;
  ranges address excerpt bytes; text_offset addresses the original full line. UI ellipses should
  be rendered separately so they do not shift byte ranges.
- Other errors reuse S1: root_unavailable (409), workspace/worktree/session_not_found (404),
  and sanitized files_unavailable (500). Foreign-profile reads are indistinguishable from missing.
- Business Rule 14 counts sensitive *paths*. Thus `.env` plus `notes.txt -> .env` reports two
  excluded paths, clarifying UT-088's stale expectation of one. Both paths remain hidden by the
  post-filter. `.env.example`, `.env.sample`, and `.env.template` remain searchable: dynamic
  literal exclusions supplement sensitive globs rather than over-excluding those exceptions.
- Cancellation coverage asserts the streamed boundary returns and joins within 200 ms; it does
  not run a package-global goleak scan. Deadline partial-result behavior is proved at the domain
  boundary with the real fixed 10-second budget; daemon integration proves error/transport wiring.
- Per-file results are recomputed from a confined current Reader snapshot after Git identifies
  a candidate file, avoiding disclosure of untrusted raw Git output and bounding retained text.
