## What Was Fixed

### `be0b2db6` — QA runtime and profile lifecycle preconditions

- **Symptoms:** the browser lane registered the operator home as a project, leaked large temporary runtime trees, sometimes stopped a daemon twice, detached desktop commands in Global, missed profile changes made by another client, retained archived profile selections in the Web, and raced with short-lived npm cache writes during cleanup.
- **Root causes:** `COMPOZY_HOME`, operator `HOME`, and project roots shared one path; cleanup did not own every launch path; daemon teardown did not distinguish a live owned child from a restarted replacement; desktop topology and data scope used one workspace identifier; the profile event stream read only the default profile; rename events omitted the previous name; selection contracts exposed archived stored rows instead of the effective fallback.
- **Fix:** isolated runtime paths, deterministic process/path cleanup with bounded filesystem retries, separate desktop and data bindings, aggregate profile lifecycle subscription, previous-name rename events, and effective `default` projection for archived remembered selections.
- **Regression evidence:** focused Go and Web unit suites plus the daemon-served Profiles, OS Shell, Agents, Attention, Tasks, and Home checks listed above.
- **Scenario effect:** none yet. Every matrix row remains `Pending` until its complete persona journey is walked and independently verified.
