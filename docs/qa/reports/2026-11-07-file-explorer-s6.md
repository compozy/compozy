# File explorer S6 full-stack evidence

Scope: S6 of `.compozy/tasks/file-explorer/_slices.md` on `feat/file-explorer-s6` (base
`feat/file-explorer` at `818ba3d5d`: S1/S2/S3/S4/S8). The Files OS app (US-002; `_uiux.md` S6,
S10). No schema, config, hook, native tool, HTTP/UDS route, or OpenAPI change: the window-manager
app inventory and palette catalog are daemon data, not a generated enum. The owning cross-surface
audit is the spec's `_impact-entry.md`; S10 owns docs, the official skill, and QA scenarios.
Affected scenarios: the new Files app journey (S10 adds it), plus any OS dock/palette scenario
that lists the dock order (Files now sits after Agents).

## Implementation

- Go (`internal/cmdpalette/corecmds`): `files` joins the daemon app inventory, so
  `RegisteredApp("files")` keeps persisted Files windows through `ReconcileRegisteredApps`, and
  the palette gains `app.open.files` titled "Open project files" (navigate, icon `folder-tree`).
  `domainDefinition.commandTitle` overrides the default "Open <title>" row.
- Go (`internal/windowmanager`): workspace unregistration removes a Files window rooted at the
  project (`/files/<workspace_id>`) from windows, nav stacks, closed entries, and history; other
  bound windows keep their catalog-route retirement.
- Web catalog/registry: app `files` (title "Files", icon `FolderTree`, path `/files`,
  `matchInstance` = the workspace id, dock group 2 right after Agents), dock glyph, palette icon,
  loading fallback, and TanStack routes `/_app/files`, `/files/`, `/files/$workspaceId`
  (`routeTree.gen.ts` regenerated by the router plugin).
- Opening: `useOpenFilesApp` resolves the project (explicit, else the focused window's project,
  else the remembered project, else the first) and calls `userOpen` with instance key = project,
  so a second open focuses the same window. The dock, the palette/Go menu (`openApp("files")`,
  honoring `/files/<id>` from an agent route) and the sessions-rail project context menu
  ("Open files") all use it.
- `FilesAppWindow` (`web/src/systems/files`): topbar project switcher (live projects only) and
  root picker (Project root + ready worktrees with branch) over the shared `FilesExplorer`, in a
  `CodeHighlightPoolProvider`. States: loading, Project archived, Project not found, root
  unavailable with "Switch to project root" (new `unavailableAction` slot on `FilesExplorer`),
  and, for a bare `/files` window, "No projects yet" with Add project (workspace setup dialog).
  The root and open path persist per project under `compozy:files:v1:<workspace_id>`.
