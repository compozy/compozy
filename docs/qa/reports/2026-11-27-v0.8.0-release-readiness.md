## Defect triage

**Release blocker #2062. Hosted browser sign-in selects production Cloud.** Open the staging hostname and select Google. Chrome opens the production authorization endpoint and displays a sign-in error. The browser needs authorization from the Cloud environment that owns the route. This prevents verification of hosted browser sessions and their stream tickets. [Reproduction](https://github.com/compozy/compozy/issues/2062)

**Should-fix under #2061. Negative DNS caching delays route readiness.** Enable a new hosted route. The VPS resolver returned zero A records while two public resolvers returned two each. The host stayed in `retrying`. Webhook binding returned HTTP 503. A fresh hostname must reach `ready` and accept a binding without the negative-cache delay. [Provisioning issue](https://github.com/compozy/compozy/issues/2061)

**Initial release blocker #2061. Hosted TLS failed in staging.** Link a VPS, add it to an authenticated controller, upgrade to Pro and enable the hosted route. With the control link connected, the assigned hostname should serve the host over HTTPS. DNS resolved and staging health returned HTTP 200, but three clients returned curl exit 35 and HTTP 000. Chrome reported `ERR_SSL_VERSION_OR_CIPHER_MISMATCH`. Restarting the host brought the control link and ready indication back. The staging edge certificate now covers the assigned hostname. The retest above records the successful TLS checks. Production reachability remains unverified. Release sign-off requires a successful hosted gateway walk after the fix. [Reproduction](https://github.com/compozy/compozy/issues/2061) · [Evidence](../assets/2026-11-27-v080-vps.json)

The web bundle pinned on main (`v0.0.840`) failed `webAssetsCheck`. On a fresh signed-out home its UI reached the generic error screen. Building the web source with Vite produced digest `875a94cfad5b0c45e9a7b5ce5ebb0805bb17678ab0a4fa9bbb37d458c57f470d`. That digest matches the `v0.0.875` bundle already pinned by release PR #2055 at `6766f11d62b5f672a75e80c78e4f64d9d1c1701c`. Rebuilding the same daemon with that pin and reloading the same home produced the sign-in screen above. The release PR already carries the correction. [Release PR](https://github.com/compozy/compozy/pull/2055)
