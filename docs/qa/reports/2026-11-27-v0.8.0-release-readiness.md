# v0.8.0 release readiness

**Decision: blocked.** Fresh and upgraded installations enforce sign-in. Staging created a Stripe Sandbox checkout. The VPS has not been provisioned, and a completed purchase has not been observed in the product. Those two journeys are required for launch sign-off.

## Candidate and environment

The Go source was main at `2d279cfe2b81cf0a0b51c693ee9af4759743e011`. Both Go builds used the release settings in `.goreleaser.yml`: version `0.8.0`, commit and date stamps, mandatory sign-in, `CGO_ENABLED=0`, `-trimpath`, and stripped symbols. The controller ran on Darwin arm64. The Linux amd64 artifact was built for the VPS.

## Defect triage

The web bundle pinned on main (`v0.0.840`) failed `webAssetsCheck`. On a fresh signed-out home its UI reached the generic error screen. Building the web source with Vite produced digest `875a94cfad5b0c45e9a7b5ce5ebb0805bb17678ab0a4fa9bbb37d458c57f470d`. That digest matches the `v0.0.875` bundle already pinned by release PR #2055 at `6766f11d62b5f672a75e80c78e4f64d9d1c1701c`. Rebuilding the same daemon with that pin and reloading the same home produced the sign-in screen above. The release PR already carries the correction. No additional product defect was confirmed in the completed checkpoints. [Release PR](https://github.com/compozy/compozy/pull/2055)

The pricing scenario previously directed a tester from the public CTA into a staging purchase. The live CTA and official daemon both select production. The revised scenario identifies the staging browser and daemon entry points for the payment walk. [Pricing scenario](../scenarios/RT-site-pricing.md)
