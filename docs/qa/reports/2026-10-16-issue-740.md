# Issue #740: provider-attributed catalog refresh failures

## Confirmed cause and change

The aggregate refresh can return source statuses with a non-success HTTP status
when a live source serves stale fallback. The Web adapter discarded those
statuses and the session composer rendered the raw error. Even successful
aggregate refreshes were reduced to the first failed source's diagnostic text.

The shared source projection now derives an optional `failure_reason` from its
persisted, redacted diagnostic: `auth_required`, `timeout`, or `refresh_failed`.
No database migration or change to refresh HTTP status semantics is needed.
Diagnostics stay in `last_error`; Web and human CLI status show guidance.
The selector renders an attributed provider notice and keeps model choices.
