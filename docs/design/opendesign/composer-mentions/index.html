Composer mentions

Type @ in the session composer to point the agent at a file, a folder, or another session of the same workspace. The picker reuses the / menu's grammar; picked targets become text-weight chips; sent mentions come back as chips in the transcript only when the daemon verified them.

What this is

The four surfaces of _uiux.md: the @ picker (S1), the mention chip in the editor (S2), the placeholder (S3) and verified chips in the user message (S4). The empty-desktop composer (S5) is unchanged and has no picker.

No new visual language: rows, headers, empty rows and the popover surface are the / menu's; chips are the skill chip's anatomy in neutral ink. All file paths are real repo paths; sessions, agents and times are illustrative.

S1 · The @ picker

A second Unstable_TriggerPopover with char="@" inside the existing trigger root. Two groups in fixed order — Files (files and folders, up to 50) then Sessions (up to 5, current session excluded). Each group owns its own empty, error and loading row, so one failing source never hides the other.

S2 · Mention chips · S3 · Placeholder

The chip renderer dispatches on directiveType: a skill keeps SessionCommandChip; a mention renders SessionMentionChip. Mentions use neutral ink so they never read as a runnable command; the icon carries the kind.

S4 · Transcript user message

History chips render only from daemon-verified mentions metadata. A token that did not resolve stays plain text. The session chip is the only interactive chip in v1: it opens that session's window.
