S1

The section — two tracks, one grammar

daemon truth per row · one apply per track
One row per trackThe Updates group keeps its home in the General page (768px form column). A Runtime row is always present — the daemon is the runtime. An App row is present exactly when the payload carries an app object. Follow-up rows (upgrade command, last error) sit directly under the track that owns them and name that track.

VC-07

Applying — runtime, staged phases

the daemon's phase word, verbatim · percent only when measured
The phase is the stateWhile a track is applying, the pill lane becomes Spinner + the operation's phase in mono. No second status chip, no progress bar — the section renders the six named phases the runtime reports and nothing it does not. The other track's action disappears while an operation is live: the home is single-flight, and the payload says so.

Two different successesThe runtime finished, so it reads Updated and keeps the daemon-restart sentence — that is truth the version alone does not carry. VC-09

Blocked — the holder is named

warning · no retry button, because waiting is the retry
Who has it, and what to doAnother surface took the lease between the last poll and the click. The daemon's refusal message names the holder and says when to try again, so the row shows it verbatim and drops the action. The section polls every 2s while an operation exists, so the row heals itself — a "Retry" button here would just re-issue a refusal.

VC-10

Failed — restored version and last error

the running version is the restored one · retry stays available
What is running, and whyThe version lane shows what actually runs now — the restored build — and still names the target that failed. The daemon's message states the restore in its own words; the raw failure gets its own track-named row so the sentence under the label stays readable. The operation is terminal and the lease is free, so Update runtime comes back.
