Orchestrates the tasks you already authored outside the Loop (via the spec skills, as today): loads them from .compozy/tasks/<slug>, executes them in dependency order, reviews and remediates what fails, and verifies against the project's own checks. Spec authoring stays outside; as a built-in it runs with zero authoring.

Contract
Goal
Ship every authored task under .compozy/tasks/{{ .inputs.slug }} · implemented, reviewed to acceptance, and verified by the project's own checks.
Definition of done
All loaded tasks reached a terminal state, the acceptance judge approved with evidence, and the project verification passed.

Read-only view. load_tasks imports the tasks you authored outside the Loop; implement fans out over them one task per agent session (batch_size 1), sequential in dependency order (max_parallel 1, max_fan_out 64), running each through execute_task (run-agent). After collect, the acceptance review, the verify definition-of-done gate, and the human approve gate decide between a next generation (revise) and a terminal outcome. Remediation is the failed-only re-attempt, not a node.

Left value is the per-loop default. The right value is the daemon ceiling, a hard backstop that can't be raised. Token and wall-clock budgets are off unless set (0 = unlimited); a set budget is enforced: checked before each node dispatch and at every generation boundary. On exceeded, on_exceeded: halt ends the run as exhausted; escalate pauses it as needs-approval. Fan-out breadth is bounded by the number of loaded tasks. Cost is display-only, not an enforced cap.
