Readme from the skill package

What it does

When an agent activates pr-review, it follows a disciplined review protocol instead of skimming the diff. It fetches the pull request, its comment threads and CI status through the GitHub MCP server, walks every hunk, and verifies each suspicious claim against the surrounding code before reporting it.

The output is a structured review: findings ranked by severity, each anchored to a file and line, with a concrete failure scenario — not a list of style nits.

How it works

  1. Fetch context. Pull request metadata, review threads and check runs come in through the github MCP server.
  2. Walk the diff. Every hunk is read in order; changed behavior is mapped to the code paths that call it.
  3. Verify before claiming. Each candidate finding is re-checked against the repository at the PR's head — unverifiable claims are dropped, not hedged.
  4. Report. Findings return as a ranked list ready to post as review comments or feed a fix loop.

When to use it

  • Reviewing incoming pull requests before merge — solo or as the review stage of a delivery loop.
  • Auditing an unfamiliar branch: the same protocol works with a local diff.
  • Not for docs-only changes — the protocol is tuned for behavior-bearing code.

Configuration

No configuration files. The skill declares the github MCP server in its frontmatter; the daemon wires it up automatically when the skill activates, gated by your skills.allowed_marketplace_mcp allow-list.
