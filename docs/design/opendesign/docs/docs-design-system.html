Docs Shell — Design System

The visual contract for the documentation shell: page masthead (title, Copy as Markdown, Open with AI), sidebar navigation with nested groups, and TOC. The site top bar and tabs are out of scope — production ships them unchanged. Tokens are copied verbatim from packages/ui/src/tokens.css and the site's global.css. Rendered example: docs-page.html.

02Typography

Three voices, strict jurisdictions. Playfair Display speaks only at display sizes — the page title and h2 headings, nothing below ~26px. Inter is everything the reader and the UI say: body, leads, h3, sidebar rows, buttons. JetBrains Mono is the system's voice: section labels, breadcrumbs, group labels, code — and it is the only face allowed to speak uppercase. Every value below maps to a token in packages/ui/src/tokens.css or the site's @theme inline block in app/global.css.

Rules

DoPlayfair only at display size — title and h2, nothing under ~26px rendered. Serif at UI sizes on the dark canvas is a legibility failure.
DoUppercase is mono-only: JetBrains Mono 500, ≤ 10.5px, tracked +0.08–0.09em. Inter is never uppercased, never tracked positive.
DoNegative tracking (−0.02em) only at ≥ 20px. Weight caps at 600 — hierarchy comes from family, size, and color, not boldness.
DoBody copy is muted; fg is earned by headings, strong, links, and code. Measures: 72ch prose, 64ch lead.
Don'tNo font-weight 700, no Playfair in the sidebar/TOC/buttons, no new size values outside this ramp — if a size isn't in the table, it doesn't exist.
Don'tNever set type in raw px in components — every size resolves to a --text-* token so make codegen-check-style drift stays impossible.

04Sidebar

The tree is never one flat run: top-level rows group under the CORE_SECTIONS separators injected by lib/runtime-navigation.ts — entry points ungrouped on top (Overview, How to Use These Docs, Getting Started), then Foundation, Capabilities, Workspace & isolation, Operations & settings, Guides & scenarios. The other current defect: a folder's internal separators (Loops → ---Operate---) render with the same component as those section labels — same size, same margins, no indent — and open folders have no visual containment. The redesign gives each level its own anatomy:

Section labelmono uppercase, 26px top gap — one per CORE_SECTIONS group; entry points above the first label stay ungrouped. Color is a warm accent mix (color-mix(accent 65%, muted)) so labels never read as menu items10.5px · accent-mix
Item28px row, 6px radius; hover = elevated; active = accent text + tint + 2px rail bar12.5px

05Page masthead

Current problems: actions are baseline-aligned to a clamp(2.55rem→4rem) title and collide at mid widths; the title is capped at 12ch and wraps awkwardly; the Audience/Focus <dl> repeats templated filler on every page. The redesign moves actions up into a context row and replaces the dl with one truthful meta strip.

RowContent
1 · ContextBreadcrumb trail (accent product · clickable parents · fg leaf, mono 10.5px) left — actions cluster right: Copy as Markdown · Open with AI · ⋯
2 · TitlePlayfair 400, clamp(2.4rem→3.4rem), no ch cap — the 46rem column bounds it
3 · Leadfrontmatter description, 18px, 64ch, muted
4 · Meta striphairline + one quiet line of derivable facts only: audience, page count from meta.json. No templated prose.
