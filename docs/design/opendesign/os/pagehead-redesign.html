AGH OS v2 · chrome spec

Window head redesign — the PageHead becomes the chrome

The route PageHead was designed for a web page with a sidebar: it had to establish identity because nothing else did. Inside an OS window that job is already done, so the head collapses into a single 44px unified bar. Peer route tabs sit immediately after the title; filters and search move to an optional 38px context strip. Identity renders exactly once, and when a route navigates in place the head grows a window-local breadcrumb instead of spawning another window.

head 44px context strip 38px · optional drill-in: breadcrumb head chrome before content: 184px → 44–82px

02 · After

One unified head — identity, peer tabs, state and the primary action in 44px

The window head absorbs the PageHead. Controls lead, a quiet 22px glyph + 13px title carry identity once, peer route tabs sit immediately after the title when the route has sibling views, the flexible gutter after the tabs stays the drag region, and the trail holds live state plus at most two actions. Filters, search and view toggles stay in the optional 38px strip: they never compete with tabs for the same row.

03 · Drill-in

Internal navigation — the head grows a breadcrumb

Some routes navigate in place: a task opens its run, a catalog entry opens its detail, a corpus opens a file. That depth never spawns another floating window — the window count belongs to the user, not to navigation. Instead the head swaps its identity glyph for a back chevron + window-local trail: every parent is a clickable crumb, the leaf is the title.

·The trail is window-local. It starts at the window's root route, never at the workspace — the menu bar owns the workspace, the dock owns the routes. A breadcrumb never grows a global prefix.

·Deep paths collapse, long names ellipsize. More than two parents fold the middle into a "…" crumb whose menu lists the hidden levels; any single crumb truncates at 150px. The head never wraps and the drag region never disappears.

·The glyph returns only at root. At depth the back chevron takes its slot — identity still renders exactly once, it just reads as a path instead of a name.

·Document windows never breadcrumb. A session or file window titles itself; if it needs to reference where it came from, that's a crumbless meta chip, not navigation.

Identity renders once per window. Glyph + title in the head; never repeated in content.

Two bars maximum. 44px head, optional 38px strip. A route that wants a third bar has an information-architecture problem, not a chrome problem.

Route tabs sit after the title. Peer views (List · Kanban, Skills · MCPs) live left in the 44px head, immediately after identity, never sharing the strip with search/filter. The strip is tools only. On drill-in, tabs hide so the breadcrumb owns the identity slot.

Depth grows a breadcrumb, not a window. Internal navigation swaps the glyph for back + trail: parents click straight back, the leaf is the title, and more than two parents collapse into a "…" crumb.

Accent in chrome means state or the primary action. The identity glyph is neutral; live dots and the single primary button are the only orange in the frame.

Scroll reveals the surface. Content slides under the head; the head gains a hairline shadow while scrolled.

Windows may be documents. Sessions, runs and files title themselves; routes use their glyph + name. Same anatomy either way.
