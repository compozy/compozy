CompozyOS · Design System · Chapter 01

Foundations

Everything a CompozyOS surface is allowed to be made of: five warm surfaces, four hairlines, six glazes, one accent, one type stack, one radius ladder, three durations, one focus ring. Every value below is already in ds-core.css — link the file or paste its :root verbatim. Nothing here is a suggestion: a value that is not on one of these ladders is a defect, not a variation.

01Surfaces & depth

Depth is flat: a five-step warm ramp, four hairline strengths and a small set of inset rings. There is no elevation scale, no layered shadow stack, no glass in window content. A surface is either one step up the ramp or it is not a surface.

Warmth invariant. Every ramp step holds OKLCH chroma ≤ .005 and a red-minus-blue delta of no more than 3 (#171615 → 23−21 = 2). More chroma reads as sepia drift and breaks the neutral base the signal palette depends on; a pure grey ramp reads clinical against the accent. Warm-dark is a product contract — color-scheme: dark, no light theme, no user-tunable ramp.

One accent object per viewport: the New session button. The live badge and the running dot are the same accent because they are the same fact — this workspace is doing something right now. Rows stay neutral; state lives in tinted pills with ink and a glyph.

01Accent ≈ once per viewport. Either the primary call to action or the live identity — never both competing, never a border, tab indicator, selection marker or decoration.
02Signal is information, never decoration. Green means the daemon reported success. Amber means a human is blocking progress. If you cannot name the daemon fact, use neutral.
03Rows are neutral at rest. Tone enters through a pill, a dot or a meter fill — the row background itself only ever carries a glaze.
04Tint plus ink, never solid banners. Signal fills run 6–12% alpha with readable ink on top. A full-bleed red bar is not available; data-form="solid" is reserved for pills that must read at a glance.
05Color never travels alone. Every state pairs hue with text, an icon or a shape — failed is a squared dot, waiting is a rotated diamond, stopped is a hollow ring. Color-blind operators read the shape.
06Charts are monochrome. Series use --viz-line / --viz-bar / --viz-other; a signal hue enters a chart only when the series is the state (failures, waits).

06Motion

Motion confirms state changes; it never entertains. Three durations, two easings, and a strict separation between state feedback and continuous cadence.

TokenValueDrives
--dur-fast120msHover and press feedback, menu open/close, icon colour
--dur180msTab switches, row selection, pill toggles, switch knob
--dur-slow260msPanel reveals, disclosure folds, progress fills
--easecubic-bezier(.22, 1, .36, 1)Default — fast out, settled landing
--ease-in-outcubic-bezier(.4, 0, .2, 1)Symmetric moves that return to origin
Shell tier120 / 240 / 320ms + spring (.32, .72, .28, 1)Window open, dock magnify, space switch (chapter 02)

The old easing was invalid CSS. Pre-#440 prototypes carried a five-argument cubic-bezier; browsers dropped the whole declaration silently, so those transitions ran on the ease default and nobody noticed. Any copied easing value must have exactly four arguments.

Above 260ms a state change stops reading as a response and starts reading as an animation the operator has to wait out.

Continuous cadence

shimmer · 2s
band sweep · 1.2s live pulse · 1.8s

Cadence is deliberately off the duration ramp. Loading shimmer runs 2s, the loading band sweeps in 1.2s, the live dot pulses at 1.8s. These are ambient rhythms, not responses — putting them on 120/180/260 would make a loading surface feel like it is being clicked. Double guard for reduced motion: honour prefers-reduced-motion in CSS (ds-core.css collapses every duration to .001ms) and gate any JS-driven loop on matchMedia("(prefers-reduced-motion: reduce)"), because a CSS-neutered animation still burns a frame budget on a requestAnimationFrame loop.

Lucide, one library, no exceptions. Icons are labels, not illustration — one concept gets exactly one glyph across the whole product, and that mapping is a contract.

01Size the parent, never the glyph. An unsized Lucide svg renders at 24×24 and blows a 20px pill open. Set width and height on the container and let the svg fill it.
02One icon per concept. A session is always bot, a loop is always repeat, a workspace is always layers. Reusing a glyph for a second meaning breaks scanning across every surface at once.
03Icons inherit ink. They take currentColor from the row or pill they sit in — an icon is never the only thing carrying a signal hue.
04Never: emoji as icons, hand-drawn SVG paths, icon fonts, or a text node standing in for a wordmark. If Lucide has no glyph for the concept, the concept needs a word, not a drawing.

08Focus & accessibility

One ring, one trigger, one value. Keyboard operators are the primary audience for an agent OS — a lost focus indicator is a broken product, not a polish item.

The rings above are painted statically so you can read them. In product they appear only on :focus-visible. A 50% white ring composites to roughly #898988 and clears 5.3:1 against every step of the ramp, including --elevated — one value works everywhere, so there is no per-surface ring. Pointer focus strengthens the border and nothing else: clicking a field must never flash a ring at a mouse user.

Why not opacity

Disabled controls swap tokens — fill to --canvas, border to --line-soft, ink to --disabled (#4a4847). Dimming the whole control with opacity would drag the mandated reason text below AA at the same time, and the reason is the one thing the operator still has to read. Buttons are the single exception: they carry no reason text, so .btn:disabled may use .5.
