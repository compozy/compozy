CompozyOS · Chapter 07

Dashboards

A dashboard is a document you read top to bottom, not a cockpit you monitor. It answers four questions in order — what needs me · what is happening · how did it go · is the machine healthy — and every zone below is placed by that answer, not by visual balance. The grammar here is the modernized form of ../_done/dashboard/dashboard.html: same zone order, but tokens now come from ds-core.css, icons are Lucide only, panels carry no signal-tinted borders, and every section is collapsible. On conflict this chapter supersedes that file.

01Zone order is locked

Order encodes priority. A dashboard that opens on charts is telling the user their attention belongs to a number instead of to the approval waiting on them. Zones may be empty (an empty zone renders a one-line honest note, never a placeholder chart) but they never trade places.

02Section head & the collapse contract

One head grammar for every zone: .eyebrow (sentence case, 12px/510) · .count-chip when a count exists · spacer · one quiet trailing link. No uppercase shouting, no icon per heading, no second action. Counts of zero render nothing at all.

Every section collapses

Sections are details/summary: icon · title · one-line gist · chevron. Defaults are calm — heavy zones (Pulse, Usage, Agents) ship closed, and a closed section still informs, because the gist carries the verdict. Collapse state is per-user, never per-session.

04Paired panels & the flush-bottom contract

Two panels side by side almost always hold unequal content, and the short one ends in a band of dead air with its footer link floating mid-column. The fix is a four-link flex chain — encode it verbatim, it is not optional styling.

/* grid → section → panelbox → list → foot */ .dsh-grid2 { display:grid; grid-template-columns:1fr 1fr; gap:20px; align-items:stretch } .dsh-col { display:flex; flex-direction:column } /* section is a column */ .dsh-col > .panelbox { flex:1; display:flex; flex-direction:column } /* panel fills it */ .dsh-fill { flex:1 } /* inner list absorbs */ .dsh-foot { margin-top:auto; border-top:1px solid var(--line-soft) }

05Chart cards

A chart card is a headline sentence with a picture under it. One headline figure per panel — 22px/620 value plus a 12px subtle caption that says what the figure counts. Below it a chart body of at least 120px, a legend, and a mandatory provenance footnote. If you cannot write the footnote, the panel does not ship.

Viz ink rules

Magnitude is neutral. A hue appears only when the series is the state — failed runs are --danger because failure is the meaning of the bar, not because red looks urgent. The expected outcome stays neutral — “finished” is the norm, not a signal — and legend swatches match their mark exactly, because a green key over a grey bar is a lie about the chart.

06Data rows

Attention rows — the tone lives in the dot

Zone 1 rows carry a 7px dot, 12.5px text, a mono timestamp, and exactly two actions: one primary verb and one ghost escape. The panel border stays neutral — a warning-tinted panel edge turns a single blocked run into a red screen. A resolved row flips to --success-tint in place and keeps its height so nothing jumps.

07Heatmap & meters

Pulse answers when is this workspace busy. A 34px label column plus 24 hourly cells of 15px at radius 3, alpha-ramped on --viz-cell. The fixed tracks give it a hard floor of 469px, so it lives in .scroll-x rather than shrinking into mush. 09Dashboard rules

H1A dashboard is a document window. Identity renders in the 44px head; the body opens on the demoted meta line. No H1, no subtitle, no PageHead stack.
H2One headline figure per panel. If a panel needs two numbers, it is two panels. The caption must say what the figure counts, in words.
H3Provenance footnotes are mandatory on every chart — the window, the population, and any estimate. A chart you cannot source does not ship.
H4Signal color only on live state. Magnitude is monochrome --viz-*; hue appears when the series is the state. Panels never take a tinted border.
H5Hero KPI 24px/620 is dashboard-only. The same metric inside a normal window renders at --text-kpi-compact 17px. Never mix the two tiers on one screen.
H6Count-ups, pulses and tickers are gated by prefers-reduced-motion and must land on the true value immediately when reduced. Live regions announce, they do not animate.
H7Responsive ladder: 1080 → paired grids collapse to one column and KPIs go 2-up; 760 → agent table drops to name + two numerics; 520 → KPIs go 1-up. The heatmap always scrolls, never shrinks.
H8Every section collapses and its summary carries the verdict, so a fully collapsed dashboard is still a readable status report.
H9Paired panels obey the flush-bottom chain (§04). Unequal content is the normal case, not the exception.
H10Empty zones tell the truth. “No runs finished in this window” beats a zeroed chart, and a zero count renders no chip at all.
