CompozyOS · Chapter 02 · Shell chrome

OS Shell — Window Manager

The shell is three fixed zones: a 44px menu bar, a wallpapered desktop of windows, and a bottom dock whose 82px band is reserved work-area. Every measurement on this page is production truth from web/src/systems/os and packages/ui/src/tokens.css, expressed as the classes in ds-shell.css. The OS radius waiver (12–22px, glass, cast shadows) applies to this layer only — window content returns to the ds-core.css scale. Demos below are live: the deck switches tabs, controls take hover tones, seams take focus.

01Menu bar

One 44px glass strip pinned above the desktop. Leading carries where you are — logo, scope, workspace, app menus. Trailing carries what needs you — status, updates, approvals, ⌘K, settings. Nothing else ever docks here: no clock, no cost meter, no avatar.

Truthful chrome. A control with no handler behind it renders inert (aria-disabled, no hover fill, honest tooltip) — never a dead button that swallows the click.

03The deck — window tabs

A window can hold several documents. The deck mounts only at ≥2 tabs and never in compact mode, so a single-document window never pays for chrome it doesn't use. When it mounts, the traffic lights move into it (controls="deck") and the head stays where it was. Each tab owns its own head and its own navigation stack.

08Compact mode — below 960px

Reflow, don't block. Compact keeps full route parity while dropping every affordance that needs a pointer and a large canvas — and it never writes over the desktop rects it can't display.

09Shell rules

S1Identity renders once. The 44px head owns it — root identity, breadcrumb, or document self-title, never two of them stacked and never a second route header inside the body.
S2Chrome is bounded. Head 44 + strip 38 + deck 37 = 119px fully loaded. Anything beyond that budget belongs in the body.
S3Views live on the strip as its leading pill-group — views · filters · spacer · Rows|Cards. The in-head .w2-tabs variant is deprecated.
S4One owner per axis. Depth is the breadcrumb, workspace is the menu bar, routes are the dock. No zone borrows another's job.
S5Documents self-title with a state dot and never breadcrumb.
S6Session documents are windows. The dock's Sessions item toggles a modal picker, not a window — it is the one dock item that isn't a route.
S7Minimize folds into the dock icon (hollow dot + dimmed glyph). No minimize tray, no desktop widgets — approvals live in the bell.
S8Settings opens from the cog. It never takes a dock slot and never becomes a route.
S9Accent in chrome means state or primary action. Live dots, attention badges, the New session button, snap previews. Tab selection is neutral.
S10The radius waiver is chrome-only (12–22px, glass, cast shadows). Window content returns to 3–18px and never casts.
S11State persists per desktop via the daemon snapshot — window rects, layout tree, tab set and order, per-tab nav stacks, wallpaper. Not localStorage, not per-browser.
S12Tiled is not floating. Tiled panes drop the cast shadow, resize only through seams and free edges, and stay inside the layout tree.
S13The dock band is reserved. 82px of work area belongs to the dock; no window rect, snap target or arrange preset resolves underneath it.
