CompozyOS · Chapter 06

Settings

Settings is a normal OS window. It opens from the cog in the menu bar, it tiles, it minimises, it stacks with everything else. The old 264px takeover shell — a full-screen surface that swallowed the desktop and hid the window manager — is retired. Inside the window, the section list is just a pane. Everything below is the vocabulary that fills the other column: the .srow family, four section info-shapes, the width ladder, and the three save models.

01Shell — a window, not a takeover

The 44px window head owns identity exactly once (rule 03). The nav pane carries a 28px search, grouped 32px rows, and a version footer pinned to the bottom. Active section = the neutral --elevated plate plus --fg-strong ink. The accent-tint active state that older settings boards used is retired — accent means "act", so it never marks which section is open.

06Save models & notices

Exactly one save bar per page, and only on a draft page. It sticks 24px above the bottom of the content column, sits on --elevated with a --line-strong border, and casts nothing — in-window chrome stays flat. Its dot is warning while changes are pending and success once they land; the wording changes with it.

07The Advanced fold

Exactly one per page, closed by default, always last before the danger zone. It is the only place mechanism keys are allowed to surface — everywhere above it, rows state policy in plain language. If a row can't be phrased as a policy, it belongs in the fold.

08Rules

G1Settings holds policy, not catalog. Installing, enabling and updating live in Marketplace. A Settings section that lists installable things keeps one .srow--link row — "Manage in marketplace" — and stops there. The section configures what is already installed; it never becomes a second store.
G2Plain language over mechanism keys. Every row states a policy in a sentence a new user can act on ("End idle sessions after"), never a config key. Keys surface only inside the Advanced fold, as a .provchip beside a label that still reads as a sentence.
G3Every row maps to a daemon-persisted value. No row exists for a value the daemon can't store and an agent can't read back over CLI, HTTP or UDS. When a saved value only takes effect after a restart, that consequence renders as a warning .notice that persists until the restart happens — never as a silent difference between what the row says and what the daemon is doing.
