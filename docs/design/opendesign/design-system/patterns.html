AGH Design System · Chapter 04

Patterns

How windows compose the vocabulary: listings, drill-in, detail pages, settings, modals, sessions and dashboards. Every pattern assumes the OS shell (chapter 02) owns identity and navigation, and the daemon owns truth — truthful UI beats plausible UI on every surface.

01

Listing surfaces

Inventory routes (Tasks, Loops, Agents, Vault, Sandbox…) share one scaffold. Tools hoist into the window's 38px context strip; the body is rows or cards.

window head 44 controls · glyph+title+count · [peer tabs] · drag · status · ≤2 actions context strip 38 [scope pill-group] · search 28 · [+ filter chips] · spacer · Rows|Cards body .list-shell → .listing-row | .listing-card-grid → .listing-card
L1Toolbar order is locked: filters/search leading → spacer → view-mode PillGroup trailing. Search before filters; facets are filter chips, never kind-tab strips.
L2Every listing route ships Rows|Cards. Rows default (operator scan); Cards for browse density. Persist the choice per route.
L3Never double-encode a facet as both a pill-group and a filter chip; never render “Sorted by …” without a real sort control.
L4Marketplace is the exception: one route, kind pill-group (Skills · MCPs · Extensions · Bundles) + search in the strip, Marketplace|Installed scope tabs in content, cards only — no Rows toggle, no per-kind routes, installed and available always together.
L5Empty states: zero-inventory CTA = the page primary; no-match CTA = Clear filters.
02

Drill-in navigation

Opening an entity from a listing pushes a level inside the same window — depth never spawns another floating window. The head swaps glyph → back chevron + window-local trail.

root [glyph] Tasks ·6· tabs: List | Kanban actions: New task level 1 [‹] Tasks / Nightly triage tabs hidden actions: Open run level 2 [‹] Tasks / Nightly triage / Run #418 actions: Stop run
D1Parents are buttons that jump straight to their level; the leaf is the title, never a link. >2 parents collapse the middle into a “…” crumb whose menu lists hidden levels; any crumb truncates at 150px.
D2Status chip, actions and the context strip are per-level — they swap on every push/pop. Back = chevron, ⌘[ or mouse-back.
D3The trail starts at the window's root route — never the workspace (menu bar owns workspace, dock owns routes).
D4Documents (sessions, runs opened as documents) never breadcrumb; origin, if needed, is a crumbless meta chip.
03

Detail pages

Entity detail (task, agent, loop) renders inside a drilled-in window. The head carries ≤2 pills of state; everything else demotes to a quiet meta strip. Operator depth lives behind an Inspect drawer, not on the page.

head 44 [‹] Tasks / Nightly triage · status pill · primary + ··· subhead priority pill · owner · created · updated (plain text, .dotsep) lane-tabs Overview | Runs ·2· | Activity (40px, 1.5px underline) layout content minmax(0,1fr) ·32px· rail 320px (sticky .railbox: .prow 26px rows) drawer Inspect → .sheet 600px right slide-over (raw ids, bridges, code)
T1Pill budget ≤2 (head status + one subhead pill). Status is derived — never render a status select.
T2One primary action in the head + ··· overflow. Stop/destructive actions stay neutral, never accent.
T3The 320px rail holds property rows (26px, key left / value right, inline-edit affordances). Sheet/drawer: width min(600px, 100vw−24px), slides .2s, scrim + blur, z-sheet.
T4Subtask/dependency rows use the 14px spine grid with state dots: done = filled success · active = hollow accent ring · todo = hollow faint ring.

07

Dashboard

The home window answers three questions in order: what needs you · what agents did · what it costs. Zones: Needs you → KPI strip → live row (Working now | Activity) → Pulse → charts (Outcomes | Usage) → Agents | Network → System.

H1Every widget maps to a persisted daemon read (/api/status, observe/tasks, agents/catalog, session usage, network/status). Metrics needing new aggregation are explicitly marked; nothing is invented to fill a layout.
H2Paired panels close flush — stretch and absorb surplus height with real content (chart flex, distributed rows), footers via margin-top:auto. Never leftover air.
H3Charts use neutral viz ink with provenance footnotes (“each bar counts task runs that ended that day”). Live cards: pulsing dot + pill, standard border.
08

States & truthful UI

U1Never render controls or metrics the runtime doesn't support. On conflict, daemon truth wins. Missing value → honest labelled placeholder, never a fake stat.
U2Every surface designs its empty, loading (skeleton), error (danger notice + retry) and degraded (stale badge) states — not just the happy path.
U3Copy follows COPY.md + the glossary: the artifact is a capability (never recipe/workflow/playbook); plain-language policy over operator jargon; consequence sentences on destructive/persistent actions.
U4Prototype data is runtime-plausible (real routes, real fields from the daemon contract) — realistic, present-tense, no marketing numbers.
