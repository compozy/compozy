AGH Design System · Chosen contract — implementation reference

Window tabs — the deck

Every floating window can multiplex surfaces through tabs, cmux-style: a thin 37px deck above the window holds the controls, the tab row and the drag region, and the 44px head below belongs entirely to the active tab — root head, breadcrumb head or document head render per tab with the full drill-in contract (back chevron, clickable parents, "…" collapse). Route views (List | Kanban) live on the 3rd row — the strip's leading slot — keeping the head two-element. A single-tab window renders today's chrome exactly: the deck costs nothing until the second tab. Demos are live — click tabs to switch, × to close, + to add. This file is the reference for folding the contract into 02 · OS Shell §02 and os/os-v2, then production.

01

Anatomy — deck · head · strip

chosen — cmux model

Three rows, one job each: the deck switches (controls, tabs, +, drag), the head identifies and acts (identity or breadcrumb + status + ≤2 actions, per active tab), the strip tools (route views first, then filters, then Rows|Cards). Tabs stay compact — root-app glyph or state dot + current leaf — so deep breadcrumbs get the head's whole width. The active tab fuses with the head surface, browser-style.

02

Contract rules

D1Tabs cost nothing until the second one. A single-tab window renders today's anatomy — root, drilled or document; the deck mounts at the second tab (⌘T) and unmounts back, controls returning to the head.
D2The head belongs to the active tab. Root identity, breadcrumb (full contract: back chevron in the glyph slot, parents clickable, 150px truncation, "…" beyond 2) or document title + status + ≤2 actions swap per tab. Every tab keeps its own navigation stack — drilling never spawns a window or another tab; the tab label follows the current leaf.
D3Route views live on the 3rd row. List | Kanban is the strip's leading pill-group, before filters (views · filters · spacer · Rows|Cards). The head never stacks a third element — this amendment applies everywhere, single-tab included.
D4S2 amendment. "Two bars maximum" becomes "head + strip, plus the deck while the window holds ≥2 tabs" — up to 119px of chrome fully loaded. The accepted trade for multiplexing.
D5A tab hosts any surface. Routes, drilled-in states and session documents mix freely. Glyphs identify the root app; state dots + badges identify live work (S9 holds — selection is neutral, accent only for state, badges and the primary action). Mild identity echo at a tab's root (label = head title) is accepted; at depth it shrinks to the leaf.
D6Drag out, drop in. Dragging a tab off the deck births a normal window at the pointer (stack preserved); dropping a tab onto another window's deck merges it. In splits, each pane carries its own deck, cmux-style. Open decision: a mixed window shows the active tab's root glyph, and each app's dock dot lights while any window holds one of its tabs.
D7Keyboard. ⌘T new tab · ⌘W closes the tab (the window when it's the last) · ⌃Tab / ⌃⇧Tab cycle · ⌘1–9 jump · ⌘[ pops the active tab's stack. All reachable via ⌘K.
D8State persists per space. Tab set, order, active index and each tab's navigation stack join window rects in desktop-state (S11).

Implementation path. Fold this contract into 02 · OS Shell §02 (window chapter) and the working prototype os/os-v2 (deck in os-v2.css, tab state + drag-out/merge in os-v2.js, per-tab heads in the window templates), then production web/. Route views moving to the strip touches every route with peer views — audit against the pagehead migration map when porting.
