CompozyOS · Design System · Chapter 05

Modals & dialogs

A dialog is where the operator commits a change the daemon will persist. This chapter is the bare-token edition of the shipped modal library: every class demoed here lives in ds-core.css under .dialog*, .dlg-scrim and the .ffield form family. The 16 delivered surfaces in ../_done/modals/ still carry the legacy --color-* names — this chapter supersedes them on naming, never on anatomy.

01Size ladder & scrim

Four widths plus a sheet. Pick by content shape, never by importance: a confirmation is small because it holds one sentence, not because it matters less.

560 · .dialog--sm confirmations · single-decision forms
720 · .dialog default — create/edit entity forms
880 · .dialog--lg multi-section forms · task builders
1180 · .dialog--xl split panes · directory browsers
576 × 100dvh · .dialog--sheet right-anchored inspector sheets

Bars are drawn to scale — .dialog--xl at 1180 is the full track, every other width is a share of it.

The scrim is window-scoped: a modal darkens the window that raised it, so the rest of the desktop stays live and readable. Only a shell-level dialog scrims the desktop.

02Shell

Four grid rows, always in the same order — head, optional mode toolbar, body, footer. The body is the only scroll owner; head and footer stay pinned so the primary action never scrolls away.

PartSpec
Gridgrid-template-rows: auto auto minmax(0,1fr) auto. The minmax(0,…) is load-bearing: without it the body refuses to shrink and the footer leaves the frame.
Frame--canvas-soft, radius 14, --shadow-overlay. No border — the overlay shadow's 1px ring is the border.
Scroll.dialog__body owns overflow-y:auto + scrollbar-gutter:stable, so content does not shift by 10px when the scrollbar appears.
Overflowoverflow:hidden on the frame clips section rules and footer bands to the radius. Popovers raised from inside the body portal out; they are never clipped children.

08Confirmation

10Rules

Eight invariants. Each one names a failure this library exists to prevent — if a dialog breaks one of them, the dialog is wrong, not the rule.

M1One primary per dialog. Two accent buttons means the decision was not made; split the surface or demote one to .btn.
M2Modals never stack. Depth drills within the body (sections, split pane, inline picker) — a dialog raised from a dialog has no legible dismissal story and traps focus twice.
M3Every field maps to a daemon-persisted value. A control the runtime cannot store is plausible UI, and plausible UI is a lie the operator finds out about later.
M4Failure renders inside the body as a .notice--danger with the verbatim cause and a retry — never a toast. The dialog stays open with every value intact.
M5The head icon well is the accent budget. No accent borders, no accent section rules, no accent selected cards — .choice selection stays neutral.
M6Scrim the window, not the desktop. A modal belongs to the window that raised it; the menu bar, dock and every other window stay live.
M7Plain language over mechanism keys. “End idle sessions after”, not session.timeout_seconds. Config keys survive as .provchip inside an Advanced fold.
M8Sheets inspect, dialogs commit. If the surface is mostly read-only property rows, it is a sheet; if it collects a decision, it is a dialog.

The 16 delivered modal surfaces — create/edit for agents, providers, bridges, MCP servers, knowledge, network channels, sandbox profiles, vault secrets, workspaces, plus the task, trigger, job and session builders — live in ../_done/modals/ with modal-system.css, modal-system.js and verify.mjs. They still use the legacy --color-* token names; this chapter is the bare-token successor. Never mix the two dialects in one file.
