CompozyOS · Chapter 08

Empty states

An empty listing is the first screen most people ever see, and it is where a product either explains itself or apologises. CompozyOS empty states are working screens with nothing in them yet — the window chrome stays fully live, the primary action stays where it always lives, and the body offers the shortest honest path to a first item. Four states are designed for every listing: first-run, filtered-empty, error, and degraded/loading. The ../_done/empty-states/ set is the newest legacy — already window-hosted; this chapter modernizes it and fills the two states it never drew.

01Placement — the chrome never degrades

The empty state lives inside the window, not instead of it. The 44px head keeps its glyph, title, zero count and primary action; the 38px strip keeps search and Rows|Cards even though there is nothing to search or switch. A poster screen that swallows the toolbar teaches the user that the controls appear and disappear, which is the one thing chrome must never do.

03Suggestion panel — consent first

When the daemon has drafted work for this workspace, the suggestions are the empty state and the intro block shrinks to an opening line. Every row is a full draft the user can read before accepting: a caret opens a detail inset holding the exact prompt and the machine facts. Nothing runs, and nothing is created, until the user presses Create — the panel note says so in the head, not in a tooltip.

04Templates variant

Same panel, different lifecycle. Templates are a catalog, not a proposal: one neutral Use template per row, no dismiss, no accepted state, no undo. The footnote states the consequence plainly — picking a template opens the create dialog prefilled, so nothing is created from this screen.

05Filtered empty

A list emptied by a filter is not a first-run screen and must never be dressed as one — showing “No jobs yet” to someone with 40 jobs and an active search is a lie. Use the compact .empty--framed inside the list area, quote the query, name every active filter, and offer exactly one way out plus one way wider. Never hide the toolbar that caused it; the search field keeps its text so the user can see what they typed.

06Error, degraded, loading

Three states the legacy set never drew, and the three that decide whether a user trusts the screen. The rule under all of them: never paint stale as live, and never let a UI claim knowledge it does not have.

Error — one honest sentence, cause on demand

The glyph takes a danger tone, the sentence says what failed in plain words, and the raw cause hides behind .empty__cause so the operator can read it without the sentence turning into a stack trace. Retry is neutral; Copy report is ghost.

Couldn’t load jobs

The daemon didn’t answer in time. Your jobs are safe — this screen just can’t read them right now.

Show the cause

the well flips tone; the panel border does not — a red frame turns one failed request into a broken product

Degraded — the list stays, the freshness label changes

When the stream drops but cached rows exist, keep rendering them. Add a stale pill and a reconnecting notice above the list. The rows stay readable and stay honest: they are what we last knew, labelled as such, with actions that could act on stale data disabled rather than hidden.

Loading — skeletons shaped like the answer

Skeleton rows use the real row grid, so the layout does not jump when data lands. Never a spinner over a whole surface, never a skeleton over chrome that is already known.

07Empty-state rules

E1Chrome stays live. Head, count, primary action and context strip render exactly as they do with data. An empty state is never a poster.
E2One accent per screen, and it lives in the window head. Body CTAs are neutral or ghost — including the one in the intro block.
E3Pills carry state only. Kinds, schedules, targets and other enums render as text or mono data. A taxonomy chip is not a badge.
E4Suggestions are consent-first. Nothing is created and nothing runs until the user accepts; the panel says so in its head, the row shows the full draft, and dismiss is durable with an undo.
E5Every listing designs four states: first-run, filtered-empty, error, degraded + loading. A screen with only a first-run drawing is an unfinished screen.
E6Machine truth is demoted, never removed. Cron strings, agent names, fire limits and socket paths live in mono ≤10.5px --subtle, or one disclosure away.
E7Wallpaper glow budget: teal depth behind the window is fine; an accent glow behind an empty state is decoration and is skipped. Accent is “act”, not atmosphere.
E8Filtered ≠ first-run. Quote the query, name the active filters, keep the toolbar, and offer Clear filters plus one wider search.
E9Stale is labelled, not styled away. Cached rows keep rendering under a stale pill; actions that need fresh truth are disabled with the reason visible.
