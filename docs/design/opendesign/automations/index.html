Automations — design set

Start: Listing →
Jobs + Triggers → one area

An automation starts on its own and does one thing. That is the whole idea someone needs to learn.

CompozyOS had two dock apps for the same idea: Jobs (time) and Triggers (events). They had two lists, two detail layouts and two dialogs. The daemon already treats them as one domain (internal/automation, one automation_runs table, shared retry, limits and Loop targets), so this set merges the UI only. The CLI, the API and the tool IDs keep their names one step deeper.
