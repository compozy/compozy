Sessions Kanban — the PR on the topbar, waiting is not done, and a board over it all

Visual contract for _uiux.md S1–S7. The session window's topbar gets an automatic PR chip whose menu carries the next delivery action; a “List | Kanban” toggle turns the window into a board of four derived columns; a waiting session stops looking finished. Titles, PR numbers, counts and times are illustrative.

What it represents

The web half of the Sessions Kanban spec: the topbar status zone (S1–S2), the window identity toggle (S3), the board and its card (S4–S5), waiting (S6) and the finished toast (S7). Behavior authority is _spec.md Part I.

Every value comes from packages/ui/src/tokens.css (dark and light) and every recipe from the named @compozy/ui component. No new token, no new primitive.

S1 · modify · useSessionTopbarSlot + new SessionPullRequestChip · US-004, US-005

S1 — Topbar status zone: the PR chip

The Topbar right-aligns the status zone against the actions, so the chip sits first in that zone — never against the toggle — in the exact geometry of the worktree chip beside it: 24 px surface-2 pill, text-badge medium, muted ink, 12 px glyphs. Anatomy: PR shape (neutral ink — the shape says open, draft, merged or closed) · #number in mono · state word · at most two signals · chevron. Color appears only when the PR needs a decision (failing, changes requested, conflicts) or is ready; everything else stays muted. Breakdown, failing names and check time live in the tooltip.

Before → after

Branch chip — before a PR exists

With a branch but no PR facts, the chip is the branch with one trailing lookup marker. With no branch (default branch, detached HEAD, no repo, removed worktree) nothing renders.

S2 · new · SessionPullRequestChip menu (DropdownMenu) · US-006, US-007, US-008

S2 — Chip menu: the next action first

A plain DropdownMenu: bg-popover, shadow-pop, 32 px items at text-small-body with 16 px glyphs. Order carries priority — no special weight: the exit plan's action for a managed worktree, else “Fix failing checks”, else “Address review comments”, else “Open PR”; then Open PR and Refresh; then the DropdownMenuLabel “Ask the agent” with any remaining prompt. Unavailable actions are absent, never disabled.

S3 · new · SessionViewToggle (ToggleGroup sm, controlled, multiple=false) · US-011

S3 — “List | Kanban” after the title menu

Right after the “…” overflow, outside it, so sessions without an overflow still get it. ToggleGroup size sm: 26 px, text-meta, 14 px glyphs, no track — the pressed item alone takes the surface-2 plate. In Kanban the board publishes its own head: route glyph well, “Sessions”, the toggle, then quiet “Hide child sessions” and secondary “New session” — window heads never carry the inverted primary.

S4 · new · SessionsBoard / SessionsBoardColumn / SessionsBoardArchiveBar · US-011, US-012, US-016

S4 — The board

The Tasks board recipe, unchanged: 296 px sunken columns (no border, no tint) on the canvas pane, 12 px apart; header = 14 px column glyph · text-item-title name · subtle count. Needs you is told apart only by its accent glyph. Columns page 50 with a quiet “Load more · N of M”; Done collapses to a 44 px rail; Archive is a bottom disclosure bar, collapsed, absent at zero.

VC-20 · column glyphs: Needs you = StateGlyph attention (accent) · Working = running · In review = git-pull-request icon (info) · Done = done.

Column states

Archive open · child sessions hidden · Done collapsed

VC-26 archived cards: transparent with a hairline, muted titles · VC-27 “Hide child sessions” pressed (surface-2 plate): children leave rows and counts (3→2, 5→3, 6→5) · VC-25.

300+ sessions. Nothing changes visually: columns hold their loaded pages, counts come from facets, the row scrolls inside the window. A live update re-renders the column queries — no drag affordance, no animation between columns (placement is derived, ADR-004).
S5 · new · SessionBoardCard · US-013, US-014, US-015

S5 — The card: three rows, calm at rest

The TaskKanbanCard recipe: bg-card + shadow-card, radius-lg, 12 px padding, 8 px row gap, hover to surface-2. One whole-card button opens the session in List. Status is a <Pill form="plain"> — a 6 px dot plus muted text, never a plate — so a full board stays neutral and only the dots carry live state (DESIGN.md §2, §10 “signal overload”).

S6 · modify · SESSION_BADGE_SIGNAL + SessionBadgeMark · US-009 · reuses StateGlyph delegated / monitoring

S6 — Waiting: one badge, two glyphs you already know

The sidebar already parks idle sessions in two shapes: delegated (info ring + dot) and monitoring (amber radar). The daemon's waiting badge now says why through waiting_on, and every surface draws the matching glyph — no hourglass, no third shape.

S7 · modify · attention-toast.tsx (ToastFrame) · US-010

S7 — Finished toast

Fires only when the badge enters done, never for waiting. With an open PR, only the body line changes.
