Session continue & fork / dialogs

Continue and Fork dialogs

Two small dialogs on the Start-session shell. Continue picks another agent (and, when the agent declares routes, another route), shows exactly how much of this conversation will be carried over, and asks where the new session opens. Fork keeps the agent locked, names the fork point, and shows the same context line — plus one extra sentence when the agent can clone its own session. Both create; neither confirms in red. The source session is never changed by either.

What this board is

The two dialogs. Continue with another agent: agent picker, runtime, optional route, optional first message, the measured context line, Open in, primary Continue. Fork session: agent read-only, the fork point (whole session or through a quoted message), the context line, Open in, primary Fork session. The context line is the daemon's preview — messages and size, truncation with the omitted count, a running turn that will not be carried, or the native clone sentence — and it decides whether the primary is live.

Continue with another agent — pick the agent, see what travels, choose the window

US-001 · US-002 · US-003 · US-005 · US-015 · VC-06..10
The Start-session shell, with the source already known.

Agent defaults to the first agent that is not the source's (Superset's rule). Runtime is the same selector the composer uses, scoped to that agent. Route appears only when the chosen agent declares fallback_chain routes (Spec A); otherwise the row does not exist.

The context line is measured when the dialog opens, before you decide. It states messages and size, or how many earlier messages were dropped to fit the budget. Continue is disabled while measuring and when the measurement failed — the size of what you send is on screen before the click.

Open in defaults to New window so this session stays visible: the promise is "this session stays unchanged", and you can see that it did.

Fork session — same agent, a named fork point, and the truth about the seed

US-006 · US-007 · US-008 · US-014 · VC-11..15
Smaller, because there is less to choose.

The agent is locked and shown read-only — a fork is the same agent by definition; another agent is a Continue. The fork point is either the whole session or "through" the message you clicked; the point is chosen on the message, so the dialog offers Change, not a picker.

The context line is the same line. When the daemon reports the native seed is possible — this agent advertises session/fork, the source is live and bound, and the point is the whole session — one extra sentence says so. Otherwise nothing claims a capability: the replay seed is always available and the line just states the size.

Two refusals the daemon can return are drawn: a cut turn that has not settled, and a transcript that changed between opening and submitting.

Foot noteFrom {source title} · {agent} (Continue) · From {source title} (Fork)
  • Primary disabled while measuring, on preview error, with no agent (Continue), on a cut turn in progress (Fork), and after a fence conflict until reopened.
  • Primary enabled on a truncated preview and on an empty source (0 messages) — both are truthful, neither is an error.
  • No danger tone. Both dialogs create; the only red is the FieldError text of a refusal. Rewind keeps its danger ConfirmDialog elsewhere.
  • Capability never guessed. The native line is a daemon fact on the preview; without it the replay seed is what runs, and the line states only the size.
  • Route row exists only with routes. Without Spec A's fallback_chain on the agent payload, the row is absent — not disabled, not "Default" alone.
  • After success the dialog closes, the child lands per Open in, and the source window is untouched (New window) or retargeted (This window).
  • Keyboard. Focus trapped; Esc cancels unless pending; radios take arrow keys; Change is a link in the tab order.
