Session continue & fork / lineage

Origin and lineage

Three quiet places say where a session came from. A neutral pill after the provider in the status line — Continued from codex or Forked from Refactor flaky manager tests — that links back to the source. A hairline with the same words at the top of the child's transcript, before its first own message. And an Origin row in the ledger after the session stops. The list already nests children under their parent; nothing else changes shape. The source shows no chrome at all: it was not touched, so it says nothing.

What this board is

Origin, shown truthfully. The child of a Continue or a Fork carries a pill in its status line, a divider at the top of its transcript, and an Origin row in its ledger. The words are the same in all three: Continued from {agent} for a continue (the thing that changed is the agent), Forked from {title} for a fork (the thing that changed is the conversation's path). Where the parent is known on the client the pill and the divider link to it; where it is gone they are plain text. Spawned workers, provenance children, recovery restarts and roots get none of this.

01

The origin pill — after the provider, neutral, a link when it can be

US-009.AC-1 AC-2 · US-009.EC-1 · VC-16 VC-17 VC-18
Information, not status.

The status line reads state · agent · provider. The pill sits after the provider: a Pill in the neutral tone with a small glyph, never a signal hue — origin is a fact about the session, not something happening to it.

"Continued from" names the agent, because that is what changed. "Forked from" names the source title, because the agent is the same and the path is what changed. When the parent is on the client the pill is a link that lands its window; when the parent was deleted the same words render plain (US-009.EC-1).

At narrow widths the window title and the agent truncate before the pill loses its verb.

02

The divider — the boundary between what was carried and what this session said

US-009.AC-3 · US-010.AC-1 · VC-19 VC-20
A hairline, not a transcript.

The carried context travels inside the child's first prompt; it is not persisted as messages, so it is not drawn as messages. What the child shows is a single divider row before its first own message, with the same words as the pill and the same link. Synara draws this boundary the same way.

A child that has not been prompted yet shows the divider alone above the composer — the carried context is staged, the conversation has not started. Nothing pretends the source's turns are here.

The ledger — one Origin row after the session stops

US-009.AC-4 · VC-23
The inspection surface gets the ids.

The status line is plain words; the ledger is where mono ids live. After a stop, the lineage panel already lists workspace, root, parent, depth. It gains one row, Origin: the kind and the anchor — continue · codex for a continue, fork · through msg_… for a fork from a message, fork alone for a whole-session fork.

Spawn children, provenance children and recovery restarts keep the panel as it is: no Origin row.

Copy, rules, what stays silent

  • One function. sessionOriginLabel(session, parent?) feeds pill, divider and ledger; the three can never disagree.
  • Kinds that show nothing. spawn, provenance, recovery, and roots — no pill, no divider, no Origin row. The list nests them as it does today.
  • The source is silent. No "has children" chrome, no marker in its transcript, no rewind banner — it was not changed (US-010).
  • Link or plain. Link when the parent is on the client (same page or resolvable by id); plain text when it was deleted. Never a broken link, never a spinner in a pill.
  • Neutral tone. Origin is information; no signal hue, no accent plate. The divider link uses accent text because it is a link, not because it is a state.
  • Nesting is untouched. session-hierarchy.ts already nests any child with parent_session_id; continue and fork children appear under the source with the pill in their status line.

Reference sources: Synara ForkSourceDivider.tsx:19-53 (hairline + link back to the source, after the last imported row) and threadHandoff.ts:76-81 (an origin badge — rejected wording "Handoff from X"), Codex TUI session_flow.rs "Thread forked from {name}" banner and status/card.rs "Forked from" label (the ledger row's ancestor). Rejected: rendering the carried context as ghost messages; a "has forks" counter on the source; a signal-toned pill. Iterate — never regenerate a delivered board.
