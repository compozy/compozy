Electron shell · the web update surface

The two surfaces ADR-006 moves into the product UI: update state for both tracks — runtime and app — lives in Settings, and a filled accent menubar indicator points at it. Everything on these boards is a projection of GET /api/settings/update; the SPA gains no desktop awareness, so a plain browser pointed at the same daemon renders exactly what the app does. Surfaces and states come from .compozy/tasks/electron-shell/_uiux.md; the section labels are the Visual Contract ids in task_02.md.

Locked decisions
Absent, never disabled A managed runtime, an absent app track, and a live operation all remove the apply control from the DOM. No dimmed buttons, no tooltips explaining why a control cannot be pressed, no rows that exist only to say a thing is missing. The daemon writes the sentences Row descriptions echo the payload's message verbatim — the same strings the CLI prints — and only when they carry truth the version and pill cannot. Up-to-date and available rows stay silent rather than restate themselves. Six phase words, no bar Applying renders Spinner plus the phase in mono: download · 62%, verify, install, start, ready-check, ready. Percent appears only where the runtime measures one, so an unmeasurable phase never shows a fabricated zero. The bar offers, the section decides The indicator exists only while an update is on offer. It carries no count and no menu, and it disappears the moment an operation starts — progress, blocking, and failure are the section's to explain.
