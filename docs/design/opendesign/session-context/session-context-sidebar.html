Context sidebar

session-context-sidebar.html · S3 · S5 · 2026-09-11

One rail, one subject. The Usage / Memory / Files / Vault tabs go; the right rail is titled Context and reads top to bottom: how full the window is and what the number is worth; what Compozy itself put in (≈, per section, per turn); tokens and cost with their provenance; the turn-by-turn history with compaction markers; and what the session is doing right now. Same 320px rail, same drawer below 1440. Content is illustrative; runtime truth owns values.

What this board is

The session's context and observability rail. A three-tier bar that segments only what has a truthful owner — Compozy context ≈, Agent & conversation, Free — with the compaction threshold drawn as a tick. Below it, the sections Compozy can stand behind. Where the agent never reports, the meter says so and the Compozy rows become a plain list. Nothing here is a control except the collapse chevron, "Show earlier turns", and the drawer's close.

US-005.AC-1 AC-2 AC-3 · US-003.AC-1 · VC-10
Compozy ≈ · Agent & conversation · Free. The first is the daemon's estimate of the text it sent (bytes/4, labelled ≈). The second is the reported used minus that estimate — one bucket because the agent's own prompt, tools, MCP catalog, rules and subagent definitions are invisible to Compozy. The third is the window left. When the estimate is larger than used, the Compozy segment is clamped and the legend says so. At 88% the headline and tick carry the warning; the segments stay magnitude colours.

Rows tell their age. A section re-sent as an "unchanged" stub keeps its original estimate and says "unchanged since turn 1". For an agent that never reports, there is no bar to be proportional to: the same rows render as a plain list under an honest headline.
