What this board is

S2 — one row that says what a thing is and where you stand with it. A 40px logo, the name, one line of description, and on the right exactly one of: Install, Installed, Update, a reason it cannot be installed, or — in the Installed view — the controls that manage it. The logo is real when the catalog or a brand has one, and a generated marble tile when it does not; it is never a generic puzzle piece. Everything is an extension, so the card never says what an entry contains; the Installed row does (“1 MCP server · 2 skills”), and everything else (author, version, tier, source) lives one click away in the detail.

card VC-02
Real when it exists, generated when it does not. 1 — the catalog or marketplace document carries an icon URL: render it at 28px inside the well. 2 — no icon, but the entry id or install slug matches a brand in @compozy/ui/logos: render the brand mark at 20px (monochrome marks take --fg; branded fills stay theirs). 3 — neither: a Boring Avatars “marble” tile generated from the entry id, filling the well (decided 2026-09-10 on the avatars board). 4 — only if that render fails: the first letter of the name. A broken image falls to 3. A generic glyph is never a fallback.

04

Installed trail — the controls that manage it, and what it contains

card VC-04
Same row, management on the right. Only the Installed view uses this trail. Every row: enable switch + overflow. When the extension provides an MCP server, the server’s status word with a dot (running · needs authorization · stopped) and Authorize when pending come first. Update, when available, precedes everything. After the name, a quiet summary of contents from the inventory (“1 MCP server · 2 skills”) and, for plugins from a marketplace, the marketplace name. Overflow = View details · Edit server configuration (when there is a server) · Remove… (type-to-confirm, unchanged).
