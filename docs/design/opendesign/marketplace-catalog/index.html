Marketplace catalog

Five boards that turn the Marketplace into one surface with one kind of thing in it: extensions. The window lists the whole catalog; an installed entry reads “Installed” on its card instead of living behind a toggle. What you have is one line at the top — a row of logos and a count — and that line drills into the Installed view. Cards become compact rows with a real logo and a description. The packaged MCP servers become extensions that carry a server; the skills catalog is retired; ClawHub goes with it. Plugin marketplaces (the marketplace.json documents Claude Code, Codex, and Cursor users already point at) become catalog sources, so the plugins Compozy can already install are in the list. Every board opens with what it is, which production components it changes, and the states it covers with their Visual Contract ids. The semantic contract is DESIGN-NOTES.md.

How to read a board
1 · Contract blockThree columns at the top: the surface in plain words · the production files it modifies, adds, deletes, or reuses unchanged (backend rows marked) · the states on the page, each linked, each with its VC id.
2 · Specimen + calloutsEvery specimen is a production-geometry OS window or a flush fragment. Inverted numbered markers point at the element; the legend under it names the component, the token values, and the authority (production · reference · delta).
3 · TagsThe mono tag strip under each specimen: state · component · VC · tone / accent budget. Grep a VC id to find its specimen.
