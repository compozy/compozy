What this board is

S4 — silence means the agent is idle, never that you are disconnected. A small chip at the window head’s trailing edge appears only when the live stream is degraded: connecting, reconnecting with the attempt count, catching up, or paused in a background window. Brief blips show nothing. If retries run out you get a sentence and Try again — never a blank conversation. Sending while disconnected fails at once and keeps your draft.

04

Retries ran out — a sentence and Try again, never a blank thread

US-018.AC-2 · task_06 VC-03
Two shapes, one rule: failed is never empty. If the conversation had loaded, it stays — with a danger chip and a marker at the end saying when live updates stopped and a Try again. If it never loaded, the pane (production ThreadStatePane geometry) says the conversation didn’t sync, how many tries, and offers Try again. The composer is inactive in both: a send couldn’t go anywhere. Danger is earned here — this is a real failure of the live view.

06

A window in the background is paused, and says so

US-018.EC-2 · US-012.AC-3 · task_06 VC-05
A lagging watcher lags alone. An unfocused session window keeps its last frame and a neutral “Paused · 4m” chip — the honest word for a live view that isn’t applying frames. Bring it forward and it catches up (section 03) then goes quiet again. The session and the other windows are unaffected: this is the watcher, not the turn.

07

The phase dictionary, and the sidebar footer

US-018.AC-1 · session-live-tail-store-contract.ts
Five store phases, four chip words, one rule for first attempts. The first connect of a fresh window reads “Connecting”; anything after a failure reads “Reconnecting” with the count (t3code’s rule). The sessions sidebar footer uses the production ConnectionIndicator with the same phase, so the list and the window never disagree.
