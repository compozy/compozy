# CompozyOS v0.3 single-cut runbook

This is the human-executed runbook for the one external v0.3 cut. It prepares
`v0.3.0-beta.1`; it is not authorization for an agent to publish, push a branch, merge, change DNS,
edit a registry, or archive a repository.

## Stop condition and owners

Do not begin until Task 13 has a fresh green pre-publish report for the exact candidate commit and
the release-PR dry-run lane is green. Record its commit SHA and evidence paths in the cut log. If any
step fails, stop. Do not infer a replacement version, move a tag, retry a partial publication, or
continue to the next external system.

The release owner executes GitHub, npm, and Homebrew operations. The hosting/DNS owner points
`compozy.com` and retires the former domain. The security owner audits secret history and rotates
exposed credentials. Use UTC in the cut log.

```bash
export CUT_REPO="compozy/compozy"
export CUT_VERSION="0.3.0-beta.1"
export CUT_TAG="v${CUT_VERSION}"
export CUT_EVIDENCE="$(pwd)/.tmp/release-cut/${CUT_TAG}"
mkdir -p "$CUT_EVIDENCE"
git rev-parse HEAD | tee "$CUT_EVIDENCE/candidate-commit.txt"
date -u +%FT%TZ | tee "$CUT_EVIDENCE/started-at.txt"
```

## 1. Pre-cut evidence and security gate

1. Confirm the Task 13 report names the same candidate commit recorded above.
2. Confirm `make verify`, `make installer-check`, `make codegen-check`, the release-PR dry-run, and
   IT-017 are green for that commit.
3. Run the repository-history secret audit from a clean clone. The security owner must record the
   scanner version and keep the redacted report in the private cut evidence, never in Git:

   ```bash
   gitleaks version | tee "$CUT_EVIDENCE/gitleaks-version.txt"
   gitleaks git --redact --report-format json \
     --report-path "$CUT_EVIDENCE/gitleaks-report.json" .
   ```

4. Triage every finding against the full Git history. Rotate any credential that was ever committed,
   even when the current tree no longer contains it. Record only provider, secret name, rotation time,
   and revocation confirmation; never record values.
5. Verify the repository or organization provides every required Actions secret:

   ```bash
   gh secret list --repo "$CUT_REPO" --json name --jq '.[].name' | sort \
     >"$CUT_EVIDENCE/actions-secret-names.txt"
   for name in RELEASE_TOKEN GORELEASER_KEY NPM_TOKEN COMPOZY_WEB_ASSETS_TOKEN \
     DAYTONA_API_KEY DAYTONA_API_URL DAYTONA_ORGANIZATION_ID DAYTONA_SNAPSHOT \
     DAYTONA_IMAGE DAYTONA_SSH_HOST; do
     grep -Fxq "$name" "$CUT_EVIDENCE/actions-secret-names.txt" || {
       printf 'missing Actions secret: %s\n' "$name" >&2
       exit 1
     }
   done
   ```

   For this cut, `COMPOZY_WEB_ASSETS_TOKEN` is required because the release-PR external web-assets
   publication path is authorized; do not silently substitute an operator credential. Confirm
   `RELEASE_TOKEN` can create tags/releases and update `compozy/homebrew-compozy`, `GORELEASER_KEY`
   is valid for the pinned GoReleaser Pro version, and `NPM_TOKEN` can publish `@compozy/cli` without
   printing token values.

6. Confirm `.github/codeql/codeql-config.yml` is present on the candidate, retains
   `security-extended`, and covers `cmd/`, `internal/`, `magefiles/`, `sdk/go/`, and `main.go`. Do not
   import the legacy `auto-docs.yml` or `claude.yml` workflows. Confirm GitHub code scanning/default
   setup uses this configuration and record the latest successful analysis URL.
7. Record pre-cut channel state:

   ```bash
   gh api "repos/${CUT_REPO}/git/ref/heads/main" --jq '.object.sha' \
     | tee "$CUT_EVIDENCE/precut-main.txt"
   npm view @compozy/cli dist-tags --json \
     | tee "$CUT_EVIDENCE/precut-compozy-cli-dist-tags.json"
   gh api repos/compozy/homebrew-compozy/contents/Formula/compozy.rb --jq '.sha' \
     | tee "$CUT_EVIDENCE/precut-homebrew-formula-sha.txt"
   ```

## 2. Create the legacy maintenance branch

Create `legacy/v0.2` from the pre-cut `main`, never from `v0.3`. Work in a separate clean worktree so
the candidate checkout remains unchanged.

1. Fetch `origin/main` and record its commit. It must equal `precut-main.txt`.
2. Create `legacy/v0.2` at that exact commit.
3. Prepend `docs/release/legacy-v0.2-readme-notice.md` to the legacy README without rewriting the
   preserved v0.2 documentation below it.
4. Commit only the maintenance notice as `docs: mark v0.2 as maintenance-only`.
5. Push `legacy/v0.2`, confirm the remote branch points at the notice commit, and record its SHA.

No v0.3 installer, runtime state, package metadata, or compatibility shim belongs on this branch.

## 3. Squash v0.3 into main

Use the protected GitHub pull request from `v0.3` to `main`. Reconfirm that its head equals the Task 13
candidate and its base equals the recorded pre-cut `main`. Squash-merge it as one replacement commit;
do not rebase the legacy history into the new tree. Record the resulting `main` SHA and confirm the
tree contains this runbook, the release workflow, README, migration guide, installer, and CodeQL
configuration.

Stop if the squash commit differs from the commit checked by the final pre-publish gate in any way
other than the expected Git squash identity. Task 13 must be rerun against changed source.

## 4. Publish the beta through the pinned workflow

Dispatch only the workflow on `main`; the workflow owns the annotated tag and publication. Pass an
unprefixed version and do not create the tag by hand.

```bash
gh workflow run release.yml --repo "$CUT_REPO" --ref main \
  -f release_ref=main \
  -f release_version="$CUT_VERSION" \
  -f release_channel=beta
run_id="$(gh run list --repo "$CUT_REPO" --workflow release.yml --event workflow_dispatch \
  --limit 1 --json databaseId --jq '.[0].databaseId')"
gh run watch "$run_id" --repo "$CUT_REPO" --exit-status
printf '%s\n' "$run_id" | tee "$CUT_EVIDENCE/release-run-id.txt"
```

The pinned `github.com/compozy/releasepr@v0.0.25` plan must emit the authoritative ref, commit,
unprefixed version, tag, predecessor tag, exact Git range, initial-release intent, channel, GitHub
prerelease/latest policy, npm tag, and Homebrew skip policy. The workflow must render the GitHub
body from that exact range, publish GitHub as a prerelease, publish `@compozy/cli` with dist-tag
`beta`, leave npm `latest` unchanged, and skip Homebrew. If the run partially publishes and then
fails, stop for incident review; never overwrite the tag or republish an immutable npm version.

Desktop publication must follow `desktop-build` → `desktop-smoke` → `desktop-publish`. The smoke
installs the candidate macOS DMG and Linux AppImage into an empty home with no operator runtime on
`PATH`, then proves one healthy self-started daemon plus matching app-record and provenance
versions before any candidate feed or release asset is published. It intentionally provisions the
current signed channel runtime; candidate runtime bytes and signatures are verified separately by
`desktop-publish`. Stop the release if either proof fails.

## 5. Point the public site and retire former hosting

The hosting/DNS owner performs this step after the GitHub/npm release exists:

1. Promote the `packages/site` deployment built from the squash-merged `main` to `compozy.com`.
2. Remove the former marketing deployment from `compozy.com`.
3. Retire the former domain's DNS and hosting. Do not add redirect infrastructure.
4. Record provider change IDs, DNS values, deployment commit, and UTC completion time privately.

## 6. Repository metadata and channel collateral

Update repository metadata, then upload the approved social preview in GitHub Settings from the new
`imgs/` collateral. Record a screenshot of the final metadata.

```bash
gh repo edit "$CUT_REPO" \
  --description "One complete environment to create, automate, and supervise agent work." \
  --homepage "https://compozy.com" \
  --add-topic agents --add-topic ai-agents --add-topic local-first \
  --add-topic golang --add-topic acp
```

In `compozy/homebrew-compozy`, keep the formula binary/version on v0.2.15 but disable it for the beta
window with a UTC cut date and a reason that points to `https://compozy.com/install.sh` and
`@compozy/cli@beta`. Replace the tap README notice with `docs/release/homebrew-beta-notice.md`. Commit
and push that notice as a separate collateral change. Do not upload a v0.3 formula archive or change
the formula to the beta tag.

## 7. Post-publish live checks

These checks are post-publication acceptance, not Task 13 preconditions. Store their outputs in the
private cut evidence.

1. GitHub release and tag:

   ```bash
   gh api "repos/${CUT_REPO}/releases/tags/${CUT_TAG}" \
     | tee "$CUT_EVIDENCE/github-release.json"
   test "$(gh api "repos/${CUT_REPO}/releases/tags/${CUT_TAG}" --jq '.prerelease')" = true
   test "$(gh api "repos/${CUT_REPO}/releases/latest" --jq '.tag_name')" != "$CUT_TAG"
   ```

2. npm channel policy:

   ```bash
   npm view @compozy/cli dist-tags --json | tee "$CUT_EVIDENCE/compozy-cli-dist-tags.json"
   test "$(npm view @compozy/cli dist-tags.beta)" = "$CUT_VERSION"
   test "$(npm view @compozy/cli dist-tags.latest)" = "0.2.15"
   ```

3. Hosted installer and Sigstore identity in a clean temporary directory:

   ```bash
   install_dir="$(mktemp -d)"
   curl -fsSL https://compozy.com/install.sh \
     | COMPOZY_INSTALL_DIR="$install_dir" COMPOZY_SKIP_BOOTSTRAP=1 sh
   "$install_dir/compozy" version | tee "$CUT_EVIDENCE/installer-version.txt"
   "$install_dir/compozy" version | grep -F "$CUT_TAG"
   ```

   Keep the installer log showing the Sigstore bundle verification and the
   `compozy/compozy/.github/workflows/release.yml@refs/heads/main` certificate identity. Remove the
   temporary directory after evidence capture.

4. Clean Go install:

   ```bash
   go_root="$(mktemp -d)"
   GOBIN="$go_root/bin" GOPATH="$go_root/gopath" GOMODCACHE="$go_root/mod" \
     go install "github.com/compozy/compozy@${CUT_TAG}"
   "$go_root/bin/compozy" version | tee "$CUT_EVIDENCE/go-install-version.txt"
   ```

5. Homebrew remains off the beta line: the formula still names v0.2.15, carries the beta-window
   disable/deprecation notice, and no formula URL or checksum points at `$CUT_TAG`.
6. `curl -fsSIL https://compozy.com` resolves to the new site and its canonical metadata names
   `https://compozy.com`. The former domain no longer serves the old site and has no redirect layer.
7. `main` contains the v0.3 squash tree; `legacy/v0.2` contains the maintenance notice and retains the
   v0.2 tree.
8. GitHub code scanning shows a successful analysis with `security-extended` after the main cut.

Record pass/fail, command output path, owner, and UTC timestamp for every check. Close the cut only
when all eight pass or an explicitly owned incident explains the remaining failure.
