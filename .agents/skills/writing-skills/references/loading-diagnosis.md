# Diagnose a Missed Reference

A skipped reference matters when its missing contract caused an incorrect result. Reading every file is not an objective by itself.

1. Confirm the failed task required the reference and inspect the observed output. A successful task without the read is useful counterevidence.
2. Check that the file exists, the path resolves, the needed section is findable, and its guidance is current. Look for conflicting instructions and a duplicate inline contract before strengthening wording.
3. Place one pointer at the point of use: when the task needs a contract, name the file and relevant section. Require a full read only for an inseparable schema/procedure. Use a short section index for long references.
4. Repair the actual cause: narrow a trigger, fix a path, reconcile ownership, remove a duplicate, or improve a helper. Avoid automatic STOP language, forced full reads, or extra subagent handoffs.
5. For a behavior-changing trigger repair, try a representative task and assess its result and cost when practical. State when validation is static only. Recheck only the repaired route after further edits.

Keep references reachable; they may link to other references when this saves duplication and the needed dependency is clear. Do not flatten or expand an entire package merely to satisfy a formatting rule.
