# Skill Review

Use for new skills or substantial behavioral rewrites. Review only affected concerns for a small edit; a concise result is sufficient. This checklist is authoring guidance, not an additional gate for every task that uses the skill.

- The trigger identifies a concrete need and avoids redundant automatic invocation.
- The outcome and stopping condition are observable; required steps exist for a dependency, contract, or evidenced failure.
- User authorization and repository policy remain authoritative; optional work does not become a permission loop.
- Shared rules have one owner; local variants and source synchronization are explicit.
- References name when and which sections to read; full reads are reserved for whole contracts that are actually needed.
- Generic knowledge, rhetorical escalation, stale model pins, and duplicated reporting/review/testing are removed.
- Metadata is valid for the target harness and existing validator; paths and helper invocations resolve from the actual skill root.
- Changed helpers pass their owning behavioral checks. A prose edit does not need a test that freezes wording.
- Validation reports what was checked and what remains uncertain; measured improvement requires comparative task evidence.

Fix substantive defects found by this review. Do not manufacture a Pass/Fail artifact for every item unless an explicit deliverable requires it.
