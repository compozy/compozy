# Lite TechSpec Template (`_techspec.md`)

The research-driven techspec: evidence-first, no interactive rounds, no ADR ceremony. It is the
document `cy-execute-task` reads for implementation guidance, so every section must be actionable
and cited. Target length: dense but bounded — link to `analysis/` instead of duplicating it.

```markdown
# TechSpec — [Title]

- **Status:** Draft (research-driven; generated by cy-research-issues)
- **Date:** YYYY-MM-DD
- **Scope:** [top-level paths in play]
- **Companion artifacts:** `analysis/summary.md`, `_tasks.md` (+ task files)

## 1. Context & Goals
[Why this workstream exists: reported symptoms, product goal, competitor benchmark. Numbered
goals; explicit non-goals.]

## 2. Root Causes / Findings (evidence-backed)
[One table or numbered list per bug class / theme. Every row: cause → `path:line` evidence →
owning analysis section. This section is the contract that fixes address causes, not symptoms.]

## 3. Target Architecture / Design
[Per surface (data layer, backend, UI...): the end-state design. Reference competitor patterns by
exact path when copying. Include the project-rule guardrails that constrain the design (design
tokens, signal palette, zero-legacy, etc.). Diagrams/row-models inline when they fit in ~20 lines.]

## 4. Delete Targets (zero-legacy)
[Table: what gets removed → what replaces it. Every breaking change lists its delete targets.]

## 5. Sequencing (waves)
[Numbered waves mapping to task ids: W1 = correctness/bug critical path, then perf, then redesign,
then hygiene. State what gates each wave (tests-first, telemetry-first, screenshots).]

## 6. Open Decisions
[Contested calls with 2+ defensible options: state options, trade-offs, and the recommendation.
Empty section = "None" explicitly.]

## 7. AGH Impact Audit
- Native tools: <impact or "no impact + checked surfaces">
- Extensibility and hooks: <extensions/hooks/skills/config lifecycle impact; contract-codegen
  co-ship duties for any API change>
- Workspace data isolation: <scope classification of new/changed data + leak-path check>
- Official AGH skill: <skills/agh/ updates required or "no impact + why">

## 8. Web/Docs Impact
[Affected web routes/components/hooks AND docs-site pages; "no impact" only after analysis.]

## 9. Verification Strategy
[Which canonical suites own the new invariants (per test-placement rules), E2E lanes, benchmarks,
screenshot verification for UI, and the repo-wide completion gate.]

## 10. Reference Catalog
[Primary files (ours + competitors) grouped by area — paths only, one line each. Full per-file
roles live in the analysis Reference Index tables; link them.]
```

## Rules

- Apply YAGNI to the target design: no new packages/abstractions unless the analyses prove the
  need.
- Standing directives and lessons (`docs/_memory/`) that constrain this domain are cited in §3.
- Contested decisions go to §6 — the skill never blocks on interactive ADR rounds; a later formal
  `cy-create-techspec`/ADR pass can harden §6 items if the user wants.
- Language: English. Active voice. Every sentence earns its place.
```
