# Spec Part I Checks

Confirm the motivating problem, observable outcome, affected users/agents, scope, and unresolved product decisions. Record material extension/manageability expectations where relevant. Reuse already accepted direction; a new stage or message does not require renewed approval.

Keep implementation detail in Part II unless it is an explicit user constraint or the subject of the feature. Framework, protocol, file-format, and storage names are not automatic defects.

The optional `.agents/skills/cy-spec-preflight/scripts/check-spec-part1-leak.py` produces keyword candidates, not a semantic verdict. Inspect each candidate; accepted technical constraints need no exception-approval ritual. An ADR is useful for a consequential decision, not mandatory for every answered question.
