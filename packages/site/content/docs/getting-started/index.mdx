Getting started is four ordered steps. Each one leaves behind state the next one uses, so work
through them in order the first time: install the binary, start the daemon and drive one real
session, add a custom agent definition, then open the same session in the web UI.

<OperatorNote>
  Every step operates on the same local daemon and the same SQLite-backed history. Nothing here is a
  sandbox or a simulation — the session you create in Quick Start is the one you inspect in the Web
  UI page.
</OperatorNote>

## Where to go next

Once the daemon is running and you have created a session, the rest of the documentation is
organized by runtime concept rather than by sequence. [Sessions](/docs/sessions) covers the
durable unit you just created, [Agents](/docs/agents) covers definition resolution and
provider supervision, and [Configuration](/docs/configuration) covers which file or
environment variable to change when you need to alter the behavior you saw here.
