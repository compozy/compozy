CompozyOS keeps shortcut defaults in the daemon. The web app, Settings, and the keyboard reference
all read the same effective keymap: daemon defaults plus your validated overrides.

## Inspect the keymap

Use the Settings API when you need the typed contract:

```bash
curl http://localhost:2123/api/settings/window-manager
```

The response separates stored and effective state:

- `config.shortcuts`: only stored overrides.
- `effective_shortcuts`: the complete map used by the shell now.
- `aliases`: workspace aliases keyed by command ID.
- `commands`: registry metadata used to group every bindable command by source.
- `extension_defaults`: extension-provided defaults, including dormant conflicts.

The CLI exposes the same discovery data under `value`:

```bash
compozy config get window_manager -o json
```

## Configure a binding

Each action accepts one chord string or an array of chord strings. An empty string or array disables
the action. A chord uses modifier names followed by one browser `KeyboardEvent.code`.

```toml
[window_manager.shortcuts]
"window.focus.left" = ["control+ArrowLeft", "alt+KeyH"]
"window.split.right" = ""
```

Indexed action families accept range bindings. Array members may also be ranges:

```toml
[window_manager.shortcuts]
"desktop.switch" = ["control+Digit1..9", "meta+Digit1..9"]
"window.tab.jump" = "control+alt+Digit1..8"
```

The daemon expands ranges before validation. A duplicate anywhere in the complete effective map
rejects the whole update; no partial binding is stored.

A binding you stored keeps working when a later release ships a default on the same chord: your
override wins, and the default loses that chord. Recording a new chord that another command already
uses is still a conflict until you overwrite it.

Use `config set` with a JSON array for alternates:

```bash
compozy config set 'window_manager.shortcuts.window.focus.left' \
  '["control+ArrowLeft","alt+KeyH"]'
```

For workspace-scoped changes, use the command-palette verbs. They update the complete keymap
atomically through the daemon. A project keymap is a full copy: it replaces the user keymap for
that project. The other window settings inherit per key, so a project shortcut edit stores only
the keymap, and a later user change to a setting such as `focus_policy` still reaches the project:

```bash
compozy cmd-palette bind window.focus.left control+ArrowLeft --workspace acme
compozy cmd-palette unbind window.focus.left --workspace acme
compozy cmd-palette bindings --workspace acme -o json
```

When a chord belongs to another command, the daemon names that owner and stores nothing. Add
`--overwrite` to transfer the chord from the named owner.

## Configure a global hotkey

The desktop shell can register a global chord for each command from anywhere outside CompozyOS. The daemon owns the intended map under
`[window_manager.global_shortcuts]`; each desktop shell reports whether its chord is active, captured
by another application, blocked by permission, or unsupported.

```bash
compozy cmd-palette bind palette.summon.global meta+shift+Space --global
compozy cmd-palette unbind palette.summon.global --global
```

A plain browser cannot register these chords and shows **requires desktop shell** without changing
the in-app keymap. Read [Global hotkeys](/docs/desktop/global-hotkeys/) for registration states,
Accessibility recovery, and platform behavior.

## Configure an alias

Aliases are workspace vocabulary for command search. They contain 1–32 characters with no
whitespace and are unique within the workspace.

```bash
compozy cmd-palette alias set session.new new --workspace acme
compozy cmd-palette alias clear session.new --workspace acme
```

Use `--overwrite` to transfer an alias already owned by another command. You can also declare
aliases in a workspace overlay:

```toml
[cmd_palette.aliases]
"session.new" = "new"
```

`window.split.right` and `.down` split the focused window and open a New tab pane beside or below
it, ready for you to pick what it shows.
`session.cycle.previous` and `.next` walk the open session list in the order you see it: project
and folder headers as well as session rows. A header takes focus, and → / ← expand and collapse it;
a session row opens that session.
`window.tile.left`, `.right`, `.top`, and `.bottom` move the focused window to that edge of its tab.
`window.unsplit` is **Move to new tab**: it takes the focused window out of its split into its own tab.
`window.swap.left`, `.right`, `.up`, and `.down` swap the focused split window with the nearest window
shown on that side of its tab; with no window there they do nothing.

Retired in v0.7.0: `window.minimize`, `window.zoom`, `window.toggle_floating`,
`window.tile.top-left`, `.top-right`, `.bottom-left`, `.bottom-right`, `window.merge_all`, and
`window.tab.detach`. A binding to one of them still loads until v0.8.0 and does nothing; Settings →
Shortcuts marks the row **retired**, and resetting it removes the binding.

Press `?` outside an editable field, or press ⌘/ anywhere, to open the live keyboard reference.
Escape remains a fixed close/focus-return key and is not part of the configurable map.

## Shortcuts while you type

Shortcuts keep working while focus is in a text field, the composer, or a terminal:

- A chord with Command, Control, or Option runs its command from a text field. Plain keys and
  Shift-only chords such as `?` stay typing.
- A text field keeps its own editing chords: undo and redo (⌘Z, ⌘⇧Z), select all, copy, cut,
  paste, bold, italic, underline, and moving the caret by word or line (⌥← and ⌘← on macOS,
  Control with an arrow elsewhere).
- In a terminal on macOS, every bound chord runs its command and every unbound chord reaches the
  shell, including ⌃K, ⌃V, and ⌃0. On Linux and Windows, a chord whose only modifier is Control
  stays with the shell (⌃W, ⌃E, ⌃1…), except the palette (⌃K), paste, copy with a selection, and zoom.
- Holding a bound chord runs it once; the key repeat is swallowed instead of typed.

Edit any binding in Settings → Shortcuts. The old Terminal preset is gone because its chords are
now the defaults.

## Platform notes

- Control+digit may switch browser tabs outside the desktop app on non-Apple platforms.
- Control+Option can alias AltGr on some keyboard layouts. AltGr chords stay typing on Linux and Windows.
- `?` depends on the current layout's Shift+Slash mapping. ⌘/ is the reliable alternative on non-US layouts.
- A focused control keeps its own local shortcuts. The keyboard reference marks those rows read-only.
