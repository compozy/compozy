description: What each gateway tier exposes, what an attacker reaches at each one, and the fail-closed guarantees that hold when something breaks.

This page states what is actually reachable at each exposure level and what the runtime guarantees
when a component fails. It is written to be checked against behaviour, not to reassure.

## What is reachable, per tier

### Local only (default)

Nothing outside the machine. The daemon binds loopback for HTTP and a Unix socket for the CLI. The
agent kernel, resource mutation, and the hosted MCP surface exist only here and never move.

**Reached by:** a process on the machine, with the file-system access to reach the socket.

### Private overlay

The full operator UI and management API, over your own overlay network, to devices that hold a
device session.

**Reached by:** anything on your overlay network reaches the _listener_. Without a device session it
gets the pairing gate and nothing else. Reaching an address is never authentication.

**Also served here:** pairing redemption, and pairing minting for an already-authenticated device.

### Public address — delivery ingress

Webhook and bridge callback endpoints only.

**Reached by:** the internet. These endpoints are deliberately unauthenticated at the operator layer
and instead verify each delivery themselves: HMAC signature, timestamp freshness, and delivery-id
uniqueness, all before any side effect. A delivery that fails verification produces no side effect,
is visible to you, and tells the sender nothing beyond the failure.

A valid delivery grants exactly one thing: dispatching its own trigger. It is not an operator
session and cannot become one.

**Not served here:** the operator UI, the management API, pairing mint, pairing redeem. The public
listener is built without those routes.

### Public address — operator access (consented)

The operator UI and the management API, on the public address.

**Reached by:** the internet reaches the _gate_. Getting past it requires a device session, and a
device session can only be obtained on the private overlay or on the daemon machine — **there is no
pairing route on the public listener under any configuration**.

This is the largest exposure the product offers. It requires explicit consent naming what becomes
reachable, and that consent is required again on every enable.

## Boundaries that hold by construction

**Tier is a property of the listener, never a header.** Each listener is built with a fixed route
inventory at construction. A request cannot ask to be treated as another tier, because the route it
wants does not exist on the listener it reached.

**Tier listeners grant no loopback trust.** Being local on a tier listener grants nothing: every
request either authenticates as a device session or verifies itself. This matters because the
provider forwards external traffic to a loopback port — if loopback implied trust, the provider
would be an authentication bypass.

**The database is the only exposure authority.** Configuration contributes static tunables and one
immutable ceiling (`gateway.enabled`). No configuration key duplicates runtime intent, so there is
no combination of flags and environment values that enables a surface behind your back.

## Fail-closed guarantees

These hold when things go wrong, which is when guarantees matter.

**Verification before advertisement.** An endpoint is advertised only after the daemon fetches a
one-time challenge _through that endpoint_ and gets its own nonce back. A reachability probe cannot
substitute for this: it proves something answered, not that it reaches this daemon's assigned tier.
Verification requires HTTPS with real TLS validation, follows no redirects, bounds the response, and
refuses a public endpoint that resolves to a private address.

**Provider failure degrades, it never half-exposes.** The reconciler applies effects in a fixed order
— persist intent, bind listener, establish provider, verify endpoint, advertise — and unwinds in
reverse on any failure. There is no intermediate state that is externally reachable. A supervised
failure marks the tier degraded and advertises nothing.

**Crash recovery restores intent, not exposure.** Boot reconciles before anything is advertised or
any tier listener accepts external traffic. A crash restores the last state you asked for and never
re-enables a surface you turned off.

**Stale effects are discarded.** Every durable transition is fenced by a generation. An effect that
completes against an obsolete intent is dropped rather than applied, so a slow provider cannot
resurrect exposure you already withdrew.

**Provider trust is re-derived, never remembered.** Install source and control digest are recomputed
from the live extension registry on every enable and every boot. A mismatch fails closed and requires
re-consent. Workspace-scoped extension sources are rejected outright: connectivity is an
operator-global capability and a workspace-scoped source has no owner rule that could authorize it.

**Revocation terminates live connections before it returns.** The revoke transaction bumps the
device's epoch, then cancels every registered stream for that device, and only then does the call
return. An in-flight mutation revalidates immediately before commit, so a device revoked mid-call
fails its transaction instead of committing a partial write.

**Credentials are one-way, and tickets are the thing that travels in URLs.** The daemon stores only
`sha256(credential)` and compares in constant time; the raw device credential exists in transit and
in client-local storage, never in a table, a log, or a URL. Live streams are a separate case worth
stating plainly: browser EventSource and WebSocket clients cannot attach the device authorization
header, so they use a short-lived, single-use **stream ticket** passed as a `?ticket=` query
parameter. That ticket can therefore appear in proxy logs, server access logs, and browser network
diagnostics — which is exactly why it is not the credential. It is redeemed once, expires on
`gateway.stream_ticket.ttl` (30s by default), and every reconnect acquires a fresh one, so a ticket
recovered from metadata is already spent or expired.

**Secrets never cross a surface unredacted.** Device credentials, pairing artifacts, stream tickets,
provider credentials, and raw claim tokens appear only as hashes, references, or truncated forms in
logs, status, events, audit output, and every tier listener response.

## What this does not protect against

Stated plainly, because a threat model that only lists strengths is not one.

- **A compromised daemon machine.** Local access is the root of trust: it can mint pairings and
  revoke devices. Someone with that machine has the product.
- **A compromised paired device.** A device session is a bearer credential. If a device is stolen,
  revoke it — that is what the inventory and immediate revocation are for.
- **A malicious connectivity provider.** A provider sees the traffic it forwards. Trust gating,
  digest confirmation, and re-consent on expanded control are the controls; they reduce the risk of
  installing one, not the consequence of running a hostile one.
- **Delivery loss while offline.** There is no store-and-forward queue. Deliveries sent while the
  daemon is down are lost from Compozy's side; sender-side retry is the mitigation.
- **Denial of service.** Ingress is rate-limited per endpoint and per source, and authentication
  failures are rate-limited per source. That bounds abuse; it does not make a public address immune
  to traffic.

## Checking your own posture

```bash
compozy gateway audit
```

Findings carry stable identities, a severity, and a remediation that names the next action. Run it
after any exposure change and after any provider incident.
