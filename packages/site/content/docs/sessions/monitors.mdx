---
title: Monitors
description: Let an agent start long-running work, end its turn, and wake up on its own when the work finishes.
---

A monitor lets an agent say "wake me when this finishes" and keep that promise. The agent starts a
long command (a build, a deploy, a release workflow), registers a monitor on it, and ends its turn.
When the command exits, prints the line you were waiting for, or a timer runs out, CompozyOS starts a
new turn in the same session with the result.

## Why agents need it

Coding agents such as Claude Code and Codex have their own background tasks and monitors. Inside
CompozyOS, those cannot start a new turn. A turn exists only when CompozyOS sends a prompt, so the
agent's "I'll report back when it finishes" never came back and the session sat idle.

Monitors are owned by the CompozyOS daemon instead, so the wake always reaches the session:

- every agent is told to use monitors for any wait on outside work, such as CI, deploys, or builds,
  whether or not it outlives the turn;
- for Claude Code sessions, CompozyOS turns off the Monitor, ScheduleWakeup, and Cron tools and
  refuses background shell commands (Bash and PowerShell), because their results could never reach you. Background
  subagents keep working: their results return inside the turn that started them.

### Shell waits are redirected

An agent that waits inside its own shell keeps the turn busy, so the session looks stuck and
CompozyOS can't supervise the wait. When a session can use monitors, CompozyOS refuses these commands
and tells the agent the exact call to make instead:

| Refused                                                    | The agent is told to                               |
| ---------------------------------------------------------- | -------------------------------------------------- |
| `gh pr checks --watch`, `gh run watch`, `watch`, `tail -f` | run it in a terminal and put a monitor on it       |
| `while`, `until`, or `for` loops that `sleep` to poll      | run the loop in a terminal and put a monitor on it |
| `sleep` for 5 seconds or more                              | set a timer monitor                                |

Shorter sleeps, `gh pr checks` without `--watch`, and text that only mentions these commands still
run. The check also sees through `timeout`, `env`, `bash -c`, and paths such as `/bin/sleep`.

What each provider gets:

- **Claude Code:** a hook refuses the command before it runs.
- **Codex and other ACP providers:** there is no hook, so the agent mostly relies on its
  instructions. CompozyOS can refuse a wait only when the provider asks for permission to run the
  command or opens a terminal through CompozyOS. Codex runs commands its sandbox allows without doing
  either, so those waits are not refused.
- **Sessions without the monitor or terminal tools:** nothing is refused, because a shell wait is the
  only wait they have.

If the check itself fails, the command runs.

## What a monitor can watch

| Kind       | Fires when                                                                                    | Limits                                                                                    |
| ---------- | --------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| `terminal` | the terminal's process exits (`until: exit`) or its output matches a pattern (`until: match`) | `timeout_seconds` defaults to 30 minutes, up to 6 hours. A timeout still wakes the agent. |
| `timer`    | `delay_seconds` have passed                                                                   | 5 seconds to 24 hours                                                                     |

Each session can hold up to 8 active monitors, and each terminal up to 4. Registering the same
terminal condition again (same terminal, `until`, pattern, normalized timeout, and description) returns the monitor that is already
active, so a retried call never adds a second wake.

There is no polling kind for remote state such as CI. The agent runs the bounded watch command
(for example `gh pr checks <n> --watch`) in a terminal and monitors that terminal, setting
`timeout_seconds` past the expected wait.

## Walkthrough: wait for a long command

Ask an agent to run something slow and report back, for example:

> Run `make release-check` and tell me when it's done.

1. The agent runs the command with `compozy__terminal_exec`. The command keeps going after the
   tool returns, so the result says `still_running` with a `terminal_id`.
2. The agent calls `compozy__monitor_create`:

   ```json
   {
     "kind": "terminal",
     "terminal_id": "term-3f9a1c2b7d10",
     "until": "exit",
     "description": "make release-check finishes"
   }
   ```

   The result returns a `monitor_id` (for example `mon-8c41e0a29b77`) and tells the agent to end
   its turn.

3. The agent ends its turn. The session goes idle, and you can keep working in other sessions.
4. When the command exits, the transcript shows a divider: **Monitor fired · make release-check
   finishes · Process exited**. Right after it, the agent's new turn reads the exit code and the last
   lines of output, and reports back.

If you send a message while the agent is busy, the wake waits behind the current turn. If the
session's input queue is full, CompozyOS keeps retrying the wake for up to 15 minutes. Stopping the
session cancels its monitors, so nothing it registered restarts it later.

## See and cancel monitors in the app

A session whose turn ended but still has an active monitor is not done yet, and the app says so:

- In the session list, the row shows an amber radar mark instead of the green done check.
- In the message box, a radar button with the number of active monitors sits next to the attach
  button. Click it to see what each monitor watches (a timer, a terminal exit, or a terminal output
  pattern) and when it fires or gives up.
- Click **×** on a monitor to cancel it. The session is not woken, and the watched command keeps
  running. A monitor that already fired reads "Waking the session…" and can no longer be canceled.

When the last monitor fires or is canceled, the radar button goes away and the row shows its normal
state again.

The same reads are available over HTTP and the local socket:

```bash
curl http://127.0.0.1:2123/api/workspaces/<workspace>/sessions/<session>/monitors
curl -X POST http://127.0.0.1:2123/api/workspaces/<workspace>/sessions/<session>/monitors/<monitor_id>/cancel
```

Every session payload also carries `monitor_summary.active` while the session has active monitors.

## Managing monitors from the agent

- `compozy__monitor_list` shows the session's active monitors first, then the ones from the last
  hour that fired, are still retrying their wake, were canceled, or could not be delivered.
- `compozy__monitor_cancel` stops a monitor from waking the session. It does not stop the command
  being watched; use `compozy__terminal_close` for that.

Monitors live in the daemon process. Restarting the daemon drops active monitors, the same way it
ends the terminals they watch.
