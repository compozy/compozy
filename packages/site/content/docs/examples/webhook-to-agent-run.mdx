## What you build

An endpoint your CI can post to that starts an agent run. A deploy finishes, CI posts a small JSON
body, and an agent picks the work up with the commit and branch already in its prompt.

The endpoint is not open. Every delivery carries an HMAC-SHA256 signature over the timestamp and
raw body, must arrive inside a 5-minute freshness window, and must bring a delivery id that cannot
be replayed while that window is open. Requests that fail any of those are rejected before an agent
is ever started.

Use it when an external system already knows something happened and you want Compozy to act on it.

## The artifact

Two halves: the trigger that owns the endpoint, and the signed request that reaches it.

```toml title="config.toml"
[[automation.triggers]]
scope = "workspace"
workspace = "/Users/you/src/checkout-api"
name = "deploy-webhook"
event = "webhook"
endpoint_slug = "deploy"
webhook_secret_ref = "env:COMPOZY_DEPLOY_WEBHOOK_SECRET"
agent = "deployer"
prompt = "Validate deployment {{ index .Data \"sha\" }} on {{ index .Data \"branch\" }}."
filter = { "data.action" = "deploy", "data.branch" = "main" }
retry = { strategy = "backoff", max_retries = 2, base_delay = "5s" }
fire_limit = { max = 6, window = "1h" }
```

```bash title="post a signed delivery"
body='{"action":"deploy","branch":"main","repository":"checkout-api","sha":"abc123"}'
timestamp="$(date -u +%s)"
signature="sha256=$(printf '%s.%s' "$timestamp" "$body" \
  | openssl dgst -sha256 -hmac "$COMPOZY_DEPLOY_WEBHOOK_SECRET" -hex \
  | awk '{print $2}')"

curl -sS -X POST "http://localhost:2123/api/webhooks/workspaces/ws_123/deploy--wbh_abc123" \
  -H "Content-Type: application/json" \
  -H "X-Compozy-Webhook-Timestamp: $timestamp" \
  -H "X-Compozy-Webhook-Signature: $signature" \
  -H "X-Compozy-Webhook-Delivery-ID: deploy-$timestamp" \
  --data "$body"
```

## Run it

Store the secret, then create the trigger and read back the path CI should post to — the full
endpoint segment is `<endpoint_slug>--<webhook_id>`, and the webhook id is assigned on creation:

```bash
# Compozy-managed secret storage; or export the env var named by webhook_secret_ref
compozy vault put automation/deploy-webhook

compozy automation triggers create \
  --name deploy-webhook \
  --scope workspace \
  --workspace /Users/you/src/checkout-api \
  --event webhook \
  --endpoint-slug deploy \
  --webhook-secret "$COMPOZY_DEPLOY_WEBHOOK_SECRET" \
  --agent deployer \
  --prompt 'Validate deployment {{ index .Data "sha" }} on {{ index .Data "branch" }}.' \
  --filter data.action=deploy,data.branch=main \
  --retry backoff:2:5s

# the response carries the webhook id — read it back any time
compozy automation triggers get <trigger-id>
```

## How it works

<Workflow>
  <WorkflowStep title="The signature message is timestamp, dot, raw body">
    `<unix_timestamp>.<raw_request_body>`, HMAC-SHA256 with the trigger's secret, hex-encoded, sent
    as `sha256=…`. Sign the raw bytes you actually send — re-serializing the JSON after signing
    changes the digest and the delivery is rejected.
  </WorkflowStep>
  <WorkflowStep title="Freshness and replay are separate checks">
    The timestamp must fall inside a 5-minute window in either direction, and
    `X-Compozy-Webhook-Delivery-ID` must not have been seen while that window is open. A retrying
    CI job that reuses its delivery id is deduplicated rather than run twice.
  </WorkflowStep>
  <WorkflowStep title="The body becomes `.Data`">
    A JSON object's fields are exposed under `.Data` for both filters and prompt templates, plus
    metadata keys `endpoint`, `endpoint_slug`, `webhook_id`, and `timestamp`. A body that is not a
    JSON object arrives as `.Data.payload`. Bodies are capped at 1 MiB.
  </WorkflowStep>
  <WorkflowStep title="Filters decide before an agent starts">
    Every filter entry must match exactly. Here the delivery only dispatches when
    `data.action` is `deploy` and `data.branch` is `main` — a staging deploy hits the same endpoint
    and is dropped without spending a session.
  </WorkflowStep>
  <WorkflowStep title="The secret is write-only">
    Compozy resolves `webhook_secret_ref` only when validating a signature. Read endpoints never
    return the secret, and neither does this page — `env:NAME` keeps it with the operator,
    `vault:automation/...` keeps it encrypted in Compozy-managed storage.
  </WorkflowStep>
  <WorkflowStep title="Target a Loop instead of a prompt">
    Swap `agent` and `prompt` for a `loop_target` to start a published Loop. Unlike scheduled jobs,
    a trigger has an activation envelope, so `input_mapping` can route `data.<path>` values into
    the Loop's inputs.
  </WorkflowStep>
</Workflow>
