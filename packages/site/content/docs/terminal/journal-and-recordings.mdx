---
title: Journal and recordings
description: Query durable command facts, understand ephemeral output, and opt in to full terminal replay.
---

CompozyOS separates terminal history into three data classes.

| Data                       | Default               | Lifetime                                                    |
| -------------------------- | --------------------- | ----------------------------------------------------------- |
| Command journal            | Always on             | Until the workspace is deleted                              |
| Live output and scrollback | Ephemeral and bounded | Until terminal or daemon runtime ends                       |
| Full recording             | Explicit opt-in       | Until its configured retention expiry or workspace deletion |

The journal writes one row for each command boundary detected in a CompozyOS terminal. It records the
actor, command, working directory, timing, exit cause, approval, output size, truncation, and detection
method. `exact` and `marker` are authenticated boundaries; `idle` is approximate and remains labeled.

Query recent rows:

```bash
compozy terminal journal --workspace my-project --since 24h --limit 50 -o json
```

Add `--actor agent`, `--failed`, or `--terminal <id>` to narrow the page. Continue with `--cursor`
when `next` is non-null. Use `--all-profiles` for an operator-owned aggregate view with profile owner
labels. See [`compozy terminal journal`](/docs/cli/terminal/journal).

## Record only when replay is needed

Start and stop recording explicitly:

```bash
compozy terminal record start term-4aa01f22e6c3 --workspace my-project -o json
compozy terminal record stop term-4aa01f22e6c3 --workspace my-project -o json
```

The response identifies the recording, terminal, owning profile, digest, byte size, timestamps, and
expiry. The browser journal can open the linked recording. HTTP or UDS clients download it from
`GET /api/workspaces/{workspace_id}/terminals/recordings/{recording_id}` under the same profile scope.

Recording uses a bounded writer. Storage failure stops the recording and reports the failure; it does
not stop the live terminal. Input marked redacted never enters a recording. Output not explicitly
recorded cannot be reconstructed after its ephemeral buffer is gone.

Spilled bounded-output artifacts follow the same workspace and profile checks. Clients download an
artifact from `GET /api/workspaces/{workspace_id}/terminals/artifacts/{artifact_id}`; a foreign-profile
or missing artifact returns the same not-found boundary instead of revealing ownership.
