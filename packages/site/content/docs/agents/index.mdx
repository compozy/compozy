---
title: Agents
description: How CompozyOS resolves agent definitions, advertises capabilities, launches providers, and supervises ACP subprocesses.
---

Agents are the executable unit CompozyOS manages. A definition file declares the agent identity, the
provider that runs it, the permissions it inherits, and the capabilities it advertises. At session
start CompozyOS resolves that definition into an ACP subprocess, injects environment, negotiates the
session, and supervises it through stop.

Use this section when you need to answer which agent will run, which provider command CompozyOS will
execute, what capabilities the agent offers for task selection, or why a session did not launch the
way you expected. Agent docs sit between configuration and sessions: configuration explains the
files, sessions explain live runtime state, and this section explains the handoff from definition to
managed subprocess.

<OperatorNote>
  This section is the runtime model for agents. The `AGENT.md` file format itself lives under
  [Configuration → AGENT.md](/docs/configuration/agent-md); reach for it when authoring, not when
  troubleshooting runtime resolution.
</OperatorNote>

For a new project, start with definitions, confirm the provider ID on the providers page, then check
spawning if the process fails. Reach for capabilities when the question is what another agent can
discover about the agent, not how the process starts.

## Activity reads

`GET /api/agents/{name}/activity?days=30&workspace=<id>&profile=<name>` returns
`reports_by_day`, `cost_by_project`, and `busy_by_hour`. Omitting `workspace` aggregates
all readable projects and User scope; `workspace=@user` selects User only. Days range from 1 to 365.

Team clients can use `POST /api/agents/activity?profile=<name>` over HTTP or UDS:

```json
{ "days": 14, "items": [{ "name": "reviewer", "workspaces": ["@user", "project-id"] }] }
```

The response's `activities` array contains one unchanged activity payload per input item, in order.
Each item selects its own definition's workspaces. The endpoint accepts 1–100 items, 1–100 workspace
references per item, and at most 5,000 authorized workspace selections overall. Both activity routes
read one profile, enforce workspace access, and are unavailable to app tokens. The batch read has
no side effects.
