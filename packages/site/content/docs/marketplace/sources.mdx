title: Plugin sources

Plugin sources add extensions from GitHub, an HTTPS Git repository, or a local folder to the daemon's
Marketplace. The folder or repository must contain `marketplace.json` at its root, under
`.claude-plugin/`, or at the Codex path `.agents/plugins/marketplace.json`, checked in that order.
Each listed plugin is loaded with the same manifest loader used during installation. The listing
reports `installable`, `install_blocker`, layout, category, and the digest of its captured package.

## Default sources

CompozyOS ships with preset sources. `compozy-plugins` is the CompozyOS-curated plugin catalog,
published at [github.com/compozy/plugins](https://github.com/compozy/plugins) and on by default. It
is generated from Anthropic's Apache-2.0 plugin catalogs plus verified MCP Registry apps, with pinned
refs, CompozyOS categories, and Featured picks. When a curated entry replaces the same app from another
default source, Browse shows it once (see `supersedes` below).

Turn it off like any preset, from Settings → Marketplace or the CLI:

```bash
compozy config set marketplace.plugin_sources.compozy-plugins.enabled false --scope user
```

Turning it off keeps plugins you already installed from it, and the rows it replaced appear again on
the next read. If you turned it off, upgrades keep it off.

## Manage sources (experimental)

Source management is experimental for this release. List, add, refresh, and remove sources through the
CLI; changes are saved to the daemon's global `config.toml` and applied immediately:

```bash
compozy marketplace sources list -o json
compozy marketplace sources add example/team-plugins --name team -o json
compozy marketplace sources refresh team -o json
compozy extension install team/tool --allow-unverified --yes -o json
compozy marketplace sources remove team -o json
```

An absolute folder or a GitHub repository URL works with `sources add` too. Removing a source keeps
its installed extensions. Presets can be disabled, but cannot be removed. The CompozyOS feed stays on.
If a plugin slug also names an existing curated acquisition ref, that curated ref keeps priority;
`compozy extension install marketplace:team/tool` explicitly selects the plugin source.

The [Marketplace API reference](/docs/api/marketplace) documents the same HTTP and UDS operations:

| Operation                                    | Behavior                                                                            |
| -------------------------------------------- | ----------------------------------------------------------------------------------- |
| `GET /api/marketplace/sources`               | All source rows, including disabled presets, ordered by the daemon.                 |
| `POST /api/marketplace/sources?dry_run=true` | Inspect `{ "ref": "example/team-plugins", "name": "team" }` without registering it. |
| `POST /api/marketplace/sources`              | Validate and save the source, then refresh its packages.                            |
| `PATCH /api/marketplace/sources/team`        | Send `{ "enabled": false }` or `{ "enabled": true }`.                               |
| `DELETE /api/marketplace/sources/team`       | Remove a custom source.                                                             |
| `POST /api/marketplace/sources/team/refresh` | Return the current state, including a degraded state if acquisition failed.         |

Every source includes `stability: experimental` and a `diagnostics` array. A `degraded` source keeps
its last successful listing. Disabled sources are neither fetched nor listed in Browse. A source that
has not been read reports `never`. `compozy marketplace refresh` reports every source and exits with
status 1 only when all attempted sources failed.

GitHub source acquisition pins the document and repository archive to one commit. A source may
therefore fail even when its marketplace JSON is reachable. The safe `error_class` distinguishes
upstream HTTP status (for example, `http_415`), `rate_limited`, `dns_failed`, `tls_failed`, and
`network_blocked`; unknown failures retain `fetch_failed`. Upstream response text and credentials
are not included. Retry uses the same public source and network policy, without borrowing a token.

A name collision returns `marketplace_source_exists` with `suggested_name`. A name retained by an
installed extension returns `marketplace_source_name_retained` with `retained_by`. Use another name
or the original source ref. `compozy` and `compozy-catalog` are reserved. A rejected document reports
`marketplace_not_a_marketplace` with both `checked` paths, or `marketplace_document_too_large` above
2 MiB. Fix the source and preview again.

## Configure a source

Add a source in `config.toml` and reload the configuration:

```toml
[[marketplace.plugin_sources]]
name = "team"
source = "github:example/team-plugins"
enabled = true
```

Sources also accept `git+https://example.com/team/plugins.git` and an absolute file URL such as
`file:///Users/me/team-plugins`. The CompozyOS feed supplies presets. An explicit config row for the same
source overrides its enabled state, even if the preset is renamed. Disabled sources are not fetched.
Refresh with `compozy marketplace refresh -o json`, then inspect the returned source states.

Source names appear in install slugs. The immutable identity is `(source_ref, entry_id)`. Registering
the same repository under two names lists it twice but joins both rows to the same installed extension.
An installed extension keeps its identity if that source is removed and later registered again.
A name retained by an installed extension cannot be reassigned to a different source.

## Plugin source shapes

Each `plugins[]` entry in `marketplace.json` names its package with one of five `source` shapes:

```json
{
  "name": "acme-plugins",
  "owner": { "name": "Acme" },
  "plugins": [
    { "name": "local", "source": "./plugins/local", "category": "productivity" },
    { "name": "gh", "source": { "source": "github", "repo": "acme/gh-plugin", "ref": "v1.2.0" } },
    { "name": "https", "source": "https://github.com/acme/https-plugin" },
    {
      "name": "whole",
      "source": { "source": "url", "url": "https://gitlab.com/acme/whole.git", "ref": "main" },
      "category": "DATA_ANALYTICS"
    },
    {
      "name": "sub",
      "source": {
        "source": "git-subdir",
        "url": "https://github.com/acme/mono.git",
        "path": "plugins/sub",
        "ref": "4f2a9c1"
      },
      "category": "design"
    }
  ]
}
```

`url` installs a whole repository. `git-subdir` installs one contained folder of a repository; its
`path` must stay inside the repository. `ref` is optional for both. Every Git URL follows the same
policy as other sources: public HTTPS, no credentials, no query or fragment. A shape the daemon cannot
read is reported on the source as `unsupported_source` and skipped; the rest of the document still
lists.

`category` is free text. CompozyOS maps it to one of its own categories and uses More when it cannot.

### Curated fields

CompozyOS-curated sources (`compozy-catalog` and `compozy-plugins`) may add an `x-compozy` object to
an entry:

```json
{
  "name": "linear",
  "source": { "source": "github", "repo": "acme/linear-plugin" },
  "x-compozy": {
    "category": "productivity",
    "featured": true,
    "supersedes": ["claude-plugins-official/linear"]
  }
}
```

`category` sets the CompozyOS category directly, `featured` adds the entry to Featured, and
`supersedes` hides each listed `<source>/<entry_id>` row from Browse, category pages, search and
counts while this entry is listed. If you installed the superseded row, that row stays visible and
the curated row is hidden instead. Superseded rows remain readable through
`compozy marketplace info`. The daemon ignores `x-compozy` from every other source, so a third-party
marketplace cannot feature itself or hide another source.

## Client plugin compatibility

Plugins in the Claude Code (`.claude-plugin/`), Cursor (`.cursor-plugin/`) and Codex
(`.codex-plugin/`) layouts load as they are:

- **Root MCP file.** A manifest without `mcpServers` loads `mcp.json` or `.mcp.json` from the plugin
  root; `mcp.json` wins when both exist. A plugin without a manifest loads its skills and MCP file
  from the default locations, using the marketplace entry for its name. The entry reports
  `client_mcp_discovered`.
- **Placeholders.** `${CLAUDE_PLUGIN_ROOT}` and `${CURSOR_PLUGIN_ROOT}` mean `${PLUGIN_ROOT}`, and
  `${CLAUDE_PLUGIN_DATA}` means `${PLUGIN_DATA}`. A command that starts with a root placeholder runs
  as a contained `./` path inside the plugin.
- **Unknown server fields.** A field CompozyOS does not support, such as `placement`, is dropped with a
  `client_field_ignored` warning instead of rejecting the server.
- **Values the plugin needs.** `${NAME}` and `${NAME:-default}` in a server's `url`, `headers`, `env`
  or `args` become plugin inputs. A name without a default is required. A name ending in `KEY`,
  `TOKEN`, `SECRET` or `PASSWORD` is a secret stored in the Vault; every other name is plain text.
  The daemon fills them in when the server starts, and secret values never appear in the catalog,
  manifest copy or logs. An invalid name reports `client_placeholder_invalid`.
- **OAuth.** A remote server's `auth` object (`CLIENT_ID`, `CLIENT_SECRET`, `scopes`) becomes its
  OAuth sign-in. Write the secret as `${CLIENT_SECRET}` so it becomes a secret input. `auth` keys
  that cannot be mapped are dropped with `client_field_ignored`.

For example, this root `.mcp.json` asks for `NOTION_TOKEN` (secret) and `SERVICENOW_HOST` (text) and
signs `servicenow` in with OAuth:

```json
{
  "mcpServers": {
    "notion-local": {
      "command": "${CLAUDE_PLUGIN_ROOT}/bin/notion-mcp",
      "env": { "NOTION_TOKEN": "${NOTION_TOKEN}" },
      "placement": "sidebar"
    },
    "servicenow": {
      "type": "http",
      "url": "https://${SERVICENOW_HOST}/sncapps/mcp-server/mcp",
      "auth": {
        "CLIENT_ID": "abc123",
        "CLIENT_SECRET": "${CLIENT_SECRET}",
        "scopes": ["mcp_server"]
      }
    }
  }
}
```

In Marketplace, Add opens the review dialog to collect required values, and the row reads **Set up**
until every value is set and every server that needs sign-in is signed in. Plugin `hooks`,
`commands`, `agents` and Cursor `rules` folders are not loaded; they report
`client_component_ignored` and do not block installation.

## Install approved bytes

Read the entry detail before installing. Send its install slug and digest through HTTP or UDS:

```json
{
  "source": "marketplace",
  "ref": "team/tool",
  "expected_digest": "<digest_sha256 from the entry>",
  "allow_unverified": true
}
```

Use this body with `POST /api/extensions`; add `"enable": true` to turn the extension on in the same
operation. The daemon also requires
`extensions.trust.allow_unverified = true`. Plugin marketplaces are unverified: a Claude plugin layout
or a matching digest does not establish publisher trust. Required inputs use the normal extension
confirmation flow. A different origin that declares an already installed instance name returns
`409 extension_name_conflict`.

The daemon captures the listed package in its home-owned cache and verifies its digest when reading
it. Refresh sweeps unreferenced packages oldest first toward a 1 GiB budget. Current catalog rows and
installed provenance keep their packages pinned; in-flight publication finishes before pins are read.
If pins alone exceed the budget, refresh reports the capacity error and preserves those packages.
Installation uses cached bytes even if the source later changes or goes offline. Missing or corrupt
blobs appear with `install_blocker: package_unavailable` in the catalog. The daemon can reacquire a
missing or corrupt blob and proceed only if the digest still matches.

| Response                                  | Next step                                                     |
| ----------------------------------------- | ------------------------------------------------------------- |
| `404 marketplace_source_not_found`        | Choose a source currently registered in the catalog.          |
| `409 extension_source_changed`            | Refresh, inspect the new package, and approve its new digest. |
| `503 source_unreachable`                  | Restore source access and retry the approved package.         |
| `422 extension_checksum_unverified`       | Review the unverified package and provide explicit consent.   |
| `422 extension_unverified_policy_blocked` | Review the daemon's extension trust policy.                   |

Updates select the current package by installed origin and compare digests, including when the
version is unchanged. They retain the existing input, publication, attachment, and rollback behavior.
Inspect the recorded source, resolved revision, layout, and digest with
`compozy extension provenance <installed-name> -o json`.

## Catalog settings

Settings → Marketplace also edits the CompozyOS catalog base URL, refresh TTL and request timeout. These settings apply live and preserve your plugin sources. The same fields are available through `GET` and `PATCH /api/settings/marketplace` as `config.base_url`, `config.ttl` and `config.timeout`.

To disable a named source from the CLI:

```bash
compozy config set marketplace.plugin_sources.team.enabled false --scope user
```

Source settings are global. Disabling or removing a source keeps its installed extensions available in Installed. The original source name remains reserved for those installed packages until they are removed; re-adding the same source is allowed.
