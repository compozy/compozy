Open Marketplace to browse one catalog of extensions. An extension can provide MCP servers,
skills, tools, profiles, or other capabilities; its contents describe what you are installing.
Search narrows the catalog. Installed entries stay marked in place, and the installed count opens
[Installed](/docs/marketplace/installed), where you manage your local extensions.

<OperatorNote>
  Start the daemon before using Marketplace in the app or through the CLI and API. The public
  [catalog](/marketplace) is a build-time snapshot; your daemon owns the active catalog and installed state.
</OperatorNote>

## Browse And Inspect

The app opens the catalog at `/marketplace`. Select an entry to inspect its description, contents,
version, source, and trust decision. With one source, entries appear in a flat grid; multiple sources
have separate sections. Refresh fetches the latest catalog. If a source is unreachable, cached
entries remain visible with their stale status. An unavailable source is not an empty catalog.

The HTTP and UDS interfaces expose the same catalog:

```http
GET /api/marketplace?q=herdr&limit=20
GET /api/marketplace/entries/herdr-bridge?source=compozy-catalog
```

A page contains `items`, the filtered `total`, `sources`, `revision`, and `stale`, plus `next_cursor`
when more entries remain. Pass the cursor unchanged with the same query, profile, and workspace.
If the server returns `marketplace_cursor_stale` with `restart: true`, discard the earlier pages and
start again. Identical refreshes retain the content revision.

An entry is identified by `(source_ref, entry_id)`. Installed state joins on that origin, not a display
name. Use `installed_name` when selecting a specific local installation. Entries without catalog
provenance still appear in Installed. Follow the returned `manage_path` for management.

## Install An Extension

Choose Install on an entry whose trust decision allows installation. Entries that need configuration
request their declared inputs before completing installation. Add also supports installation from
GitHub or a local folder. Use the entry's `install_slug` for CLI installation:

```bash
compozy extension install compozy/herdr-bridge -o json
compozy extension provenance herdr-bridge -o json
```

For curated entries, the daemon downloads the exact HTTPS `artifact_url`, verifies `digest_sha256`
before extraction, and records provenance. A mismatch returns `extension_archive_digest_mismatch`
and does not install the package; `--allow-unverified` cannot bypass it. The pre-install trust report
and a verified download are separate facts.

A non-curated install requires both daemon policy and explicit consent:

```bash
compozy config set extensions.trust.allow_unverified true -o json
compozy config reload -o json
compozy extension install acme/private-extension --allow-unverified --yes -o json
```

If policy blocks the request, inspect `extension_unverified_policy_blocked` and its repair action.
Do not infer runtime readiness from successful installation: a capability may still require inputs
or authorization. MCP configuration and authorization are described in [MCP catalog operations](/docs/marketplace/mcp-catalog).

## CLI Discovery

The existing CLI verbs remain available. Inspect their structured output before choosing an install target:

```bash
compozy marketplace search "herdr" --kind extension -o json
compozy marketplace info extension herdr-bridge -o json
compozy marketplace refresh --kind extension -o json
```

The retained CLI accepts kind selectors; the app has one catalog and a separate Installed page.
For route parameters and response shapes, use the generated [Marketplace API reference](/docs/api/marketplace).
