## 3. Remaining findings

### Blocking

**B-1 — Major — The canonical "committed success survives caller cancellation" dispatch test fails at head; reproduced locally in isolation.**
- Evidence: CI run 33187446299 (head `657a3eef1`), Go race shard 4: `TestRuntimeRegistryDispatchValidationAndPolicy/Should_preserve_a_successful_mutation_committed_before_caller_cancellation` — `RuntimeRegistry.Call() error = tool call canceled, want committed success` (`internal/tools/dispatch_test.go:217`). Reproduced locally at this head with `go test -race -run …/Should_preserve_a_successful_mutation… ./internal/tools/` — deterministic, in isolation.
- Cause: the test's tool commits, cancels the caller context, and returns success. `postDispatchContext` detaches into a bounded context **only when `r.completionTimeout > 0`** (`internal/tools/dispatch.go:116-121`); the test registry (`mustDispatchRegistry`) sets no completion timeout, so `completeDispatch` runs on the canceled context and the committed result is converted into a cancellation error — the precise `backend_unhealthy`-class lie (review 13 F-002 / summary Onda 0) this test exists to pin. `internal/tools/dispatch.go` and this test are byte-identical to review 20's head, so the pin has never been green on CI.
- Why blocking: this is the corpus's central truthfulness contract, its canonical regression is red at head, and the repo rule is fix-production-never-weaken-the-test. Expected correction: make the detach unconditional with a safe default bound (production wires `calls.operation_timeout`, default 30s — mirror that as the registry default rather than zero), or make a zero timeout mean "detached without deadline", and leave the test untouched.

**B-2 — Major — Workspace resolution now hard-requires `ProfileRuntimeResolver`, breaking the extension Host API session contract suites at head.**
- Evidence: CI shard 4: ~8 failures across `TestHostAPIHandlerBindsWorkspaceScopedExtensionCalls`, `TestHostAPIAutomationJobsTriggerContract`, `TestHostAPIHandlerBridgesMessagesIngestContract`, `TestHostAPIHandlerSessionsSoulRefreshRequiresWorkspaceOwnership` — all with `session: resolve workspace "ws-host-api": session: workspace resolver does not support profile layers` or its downstream `-32005 Unavailable`.
- Cause: `resolveWorkspaceForProfile` fails closed on a bare type assertion when the injected resolver does not implement `workspacepkg.ProfileRuntimeResolver` (`internal/session/manager_workspace.go:188-193`, introduced by `fe7353db0`/`9f269e57c`; twin branch at `internal/daemon/prompt_skills.go:278`). Whether the correct fix is production (support resolvers without profile layers, or register the capable resolver on the Host API path) or the harness (implement the interface), the head's CI is deterministically red in feature-adjacent public-contract suites, and a production resolver shape lacking the interface would break session creation at runtime.

**B-3 — Major — Profile lifecycle freeze test fails: `calls.Create()` rejected `call_widening_rejected` at head.**
- Evidence: CI shard 5: `internal/profile TestManagerProfileLifecycle/Should_freeze_queued_call_activations_and_inventory_call-owned_work` — `manager_test.go:131: calls.Create() error = call_widening_rejected: permission narrowing widens the caller set`.
- Cause shape: review 20's advisory 4 predicted exactly this — `wideningPermissionAtoms` rejects everything when the caller's persisted tool policy is empty, safe only while every caller materializes a concrete tool universe. A caller reaching `Create` through the profile-lifecycle path now trips the fail-closed branch. Expected correction: fix the policy materialization for that caller path (or the widening comparison for the empty-policy case) in production code; do not adjust the test's expectation.

**B-4 — Minor (fix already in flight) — Generated `compozy call` CLI reference lists `--sandbox-profile`, failing the site's implemented-flags contract test at head.**
- Evidence: CI Frontend lane: `packages/site/lib/__tests__/runtime-autonomy-docs.test.ts` — "lists exact implemented flags for task, channel, and call examples": `expected '…compozy call…' not to contain '--sandbox-profile'`.
- The very next commit on the branch (`ed0673fe2`, outside this review's head) is named for this repair; verify its CI before treating it closed. Whichever side is wrong (a flag documented but not implemented, or implemented but not admitted to the contract test), the public `compozy call` reference is part of this feature's agent-manageable surface and must be truthful.

**B-5 — Major — The Calls panel's Received rail can never name who asked: the `operator` branch tests a value the daemon never emits, and its test fabricates that value.**
- Evidence: `web/src/systems/agent-comms/lib/call-row-who.ts:15-16` — `if (call.caller.kind === "operator") return "operator"; return "unknown caller";`. The wire's caller-kind domain is `session | task_run | loop_run | automation_run` (`internal/network/participation/types.go:37-40`; DB CHECK in migration 00093). An operator-initiated call carries a synthetic operator-caller *session*, so `caller.kind` is `"session"` even then; `"operator"` exists only on `call_messages.from_kind`. Consequence: **every** Received row — including the operator-initiated case the branch was written to name — renders "unknown caller". The passing test hand-fabricates `caller.kind: "operator"` (`components/__tests__/agent-calls-inspector-panel.test.tsx:157`), certifying wire data the daemon cannot produce — the same test-lies-about-the-daemon class as review 18 F-006.
- Affected contract: `_uiux.md` S5 / the session-calls-panel board — "Received names who asked"; owner complaint 10/12 territory (made-vs-received legibility).
- Why blocking: the who-slot is the row's entire left half on one of the six core surfaces, and it is structurally incapable of doing its one job; the honest signals are already fetched (`actor.kind === "human"` for the operator case; `caller.id` resolvable against the already-cached session list for agent parents, as review 20 advisory 10 noted). Expected correction: name the operator from `actor.kind === "human"`, resolve session callers to their display title via the session catalog, keep "unknown caller" only as the genuine fallback — and fix the test to stage daemon-shaped data.
